# `ops/metrics/` — замер LLM (F-8) и решение по конфигурации

Здесь лежит всё, что нужно для первого замера моделей и для решения, на какой
конфигурации живёт MVP-1: описание конфигураций и порогов
([`bench-matrix.json`](bench-matrix.json)), результаты прогонов (`bench-*.csv`,
`bench-*.json`) и сам вывод ([`baseline.md`](baseline.md)).

Замер **ручной, на машине владельца**: локальная модель и GPU есть только там,
self-hosted runner не заводим (U-12). Агенты подготовили скрипты и промпты —
прогон делает пользователь.

---

## 0. Коротко: что сделать

```bash
make llm-up                    # поднять llama-server и дождаться /health = 200
bash scripts/llm-bench.sh      # прогон конфигурации E (~10–25 мин)
```

Повторить прогон **три раза** в разные моменты (см. §4) и прислать команде
файлы `ops/metrics/bench-*.csv` и `ops/metrics/bench-E-*.json`.

PowerShell 7 для этого **не нужен**: `scripts/llm-bench.sh` работает в Git Bash.
`scripts/llm-bench.ps1` — тот же замер для машины с `pwsh`, колонки одинаковые.

---

## 1. Что нужно на машине

| Что | Зачем | Проверка |
|---|---|---|
| `llama-server` (llama.cpp) | сам замер; провайдер `openai_compat` | `make llm-health` |
| модель `Qwen3.8-27B-UD-Q3_K_XL.gguf` | конфигурация E | `MV_LLM_MODEL_FILE` в `.env` |
| `curl`, `python3` | скрипт замера (`jq` **не** нужен) | `curl --version`, `python3 --version` |
| `nvidia-smi` | VRAM в отчёте (NFR-076) | необязательно: без него колонка пустая |
| Ollama | только для конфигураций C и A | `MV_OLLAMA_URL` в `.env` |

Переменные `MV_LLM_*` — в `.env` (образец: `.env.example`, `infrastructure.md`
§4.2). Минимум для замера: `MV_LLM_BIN`, `MV_LLM_MODEL_FILE`, `MV_LLM_URL`,
`MV_LLM_NUM_CTX`.

> `MV_LLM_URL` в `.env` указывает на `host.docker.internal` — это адрес **из
> контейнеров**. Скрипт запускается на хосте, поэтому для замера подставьте
> loopback: `MV_LLM_URL=http://127.0.0.1:1234 bash scripts/llm-bench.sh`
> (или временно поправьте `.env`).

## 2. Поднять сервер

```bash
make llm-up            # single-режим: одна модель из MV_LLM_MODEL_FILE (конфигурация E)
make llm-up ROUTER=1   # router-режим: модели из MV_LLM_MODELS_DIR (конфигурации E+, A)
make llm-health        # /health, список моделей, сверка билда с пином, VRAM
make llm-down          # остановить
```

`make up` (контейнеры) LLM **не поднимает** и не останавливает — это два разных
жизненных цикла (ADR-005 доп. 2 п. 7).

Контекст и тип KV-кэша задаются **при старте сервера**, а не скриптом замера:

```bash
MV_LLM_NUM_CTX=16384 make llm-up      # ячейка num_ctx = 16384
```

Скрипт замера сервер не перезапускает и не перенастраивает — он только
записывает в отчёт те значения, которые вы ему назвали (`--num-ctx`,
`--kv-cache`). Если сказать одно, а поднять другое — отчёт будет врать, это
единственное место, где нужна внимательность.

---

## 3. Запустить замер (Git Bash)

```bash
# конфигурация E, контекст 8192, KV f16 — базовая ячейка
MV_LLM_URL=http://127.0.0.1:1234 bash scripts/llm-bench.sh --configs E

# другая ячейка: сервер поднят с MV_LLM_NUM_CTX=16384, KV q8_0
MV_LLM_URL=http://127.0.0.1:1234 bash scripts/llm-bench.sh --configs E \
  --num-ctx 16384 --kv-cache q8_0

# быстрая проверка, что всё работает (по 2 промпта на фазу, ~1–2 мин)
MV_LLM_URL=http://127.0.0.1:1234 bash scripts/llm-bench.sh --limit 2
```

Аргументы: `--configs` (E, C, A, E+ через запятую), `--num-ctx`, `--kv-cache`,
`--repeats` (проходов внутри одного запуска), `--limit`, `--placement`,
`--matrix`, `--prompts`, `--out-dir`, `--help`.

Коды возврата: `0` — замер прошёл (даже если вердикт `fail`); `2` — замерить не
удалось (нет сервера, нет файла, неизвестная конфигурация). Типичное сообщение:

```
bench: no answer from http://127.0.0.1:1234/health — the LLM process is not
running. Start it: make llm-up
```

## 4. Три прогона

Один запуск скрипта = один прогон. Конфигурация считается принятой, если
`verdict=pass` для фазы `phase2` получен **во всех трёх** прогонах, сделанных в
разные моменты (разные дни либо после перезапуска `llm-server`) —
`bench-matrix.json`, `runs_required`.

```bash
make llm-down && make llm-up          # между прогонами: перезапуск сервера
bash scripts/llm-bench.sh --configs E
```

Порядок конфигураций — `decision_order` из матрицы: **сначала E**; прошла —
она и есть базовая, C и A прогонять не нужно. Не прошла — **C**, затем **A**
(для них нужен Ollama и `MV_OLLAMA_URL`, включая суффикс `/v1`, например
`http://127.0.0.1:11434/v1`).

## 5. Что получится и что прислать

| Файл | Что внутри |
|---|---|
| `bench-<дата>.csv` | по строке на ячейку (конфигурация × фаза × прогон), колонки `infrastructure.md` §6.4 |
| `bench-<конфигурация>-<дата>.json` | то же плюс каждый запрос: латентность, токены, кэш, язык |
| таблица в консоли | то, что видно во время прогона |

### 5.1. Поля, которые легко прочитать неверно

Колонки CSV с T-402 не менялись — старые отчёты сравниваются с новыми
побайтно по составу колонок. Всё новое — только в JSON (T-434).

| Поле | Как читать |
|---|---|
| `first_call_ms` (CSV и JSON) | холодный первый вызов (B2). **Пусто, если прогрев не ответил 200**: такой вызов измерил бы отказ, а не холодный старт. В CSV — пустая ячейка, в JSON — `null`, в stderr — строка с кодом ответа. Заполненное значение означает «сервер ответил 200 на прогрев» |
| `meta.matrix`, `meta.prompts` | путь внутри репозитория — относительный (`ops/metrics/bench-matrix.json`); файл вне репозитория (например, копия матрицы под id стенда) — **только имя файла**. Абсолютного пути в отчёте нет ни при каком `--matrix`/`-Matrix`: в T-402 туда попал путь профиля пользователя, и его правили руками |
| `meta.matrix_sha256`, `meta.prompts_sha256` | sha256 содержимого этих файлов. Пишутся всегда, в том числе для файла из репозитория: по ним копия матрицы проверяема, а два прогона сравнимы без доверия к имени |
| `requests[].prompt_ms` | `timings.prompt_ms` сервера, обработка промпта. `null`, если сервер его не отдал (Ollama не отдаёт `timings`). Латентность − `predicted_ms` — это «прочее»; без `prompt_ms` всплеск «прочего» по отчёту не разложить на обработку промпта и остальное (`baseline.md` §2.1, §2.5) |
| `llamacpp_build` (CSV и JSON) | источник виден в значении: `bNNNN` — из `MV_LLM_BIN --version`; `bNNNN(props)` — из `GET /props` → `build_info` **работающего сервера**; `bNNNN(pin)` — пин `build/versions.env`, когда ни того, ни другого нет. Сверка стенда с пином — дело `make llm-health` (T-404), замер её не повторяет |

Если `MV_LLM_BIN` не задан (обычный случай на стенде владельца), билд берётся
из `/props`. В T-402 этого не было, и во все строки попал пин `b10441`, пока
стенд работал на `b10840` и `b10878`.

Прислать команде: **все** `bench-*.csv` и `bench-*.json` трёх прогонов, а также
вывод `make llm-health` (билд llama.cpp и VRAM) и заметку, если во время замера
на GPU было что-то ещё (браузер, игра, вторая модель) — `nvidia-smi` считает всю
карту, и это единственное, чего скрипт про машину не знает.

Как читать таблицу:

| Колонка | Значение |
|---|---|
| `p95` | 95-й перцентиль латентности вызова, мс. Для `phase2` порог NFR-002 — 5000 |
| `tps` | токенов генерации в секунду по `timings` сервера (не по часам клиента) |
| `json` | доля ответов, разобранных как JSON (NFR-022 / B3, порог 0,98) |
| `lang` | доля ответов, прошедших NFR-090 (0 иероглифов, латиница ≤ 10 % букв **в тексте нарратива**, не в идентификаторах) |
| `cache` | доля промпта, обслуженная кэшем llama.cpp; низкая — сбрасывались слоты |
| `verdict` | `pass`/`fail` для фаз нарратива; `n/a` — для тика; `*` — порог справочный (группа из 3) |

`verdict=fail` — это результат, а не поломка: он и есть ответ на вопрос
«проходит ли E». Дальше по `decision_order` идёт C.

## 6. Куда это ведёт

Результаты сводятся в [`baseline.md`](baseline.md) (решение по U-2: какая
конфигурация базовая и почему), затем:

* блупринты MVP-1 фиксируют победившую модель (`model`, `thinking: false`);
* `ops/models.txt` сокращается до неё;
* пороги «после замера» (NFR-002 для группы, NFR-022, NFR-090) уходят в
  требования (EPIC-005, T-140);
* при обновлении llama.cpp замер победившей конфигурации повторяется
  (`infrastructure.md` §12) — поэтому в каждой строке есть `llamacpp_build`.
