# 🎮 GameService

> **GameService — это backend сервис, обеспечивающий передачу информации о сущностях и событиях на клиент.**

## 🎯 Назначение

- Передача информации о сущностях (Entity) клиенту в реальном времени
- Передача информации о событиях игрового мира клиенту
- Обеспечение синхронизации состояния клиента с состоянием игрового мира
- Управление регистрацией и входом игроков

## 🏗️ Архитектура

GameService построен по событийно-ориентированной архитектуре и интегрируется с другими сервисами "Живого Мультиверсума" через Event Bus (Redpanda).

### Основные компоненты

1. **Entity Stream Handler** - обрабатывает поток обновлений сущностей
2. **Event Stream Handler** - обрабатывает поток игровых событий
3. **WebSocket Server** - обеспечивает двунаправленную связь с клиентом
4. **Entity Cache** - кэширует часто запрашиваемые сущности для повышения производительности
5. **Event Buffer** - буферизирует события для отправки клиенту
6. **Player Service** - управляет регистрацией и входом игроков

## 🔌 Взаимодействие с другими сервисами

GameService подписывается на следующие топики Event Bus:

- `world_events` - для получения событий игрового мира
- `game_events` - для получения игровой логики (квесты, репутация, NPC)
- `player_events` - для получения событий игрока
- `system_events` - для получения системных событий
- `narrative_output` - для получения повествовательных элементов

GameService взаимодействует со следующими сервисами:

- **EntityManager** - для получения актуального состояния сущностей через MinIO
- **NarrativeOrchestrator** - для получения повествовательных элементов
- **Semantic Memory Builder** - для получения контекста сущностей
- **MinIO** - для хранения и чтения сущностей

## 📡 API

### WebSocket Endpoints

- `/ws/entities` - поток обновлений сущностей
- `/ws/events` - поток игровых событий
- `/ws/actions` - прием действий от клиента

### REST API

- `GET /entities/{entity_id}` - получение информации о сущности (требует world_id)
- `POST /players/register` - регистрация нового игрока
- `POST /players/login` - вход игрока
- `GET /entities/{entity_id}/history` - получение истории сущности
- `GET /events/recent` - получение последних событий

## 🛠️ Техническая реализация

### Язык программирования
Go 1.23+

### Основные зависимости
- Gorilla WebSocket для WebSocket соединений
- Redpanda client для работы с Event Bus
- MinIO client для получения и сохранения сущностей
- Entity caching с TTL для повышения производительности

### Архитектурные паттерны
- Event Sourcing для обработки потока событий
- CQRS для разделения чтения и записи данных
- Actor Model для обработки сообщений от клиента
- Кэширование с использованием составных ключей (entityID + worldID)

## 📈 Масштабирование

- Горизонтальное масштабирование по `player_id`
- Использование Redis для распределенного кэширования
- Балансировка нагрузки через Kubernetes

## 🔒 Безопасность

- Аутентификация через JWT токены
- Авторизация на основе ролей и прав доступа
- Шифрование данных в WebSocket соединениях (WSS)

## 🧪 Мониторинг

- OpenTelemetry для трассировки запросов
- Prometheus для сбора метрик
- Grafana для визуализации метрик

## 🛠️ Техническая реализация

- Сервис реализован в пакете `services/gameservice`
- Использует `eventbus.EventBus` для подписки на события
- Работает с MinIO через `github.com/minio/minio-go/v7`
- Подписывается на группы событий для получения игровых данных
- Использует Gorilla WebSocket для реального времени

## 🔧 Конфигурация

- Переменные окружения: `KAFKA_BROKERS`, `HTTP_ADDR`, `CACHE_TTL`
- По умолчанию: `KAFKA_BROKERS=localhost:9092`, `HTTP_ADDR=:8080`, `CACHE_TTL=5m`
