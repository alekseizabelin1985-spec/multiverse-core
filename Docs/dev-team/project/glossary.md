# Глоссарий проекта multiverse-core

Версия: 0.2 (после discovery раундов 1–3 и ревью требований, 2026-09-09). Автор: доменный эксперт dev-team.
Назначение: единая терминология для требований, эпиков и ADR. Колонка «Статус / расхождения» фиксирует, где документы и код понимают термин по-разному, и какие расхождения закрыты решениями пользователя (`journal.md`, раунды р1/р2/р3) или требованиями (`requirements/prd.md`, `user-stories.md`, `nfr.md`).

Изменения v0.2: добавлены термины требований (пробой законов, слои консистентности, record-replay, `llm.output`, псевдоним игрока, связка, эталонный клиент, ход/раунд/встреча, тип действия, деградированный режим, точка вставки фильтра, абсолютные запреты, версия законов, поломка мира, роли); обновлены определения, которые изменили решения пользователя (GM, канон, снапшот/replay, Rule Engine, Entity-Actor, игрок, группа, Первоисточник/Ω, Запрет Мира, LOD). Предложенные ревью термины (напряжение закона, лидер группы, `idle`) помечены «предложение DR-NN» — они станут проектными после принятия аналитиком/архитектором.

Условные обозначения источников: `README` — README.md; `ARCH` — Docs/architecture.md / architecture-updated.md; `ARCH_OLD` — Docs/architecture_old.md; `LW` — Docs/LIVING_WORLDS_*.md; `US` — Docs/user-stories/*; `AGM` — Docs/agent-gm-research/*; `shared/agent` — shared/agent/README.md и код; `CLAUDE` — CLAUDE.md / AGENTS.md; `код:<путь>` — исходный код; `PRD`, `USn`, `NFR` — `requirements/prd.md`, `user-stories.md`, `nfr.md`; `DR-NN` — `requirements/domain-review.md`; `р1/р2/р3` — раунды discovery в `journal.md`.

## 2. Сущности, события, состояние и память

| Термин | Определение в проекте | Синонимы / чего избегать | Источник | Статус / расхождения |
|---|---|---|---|---|
| **Сущность (Entity)** | Любой объект мира (игрок, NPC, предмет, регион, мир, Ядро) с иерархическим payload, версией и историей. Формат ссылки: `{"entity":{"id","type"}}`. Статусы `player`: `alive / dead / ascended_final` (+ `idle` в группе — предложение DR-03). | «Объект», «актор» — не синонимы (актор = Entity-Actor). | ARCH 4.1; CLAUDE; PRD §7 | Принцип «память в сущностях» уточнён: история — в сущности, индекс — в семантической памяти (проекция). |
| **Единственный писатель** | entity-manager — единственный компонент, меняющий состояние сущностей; остальные публикуют предложения (`entity.update.proposed`), entity-manager применяет по версии сущности и публикует факт (`entity.updated`). Last-writer-wins недопустим для HP, инвентаря, позиции. | «Single writer». | р2; PRD BR-03, FR-030 | Решено р2. Механизм версий/optimistic lock — архитектура. |
| **Событие (Event)** | Единица взаимодействия в шине: `id, type, timestamp, source, world, scope, payload, relations, correlation_id`. Тип должен быть зарегистрирован в реестре со схемой (целевое FR-036). | Не путать с сюжетным «событием» (narrative event). | CLAUDE; shared/eventbus; PRD §7 | Два формата payload (flat / hierarchical) сосуществуют — миграция на архитектуре. |
| **Реестр типов событий** | Список допустимых `type` с JSON-схемой; событие неизвестного типа отклоняется на входе в шину. | «Schema registry». | PRD FR-036; OQ-A-08/09 | Should в MVP-1; формат — архитектура. Для пробоя законов типы регистрируются в MVP-1 без обработчиков (DR-11). |
| **Корреляционный идентификатор (`correlation_id`)** | Идентификатор действия игрока, который проходит через всю цепочку: действие → решение → `dice.rolled` → `llm.output` → `entity.updated` → нарратив. Основа трассы решения агента. | «Trace id». | PRD FR-084; NFR-031, NFR-034 | Must в MVP-1. |
| **Scope (область повествования)** | Единица, для которой живёт один агент/GM и один поток нарратива. Допущение PRD: `solo, group, city, region, quest, world`; MVP-1 использует `solo`, `group`, `region`. Игрок находится ровно в одном scope. | В configs — `player`, `location` (заменить на `solo`, `city`). | README 4.2; CLAUDE; PRD §11 (OQ-D-05) | Допущение принято в PRD, окончательно — архитектура. Правило «один игрок — один scope» предложено как инвариант (DR-18). |
| **Онтология (Ontology)** | Три употребления: (1) онтология-дуальность — пара полюсов со свойствами и взаимодействиями (US-029); (2) онтологический профиль мира — законы/запреты/формы, версионируется; (3) схема сущности — JSON Schema в OntologicalArchivist. | Использовать уточняющие названия (1)–(3), не голое «онтология». | US-002 → US-029; ARCH 4.11; AGENTS.md | Целевое E-E. Механизм вывода профиля (2) из дуальностей (1) не определён. |
| **Онтологический профиль** | Документ мира: законы, запреты, допустимые формы; источник декларативных правил для Запрета Мира. | — | ARCH 4.3, 4.4; PRD FR-042 | Допущение OQ-D-12 (декларативные правила, не код) → архитектура. |
| **Канон (Canon)** | Слой 2 консистентности: факты мира/региона, которые **добавляются и меняются только через утверждение** (страж или человек) и имеют версию; попадают в `<canon>` промптов scope. Факт получает канонический статус через промоушен `generated → validated`. Конфликт с каноном — отклонение или явный ретрокон. | «Лор» — шире (включает мягкие факты). Не употреблять «неизменяемые факты» — канон версионируется. | р2; PRD BR-01, FR-043, FR-044; US-021 | **Закрыто р2** (ранее: нет процедуры, каноны конкатенировались при `gm.merged`). Слияние scope с конфликтующими канонами — на ревью (FR-044). |
| **Источник факта** | Метка факта в памяти: `authored` (блупринт/автор) / `validated` (утверждён в канон) / `generated` (порождён LLM, мягкий). При конфликте приоритет `authored > validated > generated`. | — | PRD FR-035; US-005 | Should в MVP-1. |
| **Semantic Memory (семантическая память)** | Сервис-проекция: индексирует события (векторы + граф связей) и отдаёт контекст агенту с пометкой источника и слоя факта; перестраивается из лога. | «Память мира», «RAG». | ARCH 4.10; PRD FR-035, §7 | Уточнено: stateful-проекция, не «stateless»; retention и удаление — E-H (FR-062). Выбор векторной БД — архитектура (OQ-A-05). |
| **Снапшот (Snapshot)** | Состояние сервиса/мира на момент времени; **источник истины при восстановлении**; пишется периодически и по завершении сессии; включает `laws_version` (DR-11). После старта сервис загружает последний снапшот и догоняет события после него. | — | р2; PRD FR-031, BR-04 | Решено р2: снапшот — истина, лог — способ догнать (не полный event sourcing). |
| **Record-replay** | Политика воспроизводимости: результат каждого недетерминированного вызова (LLM, бросок, внешний API, время/таймеры — DR-13) записывается как событие **до** его использования; при replay записанное читается, LLM и RNG не вызываются. Даёт восстановление, аудит промптов и воспроизводимые тесты без GPU. | «Snapshot + replay», «event sourcing» (не точно: лог не единственная истина). | р2; PRD BR-04, FR-032, FR-100; NFR-014, NFR-061 | **Закрыто р2** (ранее: RNG от `time.Now()`, LLM не записывалась, replay порождал другую историю). |
| **`llm.output`** | Событие записи вызова LLM: `provider, model, params, prompt_hash, response_raw, validation_status (valid / invalid / rejected_unknown_entity / …), correlation_id, caused_by, laws_version`. Обязательно до использования ответа; полный промпт — по флагу. | «LLM-вывод». | PRD FR-032, §7; US-018 | Предложение DR-08: статус `quarantined` без `response_raw` для ответов, задержанных фильтром категории (a). |
| **`dice.rolled`** | Событие броска: `seed, formula, result, roll_index, caused_by`. Seed детерминирован: `hash(event_id, roll_index)` (DR-05) — один и тот же seed даёт тот же результат. | «Бросок». | PRD FR-021, FR-022; NFR-060 | Формулировка «seed = hash(event_id)» в PRD недостаточна при нескольких бросках на действие (DR-05). |
| **Идемпотентность потребителя** | Повторная доставка события с тем же `event_id` (at-least-once) не меняет состояние второй раз. | «Дедупликация». | PRD FR-033; NFR-013 | Must в MVP-1. |
| **Relations** | Явные связи в событии (`RelLocatedIn`, `RelActedOn`), из которых граф строит рёбра. | — | AGENTS.md | — |

## 3. Нарратив, агенты и LLM

| Термин | Определение в проекте | Синонимы / чего избегать | Источник | Статус / расхождения |
|---|---|---|---|---|
| **GM (Game Master)** | Роль «мозга» мира. **Единственный GM — Agent GM Core**; legacy `GMInstance` narrative-orchestrator выводится или остаётся тонким слоем рендера текста. | «Нарратор», «рассказчик» — только для Phase 2. Не называть narrative-orchestrator «GM» в новых документах. | р1; PRD FR-010, FR-014, BR-12; US-019 | **Закрыто р1** (ранее два GM в одном пакете). Переходный фича-флаг `agent_mode` удаляется по завершении миграции. |
| **Agent GM Core (GM-агент)** | Иерархия LLM-агентов Global → Domain → Task (→ Object → Monitor — целевое), каждый по блупринту, с TTL, LOD и инструментами. Domain-агент — регион; Task-агент — встреча/квест. | «Агент», «оркестратор». Не путать с Entity-Actor. | AGM; shared/agent; PRD FR-011, FR-012 | Минимальный объём для MVP-1 (Router + Lifecycle + Pipeline + инструменты) — ADR архитектора. |
| **Domain-агент / Task-агент** | Domain-агент активируется при входе игрока в регион по блупринту (spawn по условию; повторный вход не пересоздаёт контекст). Task-агент порождается Domain-агентом для встречи с контекстом {игрок(и), NPC, регион} и завершается событием `agent.child_resolved`. | — | PRD FR-011, FR-012; US-002 | — |
| **Блупринт (Blueprint)** | Markdown/YAML-описание агента (один утверждённый формат): триггер, ограничения, TTL, LLM-настройки, схема ответа, инструменты, родитель, промпты фаз. Хранится в Git, версионируется, валидируется с указанием поля; новый регион добавляется без изменения Go-кода. | «Конфиг агента». | AGM 03; shared/agent/examples; PRD FR-090, FR-091 | Открыто: формат (frontmatter + секции vs чистый YAML) — архитектура. Теги моделей `qwen:7b`/`qwen:72b` в примере не существуют (OQ-D-13). |
| **Двухфазный конвейер** | Phase 1 (решение): строгий JSON, механика через Rule Engine, результат публикуется как событие до Phase 2; Phase 2 (нарратив): LLM, асинхронно. Пороги (после замера): механика ≤ 0,5 с p95 без LLM, нарратив ≤ 5 с p95. Phase 2 не публикует событий, меняющих состояние. | — | AGM; PRD FR-013, BR-05; NFR-001, NFR-002 | **Закрыто р1/допущение**: прежние «<100 мс» сняты. Предложение DR-12: в scope `group` Phase 2 — один нарратив на раунд. |
| **Фаза пробоя** (предложение DR-01) | Отдельный шаг конвейера, запускаемый только при напряжении закона ≥ порога или авторском триггере; единственное место, где LLM может предложить `world.law_breach.proposed`. | — | DR-01 | Предложение; в MVP-1 отключена. |
| **LOD (Level of Detail)** | Уровень детализации агента: 0 — спит; 1 — только правила; 2 — простой LLM + кэш; 3 — полный ReAct. Допущение PRD: «двухосный» — значимость события задаёт желаемый LOD, бюджет LLM — потолок; критические события не теряются. | — | shared/agent/lod.go; PRD FR-017; US-033 | Целевое E-G. В коде логика по нагрузке, в US-005 — по значимости; расхождение снимается допущением C (OQ-D-11). MVP-1: бой — LOD 1. |
| **Инструмент (Tool, ToolRegistry)** | Действие агента с владельцем-сервисом, проверкой прав и рейт-лимитом (`search_entities`, `spawn_npc`, …). Необратимые инструменты требуют лимитов объёма. | — | AGM; блупринт | — |
| **Абстракция провайдера LLM** | Единый интерфейс вызова модели; реализации: Ollama (по умолчанию, ноль внешних затрат) и облачные (OpenAI/Anthropic/DeepSeek) — выбор конфигурацией, ключи только из окружения, денежный лимит для облака. | «LLM-шлюз». | р2; PRD FR-070…072, BR-15; US-014 | **Закрыто р2**. Ограничение DR-14: облако при внешних игроках — трансграничная передача (юрист). |
| **Деградированный режим** | Работа без LLM (недоступна, таймаут, лимит, невалидный ответ): механика применяется полностью, нарратив заменяется шаблонным текстом с пометкой («упрощённый режим», `generated_by: rules`). Никогда не блокирует механику. | «Fallback». | PRD FR-015, BR-14; US-004; NFR-015 | Must в MVP-1. |
| **Фича-флаг `agent_mode`** | Переключатель пути GM на время миграции (on — Agent GM Core, off — legacy); применяется без пересборки; удаляется вместе с legacy-путём по завершении миграции. | — | PRD FR-014; US-019 | Временный; не «режим сосуществования». |
| **Тик (Tick)** | Плановое срабатывание агента scope без действия игрока (например, обнаружение NPC в радиусе восприятия). При replay тики читаются из событий (DR-13). | — | PRD FR-037, BR-10; US-002, US-022 | Допущение OQ-R-15 (подтвердить на G1). |
| **Точка вставки фильтра (`NarrativeFilter`)** | Единый интерфейс, через который проходит весь нарратив перед доставкой игроку; MVP-1 — реализация-пустышка с журналом вызовов; при ошибке фильтра — fail-closed (шаблон). Целевое: реальный фильтр входа и выхода по политике «стен» 18+. | «Модерация», «фильтр контента» (это реализация, не точка). | р3; PRD FR-050, FR-053; US-016, US-031 | Предложения DR-08 (минимальная проверка категории (a)), DR-15 (точка вставки на входе). |
