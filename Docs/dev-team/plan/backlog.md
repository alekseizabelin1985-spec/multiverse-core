## 6. Правила ведения бэклога

1. Статусы задач ведут тимлиды в `epics/*/tasks.md` (`todo / in-progress / review / done / blocked`); оркестратор дублирует в `state.js`. Этот файл хранит **связь с требованиями и порядок**, а не статусы.
2. **Коммиты (`commits=ask`): один запрос пользователю на веху или подволну** с перечнем `T-NNN: …`. В длинных вехах (M2, M4, M5) — на каждую подволну эпика, чтобы прерывание сессии агента (риск R-02) стоило не более одной подволны.
3. Новые задачи (дефекты интеграции, пробелы П-1…П-7, замечания I1-α) заводятся **в эпик-владелец** по `plan/ownership.md` с номером из его диапазона; PM добавляет строку в §3 или §4 этого файла.
4. `counters.task` в `.dev-team.json` сводит tech-lead#1 один раз после G3 (текущий максимум занятых номеров — 393).
5. Изменение объёма (пользователь сократил на G3/G4) фиксируется здесь явным списком «что выпало и куда перенесено», а не молчаливым удалением строк.
