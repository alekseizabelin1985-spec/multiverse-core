## US-001: Создание персонажа и возврат в мир

**Как** игрок, **я хочу** создать персонажа с выбранным мной именем в выбранном мире и вернуться к нему позже,
**чтобы** моё состояние не терялось между сессиями.

Приоритет: Must · Связь: FR-001, FR-006, FR-023, FR-060, BR-07, A-7

### Критерии приёмки
- **Дано** мир `dark-forest-world` существует, игрок прошёл подтверждение `/start` (US-008) и не зарегистрирован, **когда** игрок отправляет регистрацию с именем персонажа «Вася» (введено явно) и миром, **тогда** создаётся сущность типа `player` с начальными HP 10/10, пустым инвентарём, позицией `outside:dark-forest-world` и статусом `alive`, и игроку возвращается `player_id`.
- **Дано** персонаж «Вася» с HP 7/10 и трофеем «волчья шкура», **когда** игрок входит повторно после закрытия клиента, **тогда** он получает то же состояние (HP 7/10, инвентарь с трофеем, та же позиция).
- **Дано** мира `no-such-world` не существует, **когда** игрок пытается зарегистрироваться в нём, **тогда** запрос отклоняется с сообщением «мир не найден» и сущность не создаётся.
- **Дано** у этого внешнего аккаунта уже есть персонаж со статусом `alive`, **когда** приходит повторная регистрация, **тогда** второй персонаж не создаётся, возвращается существующий `player_id` (A-7).
- **Дано** персонаж этого аккаунта имеет статус `dead`, **когда** приходит регистрация с новым именем, **тогда** создаётся новый персонаж с **новым** `player_id`, связка обновляется, старый `player_id` остаётся в истории и не исключается из графа (DR-06).
- **Дано** игрок не прошёл подтверждение `/start` (возраст/согласие), **когда** он отправляет регистрацию, **тогда** запрос отклоняется с повторным показом сообщения подтверждения; сущность не создаётся.
- **Дано** регистрация без имени персонажа (или бот пытается подставить имя профиля), **когда** запрос обрабатывается, **тогда** он отклоняется с просьбой ввести имя; имя из профиля мессенджера не используется (FR-060).

### Замечания
Аутентификация вне объёма MVP-1 (FR-008); защита — псевдонимизация и доверенный круг тестеров.

## US-002: Сквозной цикл «Тёмный лес» соло, 30 ходов

**Как** игрок, **я хочу** войти в Тёмный лес, встретить волка, сразиться и получить последствия,
**чтобы** пережить полный игровой цикл, в котором мир не ломается.

Приоритет: Must · Связь: FR-010…FR-013, FR-018, FR-020, FR-023, FR-024, FR-120…FR-123, BR-03, BR-05, BR-10, NFR-012

### Критерии приёмки
- **Дано** персонаж «Вася» в позиции `outside:dark-forest-world`, GM региона `dark-forest-01` уже активен (живёт постоянно, FR-011), **когда** он отправляет `enter dark-forest-01`, **тогда** публикуется `player.entered_region`, GM региона добавляет игрока в наблюдаемый scope (контекст не пересоздаётся), персональный GM «Васи» получает сводку фоновых событий (US-036) и не позднее порога NFR-002 игрок получает описание региона, согласованное с текущей погодой мира.
- **Дано** GM региона активен и в радиусе восприятия «Васи» есть `wolf-alpha`, **когда** проходит тик GM региона, **тогда** порождается Task-агент встречи, и через персональный GM игрок получает нарратив появления волка с указанием, что можно делать (атаковать, бежать).
- **Дано** встреча активна, **когда** игрок отправляет `attack wolf-alpha`, **тогда** Phase 1 публикует `combat.decided` (попадание/промах по правилам приложения A, урон, HP сторон, `gm_path`, `phase1_mode`) до начала Phase 2, entity-manager применяет изменение HP и публикует `entity.updated`, затем волк отвечает один раз (свой `combat.decided`), и затем приходит нарратив боя, согласованный с числами обоих `combat.decided`.
- **Дано** HP волка ≤ 0 после удара, **когда** entity-manager применяет результат, **тогда** волк получает статус `dead`, игроку начисляется трофей «волчья шкура», Task-агент завершается событием `agent.child_resolved`, и волк не появляется в этом регионе ни в текущей сессии, ни по фоновому тику в течение TTL из блупринта (FR-128).
- **Дано** HP игрока ≤ 0, **когда** результат применён, **тогда** персонаж получает статус `dead`, игрок видит нарратив гибели, последующие действия отклоняются с предложением создать нового персонажа (FR-023), и персонаж не выбирается целью и не описывается действующим.
- **Дано** «Вася» ранен (HP 4/10) и вне встречи, **когда** он отправляет `rest`, **тогда** HP = 10/10 по `entity.updated`, ход засчитан; **дано** встреча активна, **когда** он отправляет `rest`, **тогда** действие отклонено без изменения состояния (FR-024).
- **Дано** «Вася» во встрече отправляет `flee`, **когда** бросок бегства успешен, **тогда** он оказывается в `outside:dark-forest-world`, встреча закрыта (`agent.child_resolved`); при провале волк атакует его вне очереди, и игрок остаётся во встрече.
- **Дано** сценарный тест выполняет 30 ходов подряд с фиксированным seed (входы, осмотры, атаки, бегство, отдых, повторный вход — приложение A PRD), **когда** тест завершается, **тогда**: ни одно действие не осталось без ответа; число расхождений между снапшотом и агрегатом лога событий по HP/инвентарю/позиции/статусу = 0; инварианты NFR-020 не нарушены; нет паник и необработанных ошибок в логах сервисов.
- **Дано** игрок атакует цель `wolf-999`, которой нет в scope, **когда** действие принято, **тогда** оно отклоняется до Phase 1, состояние не меняется, LLM не вызывается.
- **Дано** игрок вышел из региона (`leave`), **когда** истёк TTL Task-агента и персонального GM без игрока, **тогда** они переходят в сон/удаляются и вызовов LLM по ним больше нет (FR-016); GM региона продолжает тикать по расписанию (US-036).

### Замечания
Основной приёмочный сценарий MVP-1 (цели G-1, G-2). Числа правил боя — приложение A PRD (допущение A-16, калибруются после прогонов). Отдельные прогоны: seed с гибелью игрока и seed с провальным `flee`.

## US-003: Действие с предсказуемой механикой

**Как** игрок, **я хочу** чтобы исход моих действий определяли правила и броски, а не настроение рассказчика,
**чтобы** доверять миру и понимать, почему так вышло.

Приоритет: Must · Связь: FR-018, FR-020…FR-022, FR-084, BR-05, BR-06, BR-12, BR-16

### Критерии приёмки
- **Дано** правило атаки (d20 + atk против def), **когда** игрок атакует, **тогда** публикуются `dice.rolled` для каждого броска хода (попадание `roll_index=0`, урон `roll_index=1`, ответ волка `roll_index=2,3`) с `seed = hash(event_id действия, roll_index)`, формулой и результатом, и каждый `combat.decided` ссылается на свои броски.
- **Дано** два прогона с одинаковым `event_id` действия, **когда** выполняются броски, **тогда** результаты всех бросков идентичны.
- **Дано** одно действие с четырьмя бросками, **когда** сравниваются их результаты на 1000 событий, **тогда** броски с разными `roll_index` статистически независимы (например, корреляция между d20 попадания и d6 урона не отличается от нуля — тест NFR-060), а не повторяют один паттерн.
- **Дано** `combat.decided` с уроном 3, **когда** Phase 2 сгенерировала текст «волк едва оцарапан» или «волк убит», **тогда** текст не меняет HP (HP изменён ровно на 3 по `entity.updated`), а расхождение фиксируется метрикой `narrative_mechanics_mismatch` для оценки качества.
- **Дано** ответ Phase 1 содержит событие типа `player.*` (агент «решил за игрока»), **когда** он валидируется, **тогда** событие отклоняется, записывается `llm.output.rejected reason=player_agency`, применяется fallback без этого события (BR-06).
- **Дано** ответ GM региона содержит предложение изменить атрибут мира (погоду), **когда** он валидируется, **тогда** оно отклоняется с `reason=level_violation` (BR-16), остальная часть ответа применяется (`validation_status=partially_rejected`).
- **Дано** ответ тика GM региона содержит `ops`, переводящие мёртвого волка в действие или HP вне [0, hp_max], **когда** страж проверяет гипотетическое состояние инвариантами законов `laws@v1`, **тогда** элемент отклоняется с `reason=law_violation details{invariant_id}` (`inv-1`/`inv-2`), остальные элементы применяются, `laws.strain` закона увеличен (FR-034, ADR-017, G2).
- **Дано** ответ содержит `laws_version`, отличную от текущей (после `world.laws.changed`), **когда** он валидируется, **тогда** весь ответ `invalid` с `reason=law_violation`, шлюз повторяет вызов один раз с новой версией; второй провал → шаблон.
- **Дано** идентификатор действия, **когда** исследователь запрашивает трассу, **тогда** по `correlation_id` находятся все события цепочки: действие → `dice.rolled` → `combat.decided` → `llm.output` → `entity.updated` → нарратив, с указанием агента и уровня для каждого решения.

## US-004: Нарратив асинхронно и с деградацией

**Как** игрок, **я хочу** быстро узнать результат действия и чуть позже получить его описание,
**чтобы** не ждать модель и не зависать при её недоступности.

Приоритет: Must · Связь: FR-013, FR-015, FR-050…FR-052, BR-09, BR-14, NFR-001, NFR-002

### Критерии приёмки
- **Дано** LLM доступна, **когда** игрок атакует, **тогда** сначала приходит короткий механический результат (попадание/урон) в пределах NFR-001, затем нарратив от персонального GM в пределах NFR-002, оба помечены `generated_by` (`rules` / `llm`).
- **Дано** LLM недоступна (контейнер остановлен) или отвечает дольше таймаута, **когда** игрок атакует, **тогда** механика применяется, игрок получает шаблонный текст с пометкой «упрощённый режим», состояние сессии продолжается, в логах — событие деградации, а не ошибка.
- **Дано** ответ Phase 2 не соответствует JSON-схеме, **когда** исчерпан лимит повторов, **тогда** используется шаблонный текст, `llm.output` записан со статусом `invalid` по одному событию на попытку.
- **Дано** LLM снова доступна, **когда** приходит следующее действие, **тогда** нарратив снова генерируется моделью без перезапуска сервисов.
- **Дано** нарратив на русском ожидается, **когда** ответ содержит китайские иероглифы или более N % латиницы (порог — NFR-090), **тогда** ответ считается невалидным (`reason=language`) и уходит на повтор/шаблон.
- **Дано** фоновый тик GM региона выполняется в момент действия игрока, **когда** оба требуют LLM, **тогда** действие игрока обрабатывается первым, тик не задерживает NFR-001/002 (BR-10).

## US-005: Мир помнит последствия

**Как** игрок, **я хочу** чтобы мир помнил, что я сделал,
**чтобы** мои действия имели вес, а не забывались через две сцены.

Приоритет: Must · Связь: FR-001, FR-030, FR-031, FR-035, FR-127, BR-03

### Критерии приёмки
- **Дано** игрок убил `wolf-alpha` и покинул регион, **когда** он возвращается в регион в той же сессии, **тогда** волк не появляется, описание региона упоминает последствия (трофей, следы боя) или как минимум не противоречит им (волк не описан живым).
- **Дано** игрок получил ранение (HP 4/10) и не отдыхал, **когда** проходит 5 ходов и он возвращается, **тогда** HP по-прежнему 4/10 — нарратив не «залечивает» рану; фоновые тики HP игрока не меняют (FR-128).
- **Дано** GM региона получил в контексте факт из семантической памяти, порождённый LLM (`generated`), **когда** он противоречит блупринту (`authored`), **тогда** приоритет у авторского факта (проверяется тестом с подложенным противоречием). *Если 005-memory отрезана на G3/G4 (A-17) — критерий проверяется на факте из окна журнала вместо индекса; остальные критерии истории от памяти не зависят (G2).*
- **Дано** семантическая память выключена в конфигурации (или недоступна), **когда** «Вася» возвращается в регион после ≥ 2 фоновых тиков, **тогда** сводка «пока тебя не было» (FR-127) всё равно построена из журнала событий по позиции его последнего присутствия, нарратив входа её отражает, ошибок нет (Must, G2).
- **Дано** глобальный GM сменил погоду на «ливень» фоновым событием, **когда** персональный GM генерирует следующий нарратив, **тогда** погода в нарративе — ливень, а не «ясно» из более ранней памяти (факт состояния мира приоритетнее памяти нарратива).

## US-006: Групповая сессия из трёх игроков

**Как** игрок в группе, **я хочу** войти в Тёмный лес вместе с друзьями и видеть общую картину,
**чтобы** играть совместно, а не в трёх параллельных мирах.

Приоритет: Must · Связь: FR-003, FR-005, FR-025, FR-123, BR-06, BR-13, NFR-005

### Критерии приёмки
- **Дано** «Вася» отправил `group create`, **когда** «Лена» и «Олег» отправляют `group join <id>` вне встречи, **тогда** создаётся scope `group` с тремя участниками, лидер — «Вася», каждый получает подтверждение состава и лидера.
- **Дано** группа из трёх в `outside`, **когда** лидер «Вася» отправляет `enter dark-forest-01`, **тогда** в регион входит вся группа одним событием перемещения группы (`cause: group_move, by: player-A` — BR-06), GM региона наблюдает scope группы, и все трое получают через свои персональные GM один и тот же нарратив входа (без противоречий по фактам).
- **Дано** группа в `outside`, **когда** не-лидер «Олег» отправляет `enter dark-forest-01`, **тогда** действие отклоняется с подсказкой «регион меняет лидер группы», позиция группы не меняется.
- **Дано** группа в регионе во встрече с волком, **когда** «Лена» атакует, **тогда** результат `combat.decided` и нарратив раунда получают все трое (один нарратив на раунд — FR-013), а не только «Лена».
- **Дано** группа вне встречи, **когда** «Олег» отправляет `group leave`, **тогда** он переходит в scope `solo` в той же позиции, перестаёт получать групповой нарратив, а сессия «Васи» и «Лены» продолжается без прерывания.
- **Дано** лидер «Вася» отправляет `group leave`, **когда** группа обрабатывает выход, **тогда** лидером становится старейший из оставшихся («Лена», по `joined_at`), публикуется `group.leader_changed {leader: player-B, cause: leave}`, группа сохраняется.
- **Дано** лидер «Вася» погибает в бою (HP = 0), **когда** `combat.decided` применён, **тогда** лидером становится старейший **живой** участник («Лена»), публикуется `group.leader_changed {cause: death}`; «Вася» остаётся в `members[]` формально, но не в `active` и не в целях волка; следующий `enter`/`leave` группы принимается от «Лены» (BR-13, G2).
- **Дано** в группе погибли все участники, **когда** обрабатывается последняя смерть, **тогда** группа остаётся без лидера (`leader: null`), `enter` от любого участника отклоняется, группа завершается `group.disbanded` (по TTL scope или при создании новых персонажей — FR-016, FR-023).
- **Дано** группа во встрече, **когда** «Олег» отправляет `status`, **тогда** он получает своё состояние и состав группы из состояния без создания хода: раунд не открывается и не закрывается, `acted[]` не меняется, LLM не вызывается (FR-006).
- **Дано** группа во встрече с волком, **когда** четвёртый игрок отправляет `group join`, **тогда** он получает «подождите конца боя», состав не меняется.
- **Дано** группа из 6 игроков вне встречи, **когда** седьмой пытается присоединиться, **тогда** отклоняется с сообщением о лимите.
- **Дано** игрок не состоит в группе, **когда** он отправляет `group leave`, **тогда** получает понятную ошибку, состояние не меняется.
- **Дано** игрок из другого scope (`solo`, «Пётр»), **когда** группа получает нарратив, **тогда** «Пётр» его не получает (FR-003).

## US-007: Согласованный бой в группе по раундам

**Как** игрок в группе, **я хочу** чтобы удары всех участников считались по одному и тому же волку в раундах,
**чтобы** результат был честным и одинаковым для всех, а волк не кусал шестерых шесть раз.

Приоритет: Must · Связь: FR-025, FR-030, FR-033, BR-03, BR-13, NFR-012

### Критерии приёмки
- **Дано** волк с HP 10 и раунд открыт, **когда** «Вася» и «Лена» атакуют в течение одной секунды, а «Олег» — через 5 с, **тогда** раунд закрывается после действия «Олега», entity-manager применяет три результата последовательно по версии сущности (порядок — по времени приёма), итоговый HP = 10 − урон1 − урон2 − урон3, волк отвечает **один раз** (цель — последний нанёсший урон), и все трое видят одинаковый итог и один нарратив раунда.
- **Дано** волк с HP 2, **когда** два удара приходят одновременно и первый убивает, **тогда** второй удар применяется к уже мёртвой цели как «цель мертва» (`combat.decided` без урона), HP не уходит ниже 0, трофей начисляется один раз — нанёсшему последний удар.
- **Дано** раунд открыт, «Олег» молчит, **когда** истекает таймаут раунда (в тесте — `round.close`), **тогда** раунд закрывается, «Олег» получает авто-действие `defend`, волк может выбрать его целью; после двух подряд пропущенных раундов «Олег» получает статус `idle`: не действует, не ждётся при закрытии раунда, не выбирается целью, а его первое действие возвращает `active`.
- **Дано** «Лена» во встрече отправляет `flee` и бросок успешен, **когда** раунд закрывается, **тогда** «Лена» помечена `out_of_combat`, остаётся в группе, не выбирается целью; при провале волк атакует её вне очереди.
- **Дано** «Олег» во встрече отправляет `group leave`, **когда** действие обрабатывается, **тогда** оно исполняется как `flee` (BR-13): при успехе он выходит из группы и встречи в `solo` с позицией **`outside:dark-forest-world` (опушка)**, а позиция группы не меняется; при провале — свободная атака, он остаётся в группе и в бою (G2, UC-017).
- **Дано** раунд открыт и «Вася» уже атаковал в нём, **когда** «Вася» отправляет вторую `attack` до закрытия раунда, **тогда** действие отклоняется с `409 already_acted` («дождитесь конца раунда»), состояние и `acted[]` не меняются, `dice.rolled` не публикуются; после `round.closed` его следующая `attack` принимается (FR-025, G2).
- **Дано** раунд открыт, «Лена» ещё не действовала, **когда** «Лена» отправляет `say Бей слева!` и затем `look`, **тогда** реплика доставляется участникам группы сразу, описание сцены приходит ей без Phase 1, раунд не закрывается и не считает «Лену» действовавшей (`acted[]` без неё), пропуском это не считается; её последующая `attack` в том же раунде принимается (FR-025, G2).
- **Дано** группа `outside`, встречи нет, **когда** «Вася» отправляет `say Пошли`, **тогда** раунд не открывается (`round.opened` отсутствует), `player.said` доставлен «Лене» и «Олегу» (C-04).
- **Дано** событие `combat.decided` доставлено потребителю дважды (at-least-once), **когда** обрабатывается повтор, **тогда** HP изменён один раз (идемпотентность по `event_id`).
- **Дано** «Вася» погиб в групповом бою, **когда** агент генерирует следующий нарратив, **тогда** «Вася» не описывается как действующий; его действия отклоняются (FR-023), волк его не выбирает целью, остальные продолжают.
- **Дано** сценарный тест группы из 3 выполняет 30 раундов (≥ 60 действий игроков), включая раунд с молчащим игроком, индивидуальное бегство и выход участника, **когда** тест завершается, **тогда** выполняются те же условия, что в US-002 (0 расхождений, 0 без ответа, 0 паник), и позиция каждого **`alive`** участника = позиции группы (NFR-020 инв. 4; погибший участник в проверку не входит — G2).

### Замечания
Формулировка приёмки S2 принята на G1 как «30 раундов группы из 3 (≥ 60 действий игроков)»; таймаут 60 с и `idle` после 2 пропусков — стартовые значения, уточняются замером (A-15, OQ-R-18 решено). Текст S2 в `vision.md` обновляет PO.

## US-008: Telegram-бот как эталонный клиент

**Как** игрок, **я хочу** играть через бота в Telegram,
**чтобы** не устанавливать ничего и играть с телефона вместе с друзьями.

Приоритет: Must · Связь: FR-002, FR-003, FR-004, FR-009, FR-052, FR-060, FR-130, FR-131, BR-09, NFR-003, NFR-044, NFR-049, NFR-092

### Критерии приёмки
- **Дано** пользователь из allowlist впервые пишет боту `/start`, **когда** бот отвечает, **тогда** первое сообщение содержит единый текст простыми словами (FR-009, SEC-26): «контент создаётся ИИ»; «игра 18+ — подтвердите возраст»; «ваш текст (имя персонажа, реплики) обрабатывается для генерации на машине оператора; если оператор включит облачную модель — вы получите отдельное уведомление»; «мы храним псевдоним и связку с вашим аккаунтом, пока вы играете; резервная копия связки — не дольше 30 дней»; «`/forget` удаляет связку и недоставленные сообщения; персонаж остаётся в мире без владельца; тексты под псевдонимом хранятся до 30 дней (события), 90 дней (записи ИИ), 180 дней (обезличенная статистика)»; «историю чата в Telegram вы удаляете сами» — и кнопку/команду явного подтверждения; до подтверждения создание персонажа недоступно.
- **Дано** у мира игрока `worlds[].llm.cloud_enabled = true` (поле `GET /v1/worlds`, без имени провайдера/URL/ключей — SEC-21), **когда** игрок из allowlist в рамках текущей диалоговой сессии впервые после входа отправляет команду (или `/start`/`/help`), **тогда** бот показывает отдельное уведомление «сейчас тексты обрабатываются облачной моделью» (без имени провайдера) один раз за сессию диалога; бот кэширует флаг с TTL (`MV_TELEGRAM_CLOUD_FLAG_TTL`, обновление на `/start`, `/help` и по истечении TTL); при `cloud_enabled = false` уведомления нет (NFR-046).
- **Дано** пользователь Telegram, чьего `user id` нет в allowlist (`MV_TELEGRAM_ALLOWED_USER_IDS`), **когда** он пишет боту `/start` или любую команду, **тогда** бот отвечает коротким отказом «доступ по приглашению», gateway не вызывается, связка и персонаж не создаются, его id в логах бота отсутствует (FR-130, SEC-06).
- **Дано** allowlist пуст, **когда** любой пользователь пишет боту, **тогда** отказ как для неизвестного (fail-closed).
- **Дано** бот добавлен в групповой чат Telegram, **когда** в чате отправляют `/attack wolf-alpha` или `/start`, **тогда** бот не отвечает и не создаёт действий; связка и доставки привязаны только к личному чату (`from.id`), нарратив в групповой чат не уходит (FR-131, SEC-07).
- **Дано** игрок отправляет 21-ю команду за минуту, **когда** бот обрабатывает её, **тогда** отвечает «слишком часто, подождите N с» без вызова gateway; состояние не меняется; на 61-й секунде команды снова принимаются; действия других игроков в это время укладываются в NFR-001 (NFR-049).
- **Дано** пользователь подтвердил, **когда** game-service создаёт связку, **тогда** в ней проставлены `notice_shown_at`, `consent_at`, `age_confirmed_at`, и бот предлагает ввести имя персонажа и выбрать мир.
- **Дано** пользователь не подтвердил (нажал «нет» или проигнорировал), **когда** он отправляет игровую команду, **тогда** бот повторяет сообщение подтверждения и не создаёт действия в игре.
- **Дано** персонаж создан, **когда** пользователь отправляет команду из словаря FR-002 (`/enter dark-forest-01`, `/look`, `/status`, `/attack wolf-alpha`, `/flee`, `/say <текст>`, `/rest`, `/leave`, `/group create|join|leave`), **тогда** бот подтверждает приём в пределах NFR-003, затем присылает механический результат и нарратив отдельными сообщениями по мере готовности, каждое с пометкой `generated_by`.
- **Дано** пользователь отправляет неизвестную команду или произвольный текст без команды, **когда** бот обрабатывает сообщение, **тогда** он показывает список доступных команд (`/help`) и не создаёт действия в игре (A-1 решено: свободный текст — целевое).
- **Дано** два пользователя в одной группе scope, **когда** приходит нарратив раунда, **тогда** каждый получает его в своём чате с ботом (или в общем канале — по конфигурации), а игроки из другого scope — нет.
- **Дано** бот недоступен для game-service (нет сети), **когда** нарратив готов, **тогда** он сохраняется и доставляется при восстановлении связи или доступен по `/look`; действие не теряется.
- **Дано** пользователь отправляет `/help` или возвращается после 30 дней неактивности, **когда** бот отвечает, **тогда** уведомление об ИИ показывается повторно (Should).

### Замечания
Telegram — решение пользователя (р4); Discord — следующий инкремент поверх того же интерфейса game-service (E-H). Telegram не даёт механизма 18+ для ботов — подтверждение возраста делается в `/start` (DR-23).

## US-009: Псевдонимизация и удаление связки

**Как** игрок, **я хочу** чтобы мой аккаунт мессенджера не расходился по внутренностям платформы и мог быть отвязан,
**чтобы** контролировать свои данные.

Приоритет: Must · Связь: FR-060, FR-061, BR-07, NFR-041, NFR-042

### Критерии приёмки
- **Дано** игрок зарегистрировался через бота с известным тестовым Telegram ID и username, **когда** проверяются события в шине (включая `analytics.*`), снапшоты, индексы семантической памяти, логи всех сервисов **и бота**, промпты, **тогда** в них нет Telegram ID и username — только `player_id` и имя персонажа.
- **Дано** игрок вводит имя персонажа, совпадающее с его username, **когда** регистрация обрабатывается, **тогда** бот предупреждает и просит подтвердить; после подтверждения тест NFR-041 проверяет отсутствие внешнего **ID** (числового), а не строки имени (DR-10).
- **Дано** игрок отправляет `/forget`, **когда** game-service подтверждает, **тогда** запись связки удалена физически (`strings` по файлу связок и WAL не находит id — SEC-04), повторный `/start` с того же аккаунта не находит персонажа и показывает подтверждение заново, а по `player_id` нельзя получить внешний ID.
- **Дано** «Вася» (`player-A`, HP 7/10, в группе с «Леной» и «Олегом», лидер) отправляет `/forget`, **когда** запрос обработан, **тогда** персонаж `player-A` остаётся в мире со статусом `abandoned` (не удалён из графа и снапшотов), исключён из группы событием `group.left {cause: forget}`, лидером стала «Лена» (`group.leader_changed {cause: forget}`), сессия «Васи» закрыта (`analytics.session.ended end_reason=forget`), недоставленные ему сообщения помечены `dropped`, волк его целью не выбирает (FR-061, G2).
- **Дано** тот же аккаунт после `/forget` проходит `/start` и регистрацию заново с именем «Вася-2», **когда** персонаж создаётся, **тогда** это новая связка и **новый** `player_id` (`player-D`) с начальным состоянием; `player-A` остаётся `abandoned`, его история к `player-D` не привязана; вернуть `player-A` командой нельзя (FR-061 п. 4).
- **Дано** связка удалена, **когда** оператор пытается найти персонажа по внешнему ID, **тогда** результат пуст; игровая история по `player_id` (реплики `player.said`, имя персонажа, нарратив, `llm.output`) остаётся в журнале до retention 30/90/180 дн. и истекает вместе с ним (полное забвение — US-035); сроки совпадают с названными в `/start` (US-008).
- **Дано** активная встреча группы, в которой «Вася» единственный `active` участник с открытым раундом, **когда** он отправляет `/forget`, **тогда** раунд закрывается без его действия (он не в `expected[]`), встреча продолжается для остальных или завершается по FR-012, ошибок у остальных нет.
- **Дано** команда `/forget` от аккаунта без персонажа, **когда** обрабатывается, **тогда** возвращается «нечего удалять», ошибок нет.
- **Дано** библиотека бота логирует входящие обновления, **когда** проверяется конфигурация логов, **тогда** уровень логирования исключает пейлоады с `user_id`, retention логов бота ≤ 7 дней (DR-21).

## US-010: Запуск стека одной командой и здоровье сервисов

**Как** оператор, **я хочу** поднять весь стек MVP-1 одной командой и увидеть, что всё живо,
**чтобы** не собирать окружение вручную перед каждой сессией.

## US-011: Восстановление из снапшота и replay

**Как** оператор, **я хочу** перезапустить все сервисы посреди сессии и чтобы игрок продолжил с того же места,
**чтобы** сбой или обновление не ломали мир.

Приоритет: Must · Связь: FR-031…FR-033, FR-087, FR-100, BR-04, NFR-010, NFR-011

### Критерии приёмки
- **Дано** игрок сыграл 10 ходов (волк ранен, HP игрока 6/10), последний снапшот сделан после хода 7, **когда** оператор перезапускает все сервисы, **тогда** после старта состояние волка и игрока соответствует ходу 10 (снапшот + догон событий 8–10), `laws_version` из снапшота действует, и игрок может сделать ход 11.

## US-018: LLM-выводы как события (аудит промптов)

**Как** разработчик, **я хочу** видеть каждый вызов модели как событие с промптом, ответом, агентом и версией законов,
**чтобы** отлаживать промпты и объяснять решения роя.

- **Дано** сумма `tokens` по `llm.output` за 100 вызовов, **когда** сверяется с отчётом Ollama, **тогда** погрешность ≤ 5 % (NFR-052).

- **Дано** «Вася» вышел из региона, и между его сессиями прошло ≥ N часов (в тесте — эквивалент ≥ 2 региональных тиков), **когда** он отправляет `enter dark-forest-01`, **тогда** в регионе произошло ≥ 1 фоновое событие, и нарратив входа от персонального GM его отражает (проверка: факт события есть в сводке FR-127 и в тексте нет противоречия ему — погода, положение NPC).
- **Дано** мир без игроков в течение часа при бюджете B = 4, **когда** считаются `llm.output` фоновых агентов за этот час, **тогда** их ≤ B; персональные GM и Task-агенты не порождали вызовов (0).
- **Дано** LLM недоступна, **когда** срабатывает фоновый тик, **тогда** тик выполняется в LOD 1 (таблица событий/правила), событие всё равно публикуется (или тик завершается «без изменений» явным событием), ошибок нет.
- **Дано** «Вася» ранен (HP 4/10) и вне сессии, **когда** проходят фоновые тики, **тогда** его HP, позиция, инвентарь и статус не меняются; `combat.decided` против него отсутствует (FR-128).
- **Дано** «Вася» убил `wolf-alpha`, **когда** проходят фоновые тики в течение TTL региона (по умолчанию 24 ч), **тогда** волк не возрождается; после TTL блупринт может породить нового волка по `npc_table` событием `npc.spawned` с новым `entity_id` (`npc_table` — только респаун; стартовый волк создан фикстурами `mvctl world init --fixtures`, G2).
- **Дано** «Вася» вошёл в регион, где живой волк в радиусе восприятия, **когда** срабатывает ближайший «активный» тик региона (интервал 60 с; в тесте ускорен, при replay — из `tick.fired`), **тогда** GM региона порождает встречу (`encounter.started`) не позднее одного интервала после `enter`; до тика встреча не начинается, `look` до тика описывает регион без боя (FR-012, FR-124, A-19).
- **Дано** последний игрок покинул регион, **когда** проходит следующий тик, **тогда** интервал тиков региона возвращается к фоновому (30 мин), число `tick.fired` региона за следующий час ≤ 2.
- **Дано** замер после сессии, **когда** сравниваются фоновые тики без игроков и действия игроков, **тогда** ни одно действие игрока не ждало завершения тика дольше порога NFR-001 (BR-10).

## US-037: Рой GM — иерархия событий от мира до игрока

**Как** исследователь, **я хочу** видеть, как событие глобального GM доходит до игрока через GM региона и персональный GM, и что ни один агент не лезет в чужой уровень,
**чтобы** убедиться, что рой работает как одна архитектура с разделением ответственности.

Приоритет: Must · Связь: FR-010, FR-120…FR-123, BR-12, BR-16, NFR-034

### Критерии приёмки
- **Дано** стек поднят с миром `dark-forest-world`, **когда** запрашивается список активных агентов, **тогда** есть ровно один агент уровня `global` мира, ровно один агент уровня `domain` для `dark-forest-01`, по одному персональному GM на каждого игрока в сессии, и Task-агенты только для активных встреч; все — по блупринтам Agent GM Core, legacy `GMInstance` = 0.
- **Дано** глобальный GM публикует `world.weather_changed {ливень}`, **когда** событие обрабатывается, **тогда** GM региона получает его (событие в контексте регионального агента), персональный GM «Васи» получает его в сводке/контексте и следующий нарратив «Васи» упоминает ливень; в трассе по `correlation_id` тика видна цепочка `global → domain → monitor/task` без прямых вызовов между агентами.
- **Дано** GM региона публикует `region.event_occurred {вой на севере}`, **когда** событие обрабатывается, **тогда** глобальный GM получает сводку (вверх), а игроки другого региона — нет (FR-003).
- **Дано** ответ GM региона содержит предложение изменить атрибут мира (погоду) или HP игрока вне встречи, **когда** он валидируется, **тогда** предложение отклоняется с `llm.output.rejected reason=level_violation`, состояние не меняется.
- **Дано** ответ персонального GM содержит событие `player.*` или `entity.update.proposed`, **когда** он валидируется, **тогда** оно отклоняется (`player_agency` / `level_violation`), нарратив доставляется без него.
- **Дано** два GM (региона и Task-агент) одновременно предлагают изменение одного NPC, **когда** entity-manager применяет их, **тогда** оба применены последовательно по версии сущности (или второе отклонено по конфликту версии с повтором), состояние не расходится (BR-03).
- **Дано** блупринт GM региона с `max_instances=1`, **когда** приходит второй `player.entered_region` в тот же регион, **тогда** второй экземпляр не создаётся, игрок добавлен в scope существующего агента.

### Оператор: отчёт по сессии

## US-038: Отчёт по сессии и журнал инцидентов

**Как** оператор, **я хочу** после каждой сессии получить одну таблицу: держится ли мир, сколько стоил LLM, как быстро отвечали, — и вести журнал инцидентов,
**чтобы** видеть, движемся ли мы к «регулярным сессиям без поломок» (S7), без БД и дашбордов.

Приоритет: Should (CLI) / Must (события сессии и CSV) · Связь: FR-085…FR-088, FR-101, BR-17, NFR-032

### Критерии приёмки
- **Дано** игрок отправляет первое действие в scope без активной сессии, **когда** game-service принимает его, **тогда** публикуется `analytics.session.started` с `session{id, kind, actor_kind=human, started_at, players_count}` без внешних ID и текста.
- **Дано** активная сессия, **когда** проходит ≥ 30 мин без действий (или все вышли/погибли), **тогда** публикуется `analytics.session.ended` с `end_reason` (`idle`/`leave`/`death`), `turns_count`, `turns_degraded`, `turns_failed`; следующее действие открывает новую сессию.
- **Дано** ход завершён (нарратив или шаблон доставлен всем адресатам), **когда** game-service фиксирует это, **тогда** публикуется `analytics.turn.completed` с `correlation_id`, `turn{seq, action_type, status, gm_path, phase1_mode}`, `timings{received_at, acked_at, mechanics_at, narrative_at}`, `narrative{generated_by, fallback_reason?, filter_applied}`, `delivery{recipients_count, delivered_count}`.
- **Дано** тест-харнесс с `actor_kind=ci`, **когда** он играет сессию, **тогда** её события помечены `actor_kind=ci` и не попадают в недельный счёт S7 (`session-report --weekly` считает только `human`).
- **Дано** завершённая сессия, **когда** оператор запускает `session-report <session_id>`, **тогда** получает таблицу `metrics.md` §6.1 (ходы, поломки, латентности p50/p95, вызовы/токены LLM по фазам и уровням, fallback, миграция) и строку в `ops/metrics/sessions.csv`; `--audit` сверяет снапшот с логом и публикует `analytics.consistency.violated code=state_divergence` при расхождении; `--json` сохраняет артефакт (FR-101).
- **Дано** оператор вручную правил состояние после сессии, **когда** он записывает строку в `ops/metrics/incidents.csv` с `manual_fix=true`, **тогда** недельный отчёт показывает `manual_fix_sessions ≥ 1` и сессия не засчитывается в «без поломки».
- **Дано** действие отклонено до Phase 1 (неизвестная цель), **когда** публикуется `analytics.turn.completed`, **тогда** `status=rejected`, `timings` содержит только `received_at`, `acked_at`, ход не входит в латентности.
- **Дано** событие `analytics.*` попало в лог, **когда** выполняется replay, **тогда** потребители replay его игнорируют (или оно в отдельном топике) и состояние не меняется.

## Часть 2. Целевое видение (заголовки для брифов эпиков)

### Ревьюер / автор мира (эпик E-B «Эволюция законов через пробой»)

## US-020: Пробой законов неординарным событием
**Как** автор мира (ревьюер), **я хочу** чтобы мир мог пережить катаклизм, который меняет его законы, но под моим постфактум-контролем, **чтобы** мир эволюционировал, не теряя целостности. Приоритет: Must (целевое; контракт — MVP-1 FR-045) · Связь: FR-041, FR-045, FR-046, BR-02
- **Дано** напряжение закона «мёртвые не возвращаются» достигло порога автора (или сработал авторский триггер), **когда** глобальный GM в фазе пробоя публикует `world.law_breach.proposed` с `laws_removed`, `laws_added`, `canon_invalidated`, **тогда** страж выполняет автопроверку (BR-02 п. 7), создаётся `laws@v2` со статусом `pending_review`, законы вступают в силу со следующего раунда во всех scope, игроки видят событие в нарративе, ревьюер получает diff законов и `canon_invalidated`.
- **Дано** предложение пробоя без `canon_invalidated` при наличии конфликта с каноном («волк мёртв»), **когда** страж проверяет, **тогда** публикуется `world.law_breach.rejected`, законы не меняются, напряжение не сбрасывается.
- **Дано** пробой в статусе `pending_review`, **когда** приходит второе предложение, **тогда** оно отклоняется с причиной `breach_pending`.
- **Дано** ревьюер отклонил пробой через 150 ходов, **когда** выполняется откат, **тогда** создаётся `laws@v3` с содержимым v1, факты под v2 помечены `retconned` (не удалены), HP/смерти/предметы не откатываются, откат отражён в нарративе явным событием.
- **Дано** окно ревью истекло без решения, **когда** проверяется статус, **тогда** он `approved` (допущение A-11) с записью `review_decided {reviewer_kind: timeout}`.
- **Дано** обычный ход (Phase 1/2) при напряжении ниже порога, **когда** LLM «предлагает катаклизм» в тексте, **тогда** пробой невозможен по построению (схема ответа его не содержит) — 0 пробоев без зафиксированного напряжения/триггера (NFR-025).

## US-021: Утверждение канона
**Как** ревьюер/автор, **я хочу** видеть предложенные LLM факты и утверждать их в канон, **чтобы** галлюцинация не становилась памятью мира. Приоритет: Must (целевое) · Связь: FR-043, FR-044, BR-01
- **Дано** факт со статусом `generated`, **когда** он утверждён, **тогда** получает статус `validated`, версию и попадает в `<canon>` промптов scope.
- **Дано** предложенный факт противоречит канону («мост цел» при каноне «мост разрушен»), **когда** он валидируется, **тогда** отклоняется автоматически с указанием конфликтующего факта.

### Игрок (эпик E-A «Living Worlds»)

## US-022: Автономные сущности поверх живого мира
**Как** игрок, **я хочу** чтобы отдельные NPC имели собственное поведение и цели, а не только события региона, **чтобы** мир ощущался населённым. Приоритет: Should (целевое) · Связь: FR-110, FR-017, BR-16
- **Дано** NPC подключён как Entity-Actor через зарезервированный контракт, **когда** проходит тик региона, **тогда** NPC совершает действие по своим правилам/целям в пределах бюджета LLM, событие имеет `trigger.event.type ∉ player.*` и отражено в `entity.updated` и нарративе.
- **Дано** Entity-Actor предлагает изменение сущности чужого региона, **когда** предложение валидируется, **тогда** оно отклоняется (`level_violation`), как и для агентов роя.

Примечание: фоновая жизнь мира через рой GM (тики глобального и регионального GM) перенесена в MVP-1 — см. US-036 (раунд 5).

## US-023: Эволюция правил с ревью
**Как** автор, **я хочу** получать предложения новых правил из наблюдаемых аномалий и утверждать их, **чтобы** баланс менялся прозрачно. Приоритет: Should (целевое) · Связь: FR-115, FR-046
- **Дано** аномалия устойчива (порог настроен), **когда** Monitor-агент предлагает правило, **тогда** автор видит предложение с оценкой баланса и может утвердить/отклонить; без утверждения правило не действует (ревью **до** применения — в отличие от пробоя).
- **Дано** правило утверждено, **когда** оно применяется, **тогда** игроки в затронутом scope получают нарративное объявление изменения (не «невидимый» баланс).
- **Дано** предложение правила пытается изменить закон мира (не формулу), **когда** оно валидируется, **тогда** отклоняется — законы меняются только автором или пробоем (FR-046).

### Игрок (эпик E-C «Культивация и Планы»)

## US-024: Ступени культивации с бутылочными горлышками
**Как** игрок, **я хочу** расти по ступеням, где прорыв требует накопления, постижения и испытания с риском, **чтобы** рост был осмысленным, а не гриндом. Приоритет: Must (целевое) · Связь: FR-111
- **Дано** игрок на пике ступени с выполненными условиями, **когда** он инициирует прорыв, **тогда** испытание даёт один из ограниченных исходов (успех / откат / травма), и прирост внутри новой ступени убывает по мере накопления.
- **Дано** игрок спамит одно умение, **когда** проходит 50 применений, **тогда** прирост стремится к нулю, а требование разнообразия не выполнено — прорыв недоступен.

## US-025: Портрет дао, переход между Планами и финал Ω
**Как** игрок, **я хочу** чтобы переход на следующий План определялся моим путём (портрет дао), а достижение Ω было финалом персонажа, **чтобы** история имела завершение. Приоритет: Must (целевое) · Связь: FR-112, BR-05 (исключение)
- **Дано** портрет дао и числовой минимум выполнены, **когда** игрок проходит испытание вознесения, **тогда** он переходит на План выше с отражением в мире; при провале — исход из ограниченного набора с максимальным штрафом, заданным правилами; LLM-оценка записана как `llm.output` с enum-исходом.
- **Дано** игрок достигает Плана Ω, **когда** финал сыгран, **тогда** персонаж переходит в статус `ascended_final` (ретирмент), дальнейшая игра им невозможна, история сохранена, персонаж остаётся в графе.

### Игрок (эпик E-D «Города и экономика»)

## US-026: Город с честным леджером и GM города
**Как** игрок, **я хочу** чтобы награды и торговля были реальными предметами и валютой, а город жил своими событиями, **чтобы** обещания NPC исполнялись. Приоритет: Should (целевое) · Связь: FR-113, FR-120
- **Дано** квест обещает награду, **когда** он выполнен, **тогда** награда выдаётся как сущности в инвентарь в пределах лимитов леджера.
- **Дано** игрок входит в город 100 раз, **когда** обрабатываются входы, **тогда** приветственный квест выдаётся один раз, популяция не растёт от входов.
- **Дано** GM города (Domain-уровень) тикает по расписанию, **когда** он предлагает событие региона за пределами города, **тогда** предложение отклоняется (`level_violation`).

### Автор мира (эпик E-E «Генерация миров»)

## US-027: Мир по описанию
**Как** автор, **я хочу** получить играбельный мир из текстового описания и законов вселенной, просмотреть и поправить его, **чтобы** не описывать каждый регион вручную. Приоритет: Should (целевое) · Связь: FR-114
- **Дано** описание мира и вселенная с законами, **когда** запущена генерация, **тогда** создаются регионы/города/канон и блупринты GM (глобальный, региональные), согласованные с законами (автоматическая проверка), и мир недоступен игрокам до утверждения автором.
- **Дано** сгенерированный элемент нарушает immutable-закон, **когда** проверка выполняется, **тогда** элемент отклоняется с указанием закона.

## US-028: Законы вселенной (бывш. US-001 из `Docs/user-stories`)
**Как** автор, **я хочу** задавать фундаментальные законы вселенной с типом immutable/default и версиями, **чтобы** все миры подчинялись единой логике. Приоритет: Should (целевое) · Связь: FR-094, FR-046, BR-01
- **Дано** вселенная с законом типа `immutable`, **когда** мир пытается его переопределить (автором или пробоем), **тогда** переопределение отклоняется; закон типа `default` переопределяется с записью версии.

## US-029: Онтологии-дуальности (бывш. US-002 из `Docs/user-stories`)
**Как** автор, **я хочу** задавать онтологии как пары полюсов со свойствами и взаимодействиями, **чтобы** правила мира выводились из их пересечений. Приоритет: Could (целевое) · Связь: FR-094, FR-114
- **Дано** мир с тегами полюсов, **когда** он создаётся, **тогда** взаимодействия полюсов становятся правилами мира и попадают в канон с источником `authored`.

### Внешний разработчик / игрок (эпик E-H «Контент и доступ»)

## US-030: Публичный API с аутентификацией (бывш. US-006)
**Как** разработчик внешнего фронта, **я хочу** подключиться к API с токеном и получать события своего игрока, **чтобы** сделать свой клиент. Приоритет: Should (целевое) · Связь: FR-008
- **Дано** валидный токен, **когда** клиент подписывается на события, **тогда** получает только события своего игрока/scope; без токена — 401.

## US-031: Реальный фильтр контента 18+
**Как** оператор, **я хочу** включить фильтр входа и выхода по политике «стены», **чтобы** открыть игру внешним игрокам. Приоритет: Must (целевое) · Связь: FR-053, FR-054, FR-056, BR-08
- **Дано** групповой scope, **когда** нарратив содержит контент из абсолютных запретов, **тогда** он не доставляется, инцидент записан в журнал; в приватной соло-сессии применяются только абсолютные запреты.
- **Дано** текст игрока содержит признаки реального намерения самоповреждения, **когда** он проходит `InputFilter`, **тогда** игрок получает ответ вне игры (контакты помощи), нарратив не генерируется (BR-08 (e), принято на G1; протокол — FR-054).

## US-032: Свободный текст с подтверждением намерения
**Как** игрок, **я хочу** писать действия своими словами и подтверждать необратимые, **чтобы** не зависеть от команд и не пострадать от ошибки распознавания. Приоритет: Should (целевое) · Связь: FR-007, BR-06
- **Дано** текст «думаю, не напасть ли на стражника», **когда** намерение распознано как атака, **тогда** перед необратимым действием запрашивается подтверждение; без подтверждения событие не публикуется.

### Оператор (эпик E-G «Наблюдаемость и операции»)

## US-033: LOD и бюджет на действие (бывш. AGM US-005)
**Как** оператор, **я хочу** чтобы детализация агентов подстраивалась под значимость события и бюджет, **чтобы** GPU хватало на всех. Приоритет: Should (целевое) · Связь: FR-017
- **Дано** бюджет исчерпан, **когда** приходит критическое событие (смерть игрока), **тогда** оно обрабатывается с приоритетом, а рутинные события и фоновые тики понижаются до правил без LLM.

## US-034: Дашборд оператора
**Как** оператор, **я хочу** видеть метрики стека и получать алерты, **чтобы** замечать проблемы до игроков. Приоритет: Should (целевое) · Связь: FR-082, FR-088
- **Дано** латентность Phase 2 p95 превышает порог 5 минут подряд, **когда** правило алерта активно, **тогда** оператор получает уведомление.

## US-035: Полное право на забвение
**Как** игрок, **я хочу** удалить не только связку, но и свою историю, **чтобы** реализовать право на забвение. Приоритет: Should (целевое) · Связь: FR-062
- **Дано** запрос на полное удаление, **когда** он выполнен, **тогда** события игрока нечитаемы (крипто-шреддинг/удаление), индексы перестроены, а целостность мира сохранена (ссылки помечены `redacted`).

## Новые термины для глоссария (предложения к v0.3)

- **Рой GM** — иерархия агентов на Agent GM Core: глобальный GM (`global`), GM региона/города (`domain`), Task-агент встречи (`task`), персональный GM игрока (`monitor`/`task`); одна архитектура — много агентов (BR-12, BR-16).
- **Персональный GM игрока** — агент, наблюдающий события в радиусе восприятия игрока и ведущий его нарратив; состояние не меняет, `player.*` не публикует (FR-123).
- **Фоновый тик / фоновое событие** — срабатывание глобального или регионального GM по расписанию без игроков и порождённое им событие мира/региона, записанное как обычное событие (FR-124, FR-126).
- **Бюджет фоновой жизни** — лимит вызовов LLM в час на мир для фоновых тиков (FR-125).
- **`level_violation`** — причина отклонения предложения агента, изменяющего сущность чужого уровня (BR-16).
- **Сессия** — серия ходов в scope с простоем ≤ 30 мин; `actor_kind: human|ci|sim` (FR-085, BR-17).
- **Опушка (`outside:{world}`)** — позиция вне регионов, стартовая и целевая для `leave`/`flee` (FR-001).
- **Лидер группы**, **`idle`**, **`out_of_combat`**, **раунд** — по BR-13/FR-025 (переводятся из «предложение DR-03» в проектные).
- **`quarantined`** — статус `llm.output`, задержанного фильтром категории (a), без `response_raw` (FR-050; принято на G1).

Предложения к v0.4 (после G2):

- **Покинутый персонаж (`abandoned`)** — статус персонажа после `/forget`: остаётся в мире и графе, не действует, не цель, исключён из scope и группы; связки не имеет, вернуть нельзя (FR-061, FR-023).
- **Allowlist (список допуска)** — перечень Telegram `user id` в конфигурации бота; единственный способ допуска игрока в MVP-1; проверяется до любого вызова gateway (FR-130).
- **Раундовое действие** — действие, открывающее раунд и входящее в `acted[]`: `attack`, `flee`, `defend`, `group leave` во встрече; `say`/`look` — ход без раунда, `status` — запрос чтения (FR-002, FR-025).
- **Активный тик региона** — тик GM региона с интервалом обнаружения (60 с) при наличии игроков в регионе; встреча порождается на тике, не при `enter` (FR-012, FR-124).
- **`filter_blocked` / `filter_error`** — причины `llm.output.rejected`: текст задержан фильтром категории (a) / сбой реализации фильтра (fail-closed) (FR-034, FR-050).
- **`law_violation`** — причина отклонения элемента вывода LLM, нарушающего инвариант законов `laws@vN` или содержащего устаревшую `laws_version` (FR-034, ADR-017).
- **Фикстуры мира** — файлы в Git, из которых `mvctl world init --fixtures` создаёт стартовое состояние мира; `npc_table` блупринта — только для респауна (§4.1 PRD).
