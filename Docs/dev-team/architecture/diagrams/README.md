# Диаграммы архитектуры

Дата ревизии: 2026-09-11 · system-architect#1 · плагин dev-team 0.6.0 (диаграммы — обязательный артефакт архитектурных ролей).

Каталог создан после волны 0 и первых задач волны 1. Каждый файл отвечает на один вопрос читателя (вопрос — первой строкой после заголовка), ссылается на документ, который иллюстрирует, и содержит один блок Mermaid.

## Правило этого каталога

**Диаграмма, расходящаяся с кодом, хуже отсутствующей.** Поэтому:

1. Источник истины для формы — **дерево репозитория**, а не текст документа. Где текст расходится с деревом, нарисовано дерево, а расхождение названо отдельной строкой в разделе «Расхождения с деревом» под диаграммой.
2. Того, чего нет, на диаграммах нет. Предусмотренное, но не написанное, помечено `(будущее)` в подписи узла и перечислено в разделе «Что здесь будущее».
3. Диаграмма не заменяет документ. Она показывает форму; смысл, гарантии и версии полей — в `contracts.md`, `overview.md`, `components/*.md`.

## Общая шкала зрелости на дату ревизии

Волна 0 (EPIC-001) закрыта: собран фундамент (`shared/*`, `cmd/multiverse`, реестр типов и схемы, compose, CI). Волна 1 начата: из семи контекстов платформы **написан один — `internal/mechanics`**; остальные шесть зарегистрированы в `cmd/multiverse/contexts.go` как пустые заглушки, отвечающие `/health`. Играбельный срез собран из двойников `shared/testkit/*` на памяти, а не из контекстов.

Поэтому на всех диаграммах различаются три вида узлов:

- без пометки — есть в дереве и работает;
- `(заглушка)` — есть в дереве, но это двойник из `shared/testkit/*`, а не контекст;
- `(будущее)` — в дереве нет, предусмотрено контрактом или эпиком.
