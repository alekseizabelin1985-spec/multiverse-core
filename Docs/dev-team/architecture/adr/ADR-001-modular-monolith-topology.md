# ADR-001: Модульный монолит — один Go-модуль, контексты как пакеты, число процессов как параметр деплоя; судьба 15 сервисов

Статус: предложено (к утверждению на G2) · Дата: 2026-09-09 · Автор: system-architect#1
Связи: OQ-A-04 (решено р1: одна машина, границы под рост), OQ-A-12 (политика workspace), OQ-A-15 (гигиена), OQ-A-17 (новый: удаление vs заморозка); FR-010, FR-014, FR-080, NFR-070, NFR-073, NFR-075, NFR-080, NFR-081; аудит `overview.md` §8–§9 (T2, T4, T9, T10, T13).

## Контекст

As-is: 15 микросервисов в 22 Go-модулях workspace на одной машине одного разработчика; из них 3 реализованы, 6 частично, 4 in-memory прототипа, 2 неработоспособны; ~30 разрывов издатель → потребитель; дубли клиентов LLM/MinIO ×4, движков правил ×3, Dockerfile ×5; CI на сборку отсутствует. Требования MVP-1: 1 мир, 1–3 региона, ≤ 6 игроков, ≤ 20 агентов (NFR-080, NFR-083); стек должен уместиться на RTX 4090 / 128 ГБ вместе с LLM (NFR-073); «число процессов — параметр деплоя, а не архитектуры» (NFR-075, решение р1 по OQ-A-04). Видение требует статуса «в пути / заморожен / удалить» для каждого сервиса (vision.md, цель 4).

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Оставить 15 сервисов, довести каждый | ничего не переносить | 15 процессов ради ≤ 6 игроков; 30 разрывов контрактов; дубли; сборка/тесты по 22 модулям; каждый прототип надо доводить до персистентности |
| B. Сократить до 6–8 сервисов с чёткими контрактами, отдельные модули | привычная микросервисная раскладка | по-прежнему N модулей и N Dockerfile; межпроцессная задержка на критическом пути механики (≤ 0,5 с); replay и трасса по нескольким процессам сложнее |
| **C. Модульный монолит: один модуль, контексты — пакеты `internal/<ctx>`, один бинарник с флагом `--contexts`, общение контекстов только через шину; деплой MVP-1 — 3 процесса + бот** | одна сборка и `go test ./...`; e2e в одном процессе без Docker; границы контекстов сохранены (пакеты + шина), поэтому позже любой контекст выносится в свой процесс без изменения кода домена; минимальный Dockerfile | нужна дисциплина границ (импорты между `internal/*` запрещены линтером); один процесс `core` — одна точка отказа (приемлемо на одной машине) |
| D. Один процесс на всё (включая gateway) | проще некуда | ПДн-хранилище связок в одном процессе с LLM-промптами и состоянием мира — хуже для NFR-041; нельзя перезапускать ядро без потери long-poll соединений бота |

## Решение

1. **Один Go-модуль** `multiverse-core.io` (`go 1.25`, `toolchain` пин на текущий патч; обновление до 1.26+ — отдельная задача). `go.work` удаляется; замороженные сервисы остаются со своими `go.mod`, но **не входят** в сборку (не в `go.work`, compose, Makefile), каталог получает `FROZEN.md` с причиной и эпиком возврата.
2. **Раскладка** (ориентир; детализирует архитектор команды):
   - `cmd/multiverse` — один бинарник, флаг `--contexts=gateway|state,mechanics,swarm,llm,laws|memory|all`, `--mode=live|replay`;
   - `cmd/telegram-bot`, `cmd/mvctl` (CLI оператора/исследователя);
   - `internal/gateway`, `internal/state`, `internal/mechanics`, `internal/swarm`, `internal/llm` (+`guardian`, `prompt`, `providers/*`, `filter`), `internal/laws`, `internal/memory`, `internal/replay`;
   - `shared/eventbus`, `shared/jsonpath`, `shared/entity`, `shared/contracts` (реестр типов + загрузка схем), `shared/agent` (типы блупринтов и уровней), `shared/objstore` (единственная обёртка MinIO), `shared/env`, `shared/logging`;
   - `blueprints/`, `rules/`, `laws/`, `schemas/events/`, `api/gateway.openapi.yaml`, `testdata/recordings/`, `ops/metrics/`.
3. **Правила зависимостей**: `internal/<a>` не импортирует `internal/<b>`, кроме явных библиотечных зависимостей `swarm → mechanics`, `swarm → laws`, `swarm → llm`; все прочие связи — через шину и `shared/contracts`. Проверяется `depguard`/`go vet`-правилом в CI.
4. **Деплой MVP-1**: процессы `gateway` (:8088), `core` (state+mechanics+swarm+llm+laws), `memory` (:8082, профиль `memory`), `telegram-bot`; инфраструктура Redpanda, MinIO, Qdrant, Neo4j (профиль `memory`), Ollama (профиль `gpu`).
5. **Судьба сервисов** (таблица `overview.md` §16): переписать — game-service, entity-manager, rule-engine; вывести — narrative-orchestrator (после миграции, S5), ban-of-world, reality-monitor; заморозить — world-generator, universe-genesis-oracle, ontological-archivist, cultivation-module, plan-manager, city-governor, entity-actor, evolution-watcher; оставить и доработать — semantic-memory. Удаление кода ban-of-world/reality-monitor и мёртвых пакетов (`shared/schema`, `shared/redis`, `fake_deps`, `test_minio.go`, дубли Dockerfile) — по OQ-A-17 (рекомендация: удалить; история git сохраняет).

## Последствия

- Позитивные: одна команда сборки, один CI-пайплайн, e2e без Docker, контракты между контекстами — те же события, что и между процессами (NFR-081); объём кода ядра сокращается (дубли ×4 → ×1).
- Негативные: миграция раскладки — разовая механическая работа (EPIC-001); ветки `claude/*`, `gm-*` устаревают — заморозить; при выносе контекста в отдельный процесс понадобится Redis для горячего контекста роя (ADR-004 отложил).
- Что придётся сделать: EPIC-001 (единый модуль, `--contexts`, линтер границ, compose с профилями, CI), `FROZEN.md` в 8 каталогах, обновить CLAUDE.md/AGENTS.md/README по факту (OQ-A-13, NFR-095).

## Дополнение 2026-09-11 (T-416, system-architect#1): место `membus`

**Пометка (T-428, 2026-09-11; переезд — T-418).** Переезд, описанный ниже как предстоящий, выполнен: `membus` — в `shared/eventbus/membus`, исключение линтера для `bus_memory.go` снято, единственный импорт `shared/testkit` в production-бинарнике — хук `fake_contexts.go` (T-255). Пункты 1–3 ниже — запись своего времени, не переписываются.

1. **`membus` — вторая реализация C-01, а не двойник.** Его гоняет тот же contract-тест шины, что и kafka-адаптер (`shared/testkit/contract`), и он же — транспорт поддерживаемого режима бинарника `--bus=memory` (e2e без Docker, отладка одного процесса; `foundation.md` §2, ADR-010). Реализация контракта живёт рядом с другой его реализацией: пакет переезжает из `shared/testkit/membus` в **`shared/eventbus/membus`** задачей EPIC-001 с меткой `contract-change`. 14 импортёров, все они — тесты и `cmd/multiverse/bus_memory.go`. Для хаос-режимов (`Duplicate`, `ReorderTopics`) переезд ничего не меняет: это часть режима, описанного в ADR-010 п. 4.
2. **До переезда** действует узкое временное исключение линтера. Файл `cmd/multiverse/bus_memory.go` может импортировать ровно пакет `multiverse-core.io/shared/testkit/membus$`, с `$` на конце: без него исключение открыло бы любой пакет с тем же префиксом (ревью #1 T-410, Mi-3). После переезда правило «production-бинарник не импортирует `shared/testkit`» (п. 8) снова знает одно исключение — хук `cmd/multiverse/fake_contexts.go` (T-255), который уходит с EPIC-003 I1. Исключение для `bus_memory.go` снимается тем же PR.
3. **Почему переезд, а не узаконенное исключение.** Иначе у одного пакета остаются два статуса: «заглушка для потребителей» (C-01 «Заглушка») и «транспорт режима» (`foundation.md` §2). К тому же карта владения называла единственным импортом testkit файл, которого нет. Такое расхождение должен развести контракт, а не `.golangci.yml`. Исключения depguard сравнивают пакеты по префиксу и уже дважды оказывались шире заявленного (T-410 Mi-3; правила `shared-testkit-*`, T-415).
4. **Уточнение п. 4 дополнения 2026-09-09.** Читать так: у процесса один HTTP-сервер, и его адрес — `MV_CORE_ADDR` при любом `--contexts`. В compose у сервисов литералы `:8088`/`:8090`/`:8082` рядом с опубликованным портом. Имена `MV_GATEWAY_ADDR`, `MV_MEMORY_ADDR` выведены (T-408).

## Дополнение 2026-09-13 (T-444, system-architect#1): границы импортов по планам EPIC-002/003/004

Основание — сверка планов трёх эпиков с `.golangci.yml` до старта первых волн (`contracts.md` v0.11, п. 1). Правило п. 3 и дополнения 2026-09-09 п. 2, 7 не меняются. Ниже — как план укладывается в них. Где нужна правка линтера, она названа, а сама правка — задача T-445.

Общий принцип выбора: **сначала перенос кода или передача данных без чужих типов, исключение линтера — только если двойник или клиент обязан говорить типами контракта.** Каждое исключение — точное имя пакета с `$` и листовое правило для пакета, в который оно открывает дверь. *Почему:* depguard сравнивает разрешения по префиксу и не видит транзитивных импортов. Исключение без `$` уже дважды оказывалось шире заявленного (T-410 Mi-3, T-415), а исключение в нелистовой пакет открывает всё, что тот импортирует.

1. **(1a) `internal/llm` не импортирует `internal/laws` и `internal/mechanics`.** Страж получает данные, а не типы:
   ```go
   // internal/llm/guardian
   type InvariantView interface{ Get(id string) (*entity.Entity, bool); ByType(t string) []*entity.Entity; WorldID() string }
   type InvariantFunc func(v InvariantView, touched []string) []Violation // Violation{InvariantID, EntityID, Message}
   type Input struct{ …; LawsVersion string; CheckKeys []string; Invariants map[string]InvariantFunc; … }
   ```
   Набор методов `InvariantView` совпадает с `mechanics.StateView` (а `guardian.StateView` видимости остаётся своим), поэтому адаптер `mechanics.Invariant → InvariantFunc` — несколько строк в `internal/swarm`, которому разрешены оба пакета. Повтор при устаревших законах шлюз делает через `LawsSource func(world string) (string, error)`, который передаёт рой. *Почему не `$`-разрешение:* `llm` — библиотека роя **и** памяти. Корень `llm` импортирует `guardian`, и `memory → llm` транзитивно тянул бы в процесс памяти законы и механику. Кроме того, тесты стража перестают зависеть от YAML правил, а в п. 3 не появляется новое ребро.
2. **(1b) Писатель записей LLM — не двойник.** `mvctl record` — функция оператора в production-бинарнике. Писатель `*.jsonl` живёт рядом с читателем того же формата: `internal/llm/providers/recorded.Writer`, а не `shared/testkit/swarm.RecordingWriter`. Фильтр SEC-23 (`actor_kind=ci`, фикстурные игроки) — в писателе. Линтер не меняется: `cmd/*` импортирует всё. *Почему не исключение из `no-testkit-in-production`:* оно вернуло бы второй импорт testkit в бинарник, который T-418 только что снял.
3. **(1c) Рой и подпакеты `llm`.** Production-файлам `internal/swarm` к корню `internal/llm$` добавляются `internal/llm/prompt$` и `internal/llm/guardian$`: `llm.Call` несёт `prompt.Sections` и `guardian.Input`. `internal/llm/parser$` — только если дизайн EPIC-003 оставит `Call.Schema parser.Schema`. Рекомендация — передавать имя схемы строкой, тогда `parser` рою не нужен. `internal/llm/providers/fake$` — **только** в `_test.go` роя, отдельным правилом по файлам `**/internal/swarm/**/*_test.go`. `filter`, `providers` и настоящие провайдеры рою запрещены. Попутно правило памяти сужается до `internal/llm$`, `internal/llm/providers$` в production и `providers/fake$` в тестах: сегодняшний префикс `internal/llm/providers` пропускает `openai_compat` и `fake` в production.
4. **(1d) Шаблоны деградации — в `internal/swarm/template`.** Двойник нарратора (`shared/testkit/swarm`) видит ровно `internal/swarm/template$` рядом с `internal/mechanics$`. Пакет шаблонов — листовой: `internal/*` не импортирует, это закрепляет отдельное правило. *Почему не `shared/agent/template`:* исключения `.golangci.yml` по пути `shared/agent/` (as-is код до T-201) молча сняли бы с нового пакета `errcheck`, `forbidigo`, `staticcheck` и `unused`.
5. **(1e) Двойники шлюза.** `FakeGateway` — in-process сервер поверх настоящего `internal/gateway` — живёт в **`internal/gateway/gatewaytest`** (образец — `net/http/httptest`) и в production не импортируется: запрет стоит рядом с `no-testkit-in-production`. Исключение для `_test.go` снимает только этот запрет; правила контекстов действуют и в тестах, поэтому тест роя или State `gatewaytest` не импортирует *(уточнение итерации 2 T-444 — ответ system-architect по реализации в T-445)*. `Harness` остаётся в `shared/testkit/gateway`. Он видит ровно `internal/gateway/client$` и `internal/gateway/api$` — Go-форму C-08, как двойник механики видит C-03. `client` — листовой пакет: импортирует только `api`. e2e, которому нужен `FakeGateway`, живёт вне `internal/<контекст>`: правила контекстов действуют и на тестовые файлы. *Почему не исключение на весь `internal/gateway`:* общему слою открылись бы SQLite, outbox и шина.
6. **(1f) Законы не импортируют рой.** `laws.Current(world)` берёт версию через интерфейс, объявленный потребителем в `internal/laws`:
   ```go
   type WorldVersions interface{ LawsVersion(worldID string) (version string, ok bool) }
   ```
   `WorldView` роя реализует его напрямую. `nil` — старшая `approved` версия из файлов (так работает `mvctl laws show`, и он печатает источник версии). Сигнатура C-12 не меняется, линтер тоже.
7. **Регистрация контекстов (к п. 8).** Порядок старта контекстов остаётся в одном файле `cmd/multiverse/contexts.go` (EPIC-001). Фабрики объявляются переменными пакета в файлах владельцев: `contexts_state.go`, `contexts_swarm.go`, `contexts_gateway.go`, `contexts_memory.go`. Все переменные пакета инициализируются до любого `init`, поэтому порядок не зависит от имён файлов. Контексты `llm`, `laws` и `swarm` одного процесса разделяют **один** экземпляр шлюза LLM и сервиса законов: иначе окна бюджета и учёт расходятся по двум экземплярам. `runtime.Deps` экземпляры не передаёт, поэтому стек создаётся один раз в `contexts_swarm.go`. Код — T-446 (EPIC-001, раскладка) и задача EPIC-003 (подключение стека).

*Условия пересмотра.* Любое новое исключение по этому образцу оформляется так же: имя с `$`, листовое правило, мутанты «соседний пакет», «подпакет», «из production-файла». Если исключений в `shared/testkit` станет больше трёх, двойники контрактов стоит перенести в пакеты `internal/<контекст>/<контекст>test` целиком.
