# ADR-014: Планировщик роя — две очереди LLM-заданий, уступка фона отменой вызова, `tick.fired` как источник времени, бюджет фона из журнала

Статус: предложено (к ревью system-architect#1) · Дата: 2026-09-09 · Автор: architect#2 (TEAM-2, EPIC-003) · Уровень: реализация блока
Связи: ADR-002 п. 5, ADR-003 п. 4/6, ADR-005 п. 2; overview §14 п. 6, §17.3, §20 п. 10; FR-124…FR-128, BR-10, BR-16 п. 6; NFR-001, NFR-002, NFR-007, NFR-014, NFR-053; UC-018 A3, UC-019, UC-024; C-06; `components/swarm-llm-laws.md` §7.

## Контекст

Системный архитектор зафиксировал: две очереди в рантайме роя (`interactive`, `background`), «воркер фона уступает», тики 60/30 мин, бюджет ≤ B вызовов/час/мир, `tick.fired` публикуется до выполнения и служит источником времени в replay. Нужно решить, как именно фон уступает при одном GPU и `OLLAMA_NUM_PARALLEL=1` (вызов нельзя «приостановить»), где живёт счётчик бюджета, чтобы он пережил рестарт и replay, и как Phase 1 гарантированно не ждёт LLM. As-is `WorkerPool` (`shared/agent/worker_pool.go`) — один канал без приоритетов и без backpressure; `lod.go` — адаптивный LOD по «плотности игроков», в MVP-1 не нужен (фиксированный LOD, ADR-002 п. 8).

## Рассмотренные варианты

| Вопрос | Вариант | Плюсы | Минусы |
|---|---|---|---|
| Приоритет | одна очередь с приоритетом в задании | просто | фоновое задание, уже ушедшее в Ollama, занимает GPU до 30 с — NFR-002 нарушается |
| | **две очереди + окно тишины + отмена фонового вызова** при появлении интерактивного | интерактив стартует немедленно; GPU освобождается по закрытию соединения | отменённая попытка «сгорает» (записывается как `error/yielded`); тик уходит в `rule-only` |

| | **синхронно в обработчике события агента** | ≪ 10 мс, никогда не ждёт | обработчик агента не должен блокироваться на I/O (соблюдается: только `Emit`) |

| Время тика | `time.Now()` в агенте | привычно | недетерминизм; replay даёт другое «время суток» |

| Пропущенные тики | догнать пачкой | «честно» | всплеск вызовов после простоя; отклонено overview §20 п. 10 |

## Решение

1. **Две очереди** `interactive` (Phase 2 `turn|round|entry|death|world_event`) и `background` (LLM-фаза тиков). Один LLM-воркер (`SWARM_LLM_WORKERS=1`, соответствует `OLLAMA_NUM_PARALLEL=1`). Воркер берёт `background` только при пустой `interactive` и тишине интерактива ≥ `SWARM_BACKGROUND_QUIET=5s`.
2. **Уступка**: (а) фоновое задание, ждущее > `SWARM_BACKGROUND_MAX_WAIT=30s`, выполняется в `rule-only`; (б) при поступлении интерактивного задания во время фонового вызова контекст вызова отменяется, попытка записывается `llm.output validation_status=error error.code=yielded`, тик завершается по таблице `background_events` (`rule-only`), интерактивное задание стартует немедленно. Запись `yielded` делает replay детерминированным (та же ветка).
3. **Phase 1 (`rules`) выполняется синхронно** в `Behaviour.OnEvent`, минуя очереди; обработчик агента не делает сетевого I/O, кроме публикации в шину.
4. **Тики**: `next_tick_at` на timer-агента; интервал по `Tick.Mode` (`idle`/`active`, для `domain` — по наличию игроков в регионе из `ScopeIndex`); цикл планировщика — тикер `Clock` 1 с; `tick.fired {tick{seq, mode, scheduled_at, fired_at, lod_allowed}, budget{window_calls, cap}}` публикуется **до** выполнения; после выполнения `next_tick_at = now + interval` (один тик после простоя); admin-тик `FireNow` публикует тот же `tick.fired` с `meta.actor_kind=ci`. В `mode=replay` тикер выключен, `tick.fired` читаются из журнала, `FireNow` доступен харнессу.
5. **Время**: агенты не вызывают часы; «сейчас» для тика = `tick.fired.timestamp`, для хода = `timestamp` события-причины; RNG тика — `mechanics.Seed(tick.id, i)`.
6. **Бюджет фона**: `BackgroundBudget` на мир — окно 1 ч, наполняемое из `llm.output` с `meta.actor_kind=system, meta.replay=false` (live и догон); `cap` = `budget.background_calls_per_hour_world` блупринта `global-gm`; `lod_allowed` вычисляется при публикации `tick.fired` и агентом не пересчитывается; второй рубеж — middleware бюджета шлюза по ключу `(world, level∈{global,domain}, phase=tick)`. Окно дублируется в снапшот роя.
7. **Порядок на агента**: per-instance FIFO (одна горутина на экземпляр), между агентами параллельно; задания `personal-gm` и `group-narrator` дополнительно сериализованы по `correlation_id`.
8. `shared/agent/worker_pool.go` удаляется; `lod.go` остаётся без использования до E-G.

## Последствия

- Позитивные: NFR-001/NFR-002 не зависят от фона; бюджет фона и `lod_allowed` воспроизводимы в replay; одна точка отмены вместо «умных» приоритетов; планировщик тестируется на `FakeClock` без Ollama.
- Негативные: отменённая попытка тика теряет уже потраченные секунды GPU (≤ 1 тик за интерактивный всплеск); при частых ходах фон почти всегда `rule-only` — это ожидаемо (BR-10).
- Что придётся сделать: `internal/swarm/scheduler.go`, `budget.go`; тесты §18 компонентного документа; `SWARM_*` в `.env.example`; провайдер Ollama обязан уважать отмену контекста (закрытие соединения).
