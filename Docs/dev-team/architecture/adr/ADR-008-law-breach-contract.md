# ADR-008: Контракт пробоя законов в MVP-1 — `laws@vN` как версионированный документ, `laws_version` везде, типы зарегистрированы, механика отключена флагом

Статус: предложено (к утверждению на G2) · Дата: 2026-09-09 · Автор: system-architect#1
Связи: OQ-R-11 (р2), OQ-D-09, OQ-D-12, OQ-D-18 (G1: автоодобрение по таймауту), OQ-D-19 (G1: `immutable` не пробивается); FR-040…FR-046; BR-01, BR-02, BR-11; NFR-020, NFR-025, NFR-026, NFR-043; `domain-review.md` §3.1; `data-model.md` §6.4, §6.5, §9.8; `api-contracts.md` §2.3.13.

## Контекст

Ключевое доменное требование пользователя: LLM может породить неординарное событие, разрушающее старые законы и образующее новые, с контролем постфактум. Доменный эксперт оформил механику (напряжение, фаза пробоя, автопроверка стража, `pending_review`, откат-ретрокон), PRD ограничил MVP-1 контрактом (BR-02 п. 12, FR-045). Нужно решить, где живут законы, как `laws_version` пронизывает систему, как страж проверяет инварианты уже сейчас, и что именно резервируется под E-B, чтобы не переделывать контракты.

## Рассмотренные варианты

| Вопрос | Вариант | Плюсы | Минусы |
|---|---|---|---|
| Где хранить законы | сущность `World.laws[]` в State | всё в одном писателе | правка законов автором = предложение к сущности; версии законов смешиваются с версией мира |
| | **отдельный версионированный документ `laws/{world}.v{N}.yaml` в Git + объект в MinIO при пробое** | автор правит файл; `v1` воспроизводим; E-B пишет `vN+1` объектом | два источника (Git для авторских, MinIO для порождённых) — унифицируется загрузчиком `Laws` |
| Где проверять инварианты | только тест-харнесс | ничего в рантайме | мир может сломаться между тестами |
| | **State (числовые инварианты при применении) + страж LLM-шлюза (предложения) + `mvctl --audit` (сверка)** | три рубежа, каждый дёшев | дублирование списка инвариантов — снимается общим `laws@v1` |
| Инициатор пробоя в MVP-1 | разрешить фазу пробоя сразу | «функция есть» | без напряжения/ревью — дрейф мира; отклонено PRD |
| | **выключена флагом; типы и поля зарезервированы** | контракт стабилен для E-B; ноль риска в MVP-1 | пробой не демонстрируется до E-B (S11 — целевой) |

## Решение

1. **Документ законов** `laws/dark-forest-world.v1.yaml`: `{version: v1, world_id, status: approved, created_by: author, laws: [{id: inv-1, kind: invariant, text, check: <ключ проверки из фиксированного словаря>}, …, {id: law-…, kind: declarative, text, source: author}]}`. Инварианты NFR-020 (1–10) — первые законы; декларативные законы блупринта мира — далее. Контекст `internal/laws` загружает файлы из `laws/` и объекты `laws-{world}/vN.json` из MinIO (E-B), отдаёт `Current(world) → LawsVersion` и `Get(world, version)`; ручная правка автором — `mvctl laws bump --world … --from laws/….vN+1.yaml` → `world.laws.changed {created_by: author, status: approved}` + обновление `World.laws_version` через `entity.update.proposed` от `actor_kind=system, cause=laws`.
2. **`laws_version` пронизывает**: `World.laws_version` (State), контекст каждого агента (перезагрузка законов по `world.laws.changed`), `payload.laws_version` в `llm.output`, `narrative.output`, `snapshot.created`, `world.laws.*`; снапшоты State и Swarm. Страж отклоняет вывод с устаревшей версией (`law_violation`, инвариант 11).
3. **Три рубежа проверки** уже в MVP-1: (а) State — числовые инварианты при применении предложений (`law_violation` с `invariant_id`); (б) страж LLM-шлюза — предложения агентов против `allowed_event_types`/`owned_entity_types` и инвариантов; (в) `mvctl session-report --audit` и тест-харнесс — сверка снапшота с агрегатом журнала → `analytics.consistency.violated {layer: law|canon|state|momentary}`.
4. **Зарезервированные типы** (реестр ADR-007, схемы в `schemas/events/`): `world.laws.changed`, `world.law_breach.proposed / rejected / applied / review_decided / rolled_back` — поля по `api-contracts.md` §2.3.13 без изменений; обработчиков в MVP-1 нет; `mvctl contracts check` допускает их как «зарегистрированы, издатель E-B».
5. **Флаги и точки расширения**: `LAWS_BREACH_PHASE_ENABLED=false` (фаза пробоя в конвейере `global`/`domain` агентов — отдельная схема ответа `breach.json`, не Phase 1/2); `strain` — счётчик напряжения по закону в `internal/laws` (интерфейс есть, инкременты — от стража при `law_violation` и от Monitor-агента E-A; в MVP-1 только накапливается и виден в `mvctl laws show`); уровень `monitor` — страж-аномалий (E-A/E-B).
6. **Семантика E-B (фиксируется контрактом сейчас)**: `immutable`-законы вселенной не пробиваются (`rejected reason=immutable_touched`); формулы механики пробой не меняет (`formula_change`); применение — с границы следующего раунда во всех scope мира (`effective_from.round_boundary=true`); один `pending_review` на мир (`breach_pending`); истечение окна ревью → `review_decided {decision: approved, reviewer_kind: timeout}`; откат — `vN+2 = vN`, факты под `vN+1` помечаются `retconned` в памяти, числовое состояние не откатывается; replay фазы пробоя — из `llm.output phase=breach`.
7. **Защита от инъекции** (NFR-043): фаза пробоя не читает `<player_text>`; `player.said` не входит в контекст фазы пробоя по построению; тест с 10 инъекциями — 0 `world.law_breach.proposed`.

## Последствия

- Позитивные: S11 достижим без смены контрактов; инварианты «Тёмного леса» проверяются в трёх местах уже в MVP-1; `laws_version` в каждом `llm.output` даёт аудит при ретроконе.
- Негативные: два источника документов законов (Git и MinIO) — скрыты загрузчиком; напряжение в MVP-1 — только счётчик без последствий.
- Что придётся сделать: EPIC-003 — `internal/laws`, файл `laws/dark-forest-world.v1.yaml`, страж, `mvctl laws bump/show`; EPIC-007 (E-B) — фаза пробоя, ревью, откат, Monitor-агент.
