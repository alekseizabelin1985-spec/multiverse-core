# ADR-009: Безопасность данных игроков — псевдонимизация на входе, изолированное хранилище связок, фильтр категории (a) fail-closed, облако за флагом, гигиена секретов

Статус: предложено (к утверждению на G2) · Дата: 2026-09-09 · Автор: system-architect#1
Связи: OQ-D-04 (р3), OQ-D-14, OQ-D-16 (G1), OQ-D-17 (G1), OQ-A-11 (р3), OQ-A-14; FR-009, FR-050…FR-056, FR-060…FR-062, FR-083; BR-07, BR-08, BR-09, BR-15; NFR-040…NFR-048; `integrations.md` §7; `domain-review.md` §3.4, §3.5, DR-10, DR-14, DR-21.

## Контекст

As-is: регистрация без согласия, `player_id` задаёт клиент, WS-широковещание всем, секреты (`.mcp.env` с токенами) в истории git, значения по умолчанию `minioadmin`/`neo4j/password`, логи с пейлоадами. Решения: псевдонимизация в game-service, связка отдельно и удаляема, уведомление об ИИ и 18+, фильтр только категории (a) fail-closed с `quarantined` без `response_raw`, облако только через абстракцию, секреты — гигиена индекса, `git filter-repo` — по явной команде.

## Рассмотренные варианты

| Вопрос | Вариант | Плюсы | Минусы |
|---|---|---|---|
| Хранилище связок | вместе с сущностями в MinIO | ничего нового | ПДн рядом с состоянием мира и промптами; удаление — версии объектов остаются (versioning) |
| | **отдельный SQLite-файл `links.db` в томе gateway** | физическое удаление; отдельный бэкап/шифрование; единственная копия | одна точка (приемлемо; бэкап по политике оператора) |
| `player_id` | производная от внешнего ID (хэш) | простая связка | обратима перебором для Telegram ID (числа) — нарушает NFR-042 |
| | **случайный `player-<ulid>`** | необратим по построению | нужна таблица связок (она и так есть) |
| Фильтр (a) | в боте | ближе к экрану | `response_raw` уже записан; бот — не место политики контента |
| | **в LLM-шлюзе до записи `llm.output`** (ADR-005) | fail-closed до сохранения; один код для всех клиентов | — |
| Секреты | только `.gitignore` | быстро | история хранит токены — пользователь отзывает сам (р3) |
| | + `gitleaks` в CI/pre-commit | ловит новые утечки | ложные срабатывания — allowlist |

## Решение

1. **Псевдонимизация** (BR-07, FR-060): gateway генерирует `player_id = "player-" + ULID` при создании персонажа; внешний ID принимается только `POST /v1/links/*` и `POST /v1/characters`; тела этих запросов не логируются; во все события, хранилища, промпты, аналитику и логи попадает только `player_id` и имя персонажа. Тест NFR-041 сканирует MinIO, все топики, Qdrant, Neo4j, логи всех процессов и бота на числовой внешний ID и username.
2. **Хранилище связок** — `links.db` (ADR-004): единственная копия связи; `/forget` и `DELETE /v1/admin/links/{player_id}` — `DELETE` строки + отмена доставок + закрытие сессии + выход из группы; восстановление внешнего ID по `player_id` невозможно (нет другой копии; `previous_player_ids` не хранятся в MVP-1). Резервная копия `links.db` — по политике оператора (шифрование `age`/`gpg`, срок ≤ 30 дней) — фиксируется DevOps в `infrastructure.md`.
3. **Согласие и уведомление** (FR-009, BR-09): `notice_shown_at`, `consent_at`, `age_confirmed_at` обязательны для `consented`; создание персонажа невозможно без них (`403 consent_required`); `generated_by` в каждом `narrative.output` и `Delivery`; повтор уведомления по `/help` и через 30 дней (`last_seen_at`).
4. **Бот**: не использует `username`/имя профиля/фото ни для чего, кроме доставки; предупреждение при совпадении имени персонажа с username — на стороне бота; логи бота — без пейлоадов обновлений, `retention ≤ 7 дней` (ротация файлов/journald), уровень `info` без текста.
5. **Контент** (FR-050/051/056): `NarrativeFilter` категории (a) — middleware LLM-шлюза, словарь и регулярные выражения в `config/absolute-limits.yaml` (не в коде), fail-closed (ошибка фильтра → `filter_error`, текст не доставляется, `llm.output` без `response_raw`, `content.incident.recorded`); `InputFilter` — пустышка с журналом на `say` и имени персонажа; системный промпт получает короткую позитивную формулировку BR-08 из того же файла; полный список BR-08 (7 пунктов) — в контракте фильтра, остальные категории в MVP-1 не фильтруются (р3, G1). Золотой набор NFR-065: 0 ложных срабатываний.
6. **Инъекции** (FR-055, NFR-043): текст игрока и имена сущностей — в секции `<player_text>`/`<state>` как данные с экранированием `<`/`>`; схема Phase 2 не содержит полей действий/событий, схема тика — только `allowed_event_types`; фаза пробоя не читает текст (ADR-008).
7. **Облако** (BR-15, NFR-046): выключено по умолчанию; включение — флаги ADR-005 п. 6 с записью `config.cloud_enabled` в журнал; за рубеж уходят только `player_id`, имена персонажей, текст `say` (о чём сказано в уведомлении FR-009).
8. **Секреты и конфигурация** (FR-083, NFR-040): `.env`, `.mcp.env` — вне индекса (`git rm --cached`), `.gitignore` расширен, `.mcp.env.example` и `.env.example` — полные (NFR-074); `gitleaks` в CI и pre-commit; compose без паролей по умолчанию (`MINIO_ROOT_PASSWORD`, `NEO4J_AUTH` — только из `.env`); токен бота — только env. Очистка истории (`git filter-repo`) — **не** выполняется без явной команды пользователя (OQ-A-11, D6); до неё токены считаются скомпрометированными и отозваны пользователем.
9. **Аутентификация** (OQ-A-14): MVP-1 — доверенный контур, `X-Client-Id` из списка, `X-Actor-Kind: ci|sim` только для разрешённых клиентов; сетевая изоляция — compose-сеть, порт gateway привязан к `127.0.0.1`; при первом внешнем клиенте — токен клиента (E-H).
10. **Право на забвение** (FR-062, целевое E-H): события помечены `player_id`; полное удаление истории потребует крипто-шреддинга (ключ на игрока для `player.said`/`narrative.output`) или перестройки журнала — архитектурная заметка для E-H, в MVP-1 не реализуется.

## Последствия

- Позитивные: приватность проверяется тестом, а не обещанием; удаление связки физическое; фильтр (a) не даёт сохранить недопустимый текст.
- Негативные: ULID вместо «говорящих» `player_id` в логах — компенсируется именем персонажа; бэкап `links.db` — ручная политика.
- Что придётся сделать: EPIC-001 — гигиена секретов, gitleaks, compose без дефолтных паролей; EPIC-004 — links/consent/forget, ULID, логи бота; EPIC-003 — фильтр (a), `config/absolute-limits.yaml`, экранирование; security-engineer — модель угроз `architecture/threat-model.md` на стыках gateway↔core и облако.

## Дополнение 2026-09-09 (сведение A3 шаг 4; `threat-model.md` §8)

1. **Allowlist (SEC-06/07, решение пользователя)**: круг игроков ограничен списком Telegram user id в конфигурации бота (`MV_TELEGRAM_ALLOWED_USER_IDS`), проверка до любого вызова gateway; только личные чаты; инвайт-коды — E-H (ADR-006 дополнение п. 1–2).
2. **Идемпотентность `POST /v1/characters` без внешнего ID в `gateway.db` (SEC-03, п. 1 уточнение)**: при `links/resolve` связке присваивается суррогат `link_id` (ULID, хранится только в `links.db`); ключ идемпотентности создания персонажа = `(link_id, action_key)` — таблица `character_requests` живёт в `links.db` (каскадно удаляется при `/forget`); `gateway.db` (`pending_characters`, `idempotency_keys`, `turns` …) содержит только `player_id`/`link_id`, ни одного поля с внешним ID; тест NFR-041 сканирует оба файла и WAL. HMAC-вариант не нужен: `link_id` случаен и необратим.
3. **Непубликация всех портов (п. 9 уточнение, SEC-13)**: правило `127.0.0.1` распространяется на **все** контейнеры compose — Redpanda (19092, 9644), MinIO (9000/9001), Qdrant (6333/6334), Neo4j (7474/7687), Ollama (11434), Redpanda Console (8092), `core` admin (8090), `memory` (8082), gateway (8088); job `compose-lint` проверяет, что каждая публикация имеет вид `127.0.0.1:<host>:<container>`, а `redpanda-init`/`minio-init` не публикуют ничего. Внутри compose-сети сервисы доступны по именам; шина без SASL — принятый остаточный риск до первого внешнего клиента.
4. **Редакция токена бота (п. 4/8 уточнение, SEC-08)** — ADR-006 дополнение п. 3; логи бота — ротация по объёму, без ПДн по построению (ADR-006 дополнение п. 5).
5. **Записи LLM и golden только с `actor_kind=ci` (SEC-23)** — ADR-010 дополнение п. 1.
6. **`{client_id}` == `X-Client-Id` (SEC-12)**: `403 client_mismatch`; `route.external_id` выдаётся только клиенту платформы связки (C-08 v1.1).
7. **Rate limit и лимиты (SEC-11)**: бот — 20 команд/мин на user id; gateway — 30 действий/мин на `player_id` (burst 5), один long-poll на `client_id`, тело ≤ 64 КиБ (C-08 v1.1).
8. **`links.db` (SEC-04/05)**: `secure_delete=ON`, `wal_checkpoint(TRUNCATE)` + `incremental_vacuum` сразу после `/forget` (ADR-004 дополнение п. 4).
9. **Инъекция второго порядка (SEC-17)**: `generated`-факты памяти — данные с экранированием (ADR-005 дополнение п. 4).
10. **Гигиена индекса (SEC-24, F-1)**: в F-1 входят `.claude/worktrees/*` (13 gitlink-записей — блокер `git status`, первый шаг), плейсхолдер вместо реального ключа в `shared/oracle/README.md` (ключ **реальный** — пользователь отзывает сам; до замены считать скомпрометированным), `.gitleaks.toml` allowlist — только `.env.example` и `.mcp.env.example` (не `README`, не `testdata/`, не `Docs/`; ложные срабатывания — точечные `gitleaks:allow` или fingerprint). OneDrive `Documents` не синхронизируется (пользователь) — SEC-30 снят.
11. **Уведомление FR-009 (SEC-26)** — текст дополняется BA: облако (если включено), сроки retention 30/90/180 дней, бэкап связки ≤ 30 дней, что удаляет `/forget`.
12. **Облако (п. 7 уточнение)**: `config.cloud_enabled` без ключей; блупринт не может включить облако (ADR-005 дополнение п. 3).
