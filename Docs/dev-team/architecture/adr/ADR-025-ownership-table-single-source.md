# ADR-025: Таблица владения — один файл в `shared/contracts`, без копии и без теста равенства

Статус: принято architect#1, **подтверждено system-architect#1 (T-416, 2026-09-11)** — см. раздел «Подтверждение» в конце · Дата: 2026-09-11 · Автор: architect#1 (TEAM-1)
Уровень: процедура контракта C-02 и `contracts.md` §16 п. 6. Затрагивает EPIC-002 (единственный проверяющий потребитель), EPIC-003 (T-202) и EPIC-004 (строка `gateway`); стек, стиль и границы блоков не меняются.
Связи: C-02 v1.4, `contracts.md` §16 п. 6 (v0.6), ADR-015 п. 4 (устаревает в части «экспорт»), ADR-002 п. 1; задачи T-006 (копия, сделано), T-202 (EPIC-003, `levels.go`); `diagrams/domains.md` и `diagrams/c4-component-swarm-llm-laws.md` (разделы «Расхождения с деревом»); `journal.md` 2026-09-11 (T-409).

## Контекст

C-02 v1.1 и §16 п. 6 (v0.4, TL2-3) объявили единственной истиной таблицы владения `shared/agent/levels.go` (EPIC-003), `shared/contracts/ownership.go` — её статичной копией, а тест равенства двух таблиц (T-202) — блокирующим merge. На 2026-09-11 в дереве:

- **копия есть**: `shared/contracts/ownership.go` покрыт `ownership_test.go`, его читает двойник State, на нём держится разбор ревью T-219;
- **истины нет**: в `shared/agent` лежит as-is Agent GM Core, ни одного целевого файла (`types.go`, `blueprint.go`, `parser.go`, `validator.go`, `levels.go`);
- **теста равенства нет**: сравнивать не с чем.

Документ объявляет истиной несуществующий файл. Фактически истиной служит копия, а процедура прямо это запрещает: «обратный порядок (правка копии без истины) запрещён».

Помимо того, что файла нет, против схемы «истина в `shared/agent`» говорят три структурных факта:

1. **В таблице не только уровни роя.** Строки `gateway`, `author`, `system` описывают тех, кто предлагает изменения без агента (C-02 v1.2: `/forget` шлюза). `levels.go` — реестр уровней роя. Строка шлюза в пакете роя — это данные EPIC-004 в пакете EPIC-003.
2. **«Экспорт в `shared/contracts` при сборке реестра» разворачивает зависимость.** Нужен либо импорт `shared/agent` из `shared/contracts` (фундамент EPIC-001 зависел бы от пакета роя EPIC-003), либо шаг генерации кода ради одной таблицы. ADR-015 п. 3 уже выбрал обратное направление: `shared/agent` не зависит от `contracts`, окружение валидатору передаёт вызывающий.
3. **Форма уже одна.** `OwnershipRule{Proposer, EntityTypes, Paths, Causes, Create}` написан, проверен и нужен одному проверяющему — State. Второй экземпляр тех же данных нужен только для того, чтобы их сравнивать.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Оставить процедуру и ждать `levels.go` (T-202) | ничего не переписывать | до T-202 истины нет, и копию правят в обход процедуры; строка `gateway` потом переедет в пакет роя; экспорт требует цикла или генерации |
| B. Создать `levels.go` сейчас отдельной задачей | процедура формально соблюдена | файл-заглушка ради теста равенства; две копии одной таблицы навсегда; проблемы 1–2 никуда не деваются |
| **C. Одна таблица в `shared/contracts/ownership.go`; `levels.go` — производный вид** | один источник, который уже существует и проверен; сравнивать нечего; зависимости идут в естественную сторону | владельцем файла становится EPIC-001 (system-architect), строки меняют команды через PR `contract-change` — ровно так, как уже принято для `shared/contracts/registry.go` (C-01, «Реализации для потребителей»; до T-431 — «Заглушка») |

## Решение

1. **Единственная истина таблицы владения — `shared/contracts/ownership.go`** (`contracts.OwnershipRules`). Слово «копия» из контракта убирается, теста равенства нет.
2. **Строку меняет владелец её семантики**: уровни роя (`global`, `domain`, `task`, зарезервированные `object`, `monitor`) — EPIC-003; `gateway` — EPIC-004; `author`, `system` — EPIC-002 (bootstrap и `mvctl world init`). Правка оформляется PR с меткой `contract-change` и ревью system-architect и tech-lead#1: EPIC-002 — единственный потребитель, который по таблице отказывает.
3. **`shared/agent/levels.go` (EPIC-003, T-202) остаётся реестром уровней для валидатора блупринтов, но таблицы владения не держит.** `AllowedEventTypes(level, role)` — данные роя о типах событий, не о путях сущностей, и живут в `levels.go`. Вид «какие типы сущностей у уровня» валидатор получает от вызывающего, собранный из `contracts.OwnershipRules`, — тем же способом, каким ADR-015 п. 3 передаёт реестр типов через `ValidationEnv`. Так `shared/agent` не получает зависимости на `shared/contracts`.
4. **Связка «путь ↔ причина» — норма C-02, а не форма таблицы.** Таблица — это декартово произведение путей и причин, поэтому она шире нормы: строка `gateway` формально пропускает `set status` с `cause=move`. Условия «`status` — только `alive → abandoned` с `cause=forget`» и «`hp` — только с `cause=rest`, вне встречи, не выше `hp_max`» проверяет каждая реализация State поверх таблицы. Это уже записано в комментарии `ownership.go`, теперь — и в C-02.

## Последствия

- **Позитивные.** Контракт перестаёт объявлять истиной несуществующий файл. State, валидатор блупринтов и страж опираются на одно место. Исчезает целый класс дефектов «копия разошлась с истиной».
- **Негативные.** Процедура TL2-3 отменяется, T-202 нужно переформулировать. Командам EPIC-003 и EPIC-004 для правки своих строк нужен PR в пакет фундамента — это цена, уже принятая для реестра типов.
- **Что придётся сделать в коде** (исполнитель — tech-lead#1 определяет задачу):
  - комментарии `shared/contracts/ownership.go` (блок над `ownershipRules`) и `shared/contracts/ownership_test.go` (заголовок) называют истиной `shared/agent/levels.go` и ссылаются на тест равенства T-202 — поправить на ADR-025. Правка только комментариев, но это пакет `shared/contracts`, поэтому метка `contract-change`;
  - EPIC-003 **T-202**: убрать «источник для `contracts.OwnershipRules`» и тест равенства; `OwnedEntityTypes` — из окружения валидатора, собранного вызывающим из `contracts.OwnershipRules` (правит tech-lead EPIC-003 в индексе задач).
- **Документы** приведены в T-409: C-02 v1.4, `contracts.md` §16 п. 6, ADR-015 п. 4, `analysis/api-contracts.md`, `components/foundation.md` §6, `components/state-and-mechanics.md`, `components/swarm-llm-laws.md` §2.
- **Условие пересмотра.** Если строке уровня роя понадобится условие, которое форма `OwnershipRule` не выражает и которое требует кода роя, — вернуться к варианту с генерацией, но истина и тогда останется одна.

## Подтверждение (system-architect#1, T-416, 2026-09-11)

Решение подтверждается без изменений. Процедура сведения 3 (TL2-3, `contracts.md` v0.4 §16 п. 6), которую оно отменяет, вводилась мной. Отменяю её по трём доводам:

1. **Процедура опиралась на факт, которого нет.** Она предполагала, что `shared/agent/levels.go` появится раньше, чем таблицу начнут читать. Вышло наоборот: таблицу читают двойник State и разбор ревью T-219, а `levels.go` ждёт T-202. Правило, которое с первого дня исполняется в обратном порядке, — не процедура, а источник расхождений.
2. **Направление зависимостей.** Истина в пакете роя требовала бы либо импорта `shared/agent` из фундамента, либо генерации кода ради одной таблицы. ADR-015 п. 3 уже выбрал противоположное направление — окружение валидатору передаёт вызывающий, — и ADR-025 п. 3 ему следует.
3. **Строки без агента.** Строки `gateway`, `author` и `system` в реестре уровней роя были бы данными чужих эпиков в пакете EPIC-003. В `shared/contracts` они лежат рядом с реестром типов, где владение по строкам уже принято (`Spec.Publishers`, §16 п. 7).

**Два уточнения. Решение они не меняют, только его исполнение:**
- Ревью PR, меняющего строку, выполняют system-architect и tech-lead#1, а автор PR называет в описании все блупринты, чьи `owned_entity_types` задевает правка. Этот список виден валидатору блупринтов только через окружение, которое собирает вызывающий, и без него ревьюер строки не увидит, кого она ломает.
- Сегодня тест `shared/contracts/ownership_test.go` покрывает строки всех трёх групп (рой, `gateway`, `author`/`system`). Это требование к любому PR, меняющему таблицу, а не свойство сегодняшнего теста: строка без теста — это та же копия без истины, только в одном файле.

Устаревшие ссылки на `levels.go` как на истину в плане и дизайнах эпиков исправлены в T-416. В `tasks.md` эпиков ссылки остаются, их исправит тимлид по списку из отчёта T-416: T-202 (EPIC-003 `tasks.md:53–56`), риск 9 и решение 3 (`:697`, `:709`), EPIC-002 `tasks.md:238`.
