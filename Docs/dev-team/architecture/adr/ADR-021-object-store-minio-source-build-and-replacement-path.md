# ADR-021: Объектное хранилище — MinIO из исходников на MVP-1 за минимальным интерфейсом `objstore`, без зависимости от bucket versioning; путь замены сервера по триггерам

Статус: предложено (к утверждению на G2; подтверждение владельца — OQ-A-20) · Дата: 2026-09-09 · Автор: system-architect#1
Связи: ADR-004 п. 1 (MinIO как хранилище состояния и снапшотов), ADR-004 дополнение п. 1–2, ADR-011 (объект на сущность, снапшоты, `latest.json`), ADR-013 (интент-объект), C-14; `infrastructure.md` §2.4, §5.2, §11 замечание 2; NFR-010, NFR-011, NFR-071 (пины образов), NFR-073; `foundation.md` §7 (`shared/objstore`).

## Контекст

ADR-004 выбрал MinIO как хранилище сущностей и снапшотов (объект на сущность, bucket versioning для «бесплатного» отката). После принятия ADR-004 devops-engineer установил (проверено 2026-09-09): MinIO Inc. прекратила публикацию Docker-образов и бинарников community-версии в октябре 2025 — последний образ на Docker Hub `RELEASE.2025-09-07T16-13-09Z`; фикс CVE-2025-62506 (`RELEASE.2025-10-15T17-29-55Z`) вышел только исходниками; в феврале 2026 репозиторий `minio/minio` архивирован. Пин на замороженный образ означает объектное хранилище без security-обновлений на неопределённый срок; сборка из исходников архивированного репозитория — то же самое, но с актуальным CVE-фиксом.

Что реально использует платформа от S3-сервера: `PutObject` (целиком, атомарная замена), `GetObject`, `ListObjects` по префиксу, `DeleteObject`, `StatObject`; bucket versioning — только как удобство отката (снапшоты и так ротируются K=5, сущность несёт `history ≤ 50` и `last_change`); ILM — истечение старых версий и промптов. Сервер слушает только `127.0.0.1`/compose-сеть на одной доверенной машине (ADR-009 дополнение п. 3), внешних клиентов нет — эксплуатационный риск непропатченного сервера низкий, но принимать его «по умолчанию» на целевую архитектуру нельзя.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Оставить замороженный образ `minio/minio:RELEASE.2025-09-07` | ничего не делать | известная непропатченная CVE-2025-62506; нарушает NFR-071 по духу (пин на мёртвый образ) |
| **B. Собирать MinIO из исходников последнего тега `RELEASE.2025-10-15T17-29-55Z` (`build/minio.Dockerfile`, multi-stage `golang:1.26` → distroless), пин по git-тегу; `objstore` — минимальный интерфейс, versioning необязателен** | тот же SDK (`minio-go/v7`), та же семантика, CVE-фикс включён; ≈ 5 мин сборки (кэшируется); нулевые изменения в дизайнах EPIC-002/003/004 | будущих фиксов не будет (репозиторий архивирован); сборка старого кода новым toolchain может сломаться (пин Go в `build/minio.Dockerfile` отдельный: `golang:1.24`-образ для сборки MinIO) |
| C. Community-форк (например `pgsty/minio`) | образы публикуются; тот же API | зависимость от стороннего форка без гарантий; лицензия/происхождение образа проверять отдельно |
| D. Заменить на SeaweedFS (`weed server -s3`, versioning в S3 API есть) | живой upstream, один бинарник, S3 versioning | другая семантика ILM/versioning — нужен spike; ещё одна новая технология в волне 0 при одном разработчике |
| E. Заменить на RustFS | активный проект, заявленная S3-совместимость | молодой (2025), пробелы в редких операциях; риск для «истины» состояния |
| F. Garage | простой, живой | **нет bucket versioning и lifecycle** — не подходит под ILM `prompts-*` и откат |

## Решение

1. **MVP-1 — вариант B**: MinIO собирается из исходников тега `RELEASE.2025-10-15T17-29-55Z` в `build/minio.Dockerfile` (F-6, devops-engineer); образ `multiverse-core/minio:<tag>` используется compose и testcontainers (через `build/versions.env`; модуль `testcontainers/minio` принимает произвольный образ). `mc` (`minio/mc`) — последний опубликованный образ, только в init-контейнере (не в рантайме платформы); при исчезновении образа `mc` — init-скрипт на `minio-go` внутри `mvctl storage init`.
2. **Минимальный интерфейс** `shared/objstore.Client`: `Put(ctx, bucket, key, body, opts) (ETag, error)`, `Get`, `Stat`, `List(prefix)`, `Delete`, `EnsureBucket(name, opts)`, `Capabilities() {Versioning, Lifecycle bool}`; реализации — `minio` (над `minio-go/v7`; SDK совместим с любым S3), `memory` (тесты). Многочастные загрузки, presigned URL, object lock, уведомления — **не используются** и в интерфейс не входят. `EnsureBucket` включает versioning/ILM, если `Capabilities()` позволяет; иначе — предупреждение в `/health.store`.
3. **Ни один путь кода не зависит от bucket versioning**: откат снапшота — из ротации `snapshots-{world}/{component}/` (K=5, C-14); история сущности — `history`/`last_change` в объекте (ADR-011); интент-объект ADR-013 — обычный объект. Versioning остаётся включённым как дополнительный страховочный слой (ILM `noncurrent-expire-days 30`).
4. **Триггеры замены сервера** (любой из): (а) CVE в MinIO с CVSS ≥ 7, затрагивающая используемые операции, без возможности собрать патч; (б) сборка последнего тега перестаёт проходить на поддерживаемом Go при обновлении `build/minio.Dockerfile` и нет разумного обходного пути; (в) появление первого внешнего сетевого клиента хранилища (E-H). При срабатывании — задача EPIC-012 (E-G): spike SeaweedFS (предпочтительно, есть versioning) → contract-тест `objstore` на testcontainers против нового сервера → смена образа в `versions.env`; код контекстов не меняется.
5. **Что не делаем**: не переходим на SeaweedFS/RustFS в волне 0 (новая технология на критическом пути EPIC-001 при одном разработчике); не берём Garage (нет versioning/lifecycle); не берём форк как основной путь без проверки происхождения (может стать вариантом при триггере, если SeaweedFS-spike провалится).

## Последствия

- Позитивные: дизайны EPIC-002/003/004 не меняются; CVE-2025-62506 закрыт; замена сервера в будущем — смена образа и прогон contract-теста; `objstore` не обрастает MinIO-специфичными вызовами.
- Негативные: ещё один Dockerfile и ≈ 5 мин первой сборки (кэш слоёв GitHub Actions — `docker/build-push-action` с `cache-from: gha`); осознанно принят риск «архивированный upstream» на срок MVP-1 (loopback-only, доверенная машина).
- Что придётся сделать: EPIC-001 F-5 — `objstore` по п. 2 с contract-тестом (`integration`), F-6 — `build/minio.Dockerfile` + `versions.env`; EPIC-012 — задача-заглушка «замена объектного хранилища» с триггерами п. 4; `.dev-team.json.stack` — по факту после EPIC-001 (tech-writer, F-9).
- Вопрос владельцу (OQ-A-20): подтвердить вариант B на MVP-1 или потребовать замену сервера уже в EPIC-001 (вариант D) — влияет на стек и объём волны 0.
