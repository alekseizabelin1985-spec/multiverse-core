# ADR-020: Координатор раундов группы в gateway — машина состояний в памяти с durable-таблицей, таймаут через `Clock`, порядок публикации `player.defended` → `round.closed`, `idle` и лидерство

Статус: предложено (к утверждению на G2 с планом EPIC-004) · Дата: 2026-09-09 · Автор: architect#3 (TEAM-3, EPIC-004) · Уровень: реализация блока
Связи: ADR-003 п. 4, 6 (`round.closed` записывается до обработки; таймеры поверх `Clock`, в replay не срабатывают — не пересматривается), ADR-007 (топики, `meta`), C-04 (издатель `round.*`, `player.defended`), C-05 (gateway открывает первый раунд по `encounter.started`), C-03 (`NPCTarget` исключает `idle`); FR-025, BR-13, BR-04, BR-06; NFR-005, NFR-012, NFR-013, NFR-061; `domain-review.md` §3.2; UC-016, UC-017, UC-009; `data-model.md` §5.4, §9.3; `components/gateway-and-bot.md` §7.3, §9.

## Контекст

Аналитик определил модель раунда (DR-03/FR-025): в `group` раунд закрывается, когда все `active` участники действовали или истёк таймаут 60 с (в CI — явное закрытие); молчавший получает `defend`, после двух подряд — `idle`; NPC действует один раз после `round.closed`; порядок — по времени приёма. Системный архитектор закрепил: координатор — gateway (не рой), `round.closed` публикуется до обработки раунда и содержит всё нужное механике (`acted[]`, `auto_defended[]`, `idle[]`), в `solo` раунды не публикуются, таймаут — через `Clock` (в replay читается из журнала), первый раунд открывается по `encounter.started`. Открытые места для команды: где хранить состояние, как обеспечить атомарность закрытия при гонке «действие vs таймер», как ведётся `idle`, что при смерти/выходе участника и лидера, что при рестарте, как `say` относится к раунду.

## Рассмотренные варианты

| Гонка «действие vs таймер» | **один мьютекс на scope; закрытие — `state=closing` под мьютексом, публикация вне мьютекса, `state=closed` после успеха; действие, пришедшее в `closing/closed`, относится к следующему раунду** | детерминированный результат; нет двойного `round.closed` | действие «на грани» таймаута попадает в следующий раунд — ожидаемо (игрок опоздал) |

| Причина бросков NPC | **`round.closed` — корневое событие (`meta.correlation_id = id`)** | seed ответа NPC = `hash(round.closed.id, idx)` (ADR-003 п. 5) | ходы игроков раунда и ответ NPC имеют разные `correlation_id`; связь — `round{seq}` + scope (turns это учитывает) |
| Открытие раундов | **раунд 1 — по `encounter.started` (C-05); раунд N+1 — первым `attack/flee/defend` после `round.closed`** | C-05 соблюдён; после закрытия «мир не ждёт» только когда кто-то действует — группа, ушедшая пить чай, не получает укусы каждые 60 с бесконечно (TTL агента встречи закрывает `abandoned`) | асимметрия правил открытия (описана явно; запрос BA — §14 п. 6 компонентного документа) |

| `idle` | **счётчик `missed_rounds` в `gateway.db` (`group_participation`); при ≥ 2 → `entity.update.proposed group.members[p].participation=idle` (`cause=group`, `expected_version`); первое действие → `active`** | gateway — владелец `Group.members[].participation` по `data-model.md` §4; механика видит `idle` в проекции группы (`NPCTarget`); `round.closed.idle[]` — дубль для агента | предложение может быть отклонено State по версии → повтор с актуальной версией (≤ 3) |

## Решение

1. **Пакет** `internal/gateway/rounds`: `Coordinator` (§6 компонентного документа), `roundState{seq, encounterID, expected, acted[], autoDefended[], idle[], deadline, timer, state}`; таймер — `Clock.AfterFunc(deadline − now, closeByTimeout)`; `deadline = openedAt + GATEWAY_ROUND_TIMEOUT` (60 с; после появления `encounter.started.round.timeout` — из события, §14 п. 4).
2. **Открытие**: (а) `encounter.started` для scope `group` → `seq=1` (при рестарте между `encounter.started` и `round.opened` — `Restore` доводит); (б) после `closed` — первый `Accept` с `actionType ∈ {attack, flee, defend, group.leave}` → `seq+1`. `round.opened {scope, encounter, round{seq}, expected[], deadline_at}` публикуется **до** ответа `202` на открывающее действие (в одной последовательности с `player.*`); всем участникам — доставка `kind=group`.
3. **Приём**: `Accept(scope, player, type, eventID, at)` под мьютексом: `state≠open` → открыть новый (п. 2b); участник ∉ `expected` (idle/out_of_combat/dead) → действие принимается как обычный ход, в `acted[]` не входит (для `idle` — возврат в `active` до приёма, п. 6); участник ∈ `acted` → `ErrAlreadyActed` (`409 already_acted`); иначе `acted += {player, eventID, at}`; `expected ⊆ acted` → `Close(all_acted)`.
4. **Закрытие** `Close(reason)`: под мьютексом `state=closing`, `timer.Stop()`, снимок списков; вне мьютекса — для каждого `p ∈ expected − acted`: `player.defended {entity{p}, scope, encounter, round{seq}, cause: round_timeout}` (корневое, `actor_kind` сессии scope) и `missed_rounds[p]++`; затем `round.closed {round{seq, close_reason}, acted[] (по `at`), auto_defended[], idle[], closed_at: Clock.Now()}` (корневое); запись в `rounds` (`closed_event_id`), `state=closed`; для `p` с `missed_rounds ≥ 2` — предложение `participation=idle` (п. 6). Ошибка публикации → `state` остаётся `closing`, повтор через 1 с (идемпотентно: `round.closed` для `(scope, seq)` публикуется один раз — проверка `closed_event_id`).
5. **Явное закрытие** `POST /v1/scopes/{scope}/rounds/close` (только `ci`): `Close(explicit)`; нет открытого раунда → `409 no_open_round`.
6. **`idle`/`active`**: `missed_rounds` в `group_participation`; ≥ `GATEWAY_ROUND_IDLE_AFTER_MISSED` → `entity.update.proposed` группы (`members[p].participation=idle, missed_rounds`) с `expected_version`; первое действие `idle`-участника: сначала предложение `active` (ожидание факта ≤ 2 с, при таймауте действие всё равно принимается, `expected` пересчитается по факту), `missed_rounds=0`. `idle` не ждётся, не цель (C-03), получает нарратив раунда (C-05 `recipients` — забота нарратора).
7. **Изменение состава**: `entity.updated` группы/встречи/игрока (`status=dead`, `out_of_combat`, `members`) → `OnParticipantsChanged` → пересчёт `expected` открытого раунда; `expected ⊆ acted` → `Close(all_acted)`; `expected = ∅` → `Close(all_acted)` с пустыми списками (агент завершит встречу `players_out`). `encounter.ended` → `OnEncounterEnded`: открытый раунд закрывается `explicit`? — **нет**: сбрасывается без `round.closed` (встречи больше нет, NPC отвечать не будет); строка `rounds` получает `state=closed, close_reason=NULL` — отмечается в аудите как «раунд прерван встречей».
8. **Лидерство при смерти** (предложение, до решения BA): при `entity.updated player.status=dead` лидера → `groups.TransferLeadership`: старейший `alive` по `joined_at`; `entity.update.proposed group.leader_id` + `group.leader_changed {cause: death}`; живых нет → лидер не меняется, группа доживает до `disbanded`/`session.ended death`.
9. **Replay**: `Deps.Mode=replay` → таймеры не создаются, `Close` по таймеру не вызывается, `Accept` только учитывает; `round.opened/closed` из журнала применяются к `rounds` (`state`, `closed_event_id`), после переключения в `live` открытые раунды получают таймеры от `deadline_at`.
10. **Restore** при старте (`live`): `open` → таймер на `deadline_at` (прошёл → `Close(timeout)` немедленно); `closing` без `closed_event_id` → повторить п. 4 (публикации идемпотентны по `(scope, seq)`).

## Последствия

- Позитивные: агент встречи получает один самодостаточный `round.closed`; детерминированный e2e `group-3x30` с `rounds/close`; смерть/бегство участников не заставляют группу ждать таймаута; `idle` виден и механике (проекция группы), и нарратору (`round.closed.idle[]`).
- Негативные: параметры раунда временно дублируются в env gateway и блупринте (снимается запросом §14 п. 4); две причины открытия раунда (`encounter.started` / первое действие) — требуют явного теста; предложение `idle` может отклоняться по версии в гонке с механикой — повтор ≤ 3 с актуальной версией.
- Что придётся сделать: EPIC-004 I2 — пакет `rounds`, `group_participation`, тесты с `FakeClock` (all_acted, timeout, explicit, idle, смерть участника, restore, replay); BA — закрепить `say` вне раунда (FR-025) и лидерство при смерти (BR-13); EPIC-003 — учитывать `round.closed.idle[]` и `auto_defended[]` без ожидания `player.defended` из PE.
