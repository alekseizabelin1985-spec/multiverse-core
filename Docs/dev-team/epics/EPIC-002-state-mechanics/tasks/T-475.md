## Описание и DoD
См. раздел «### T-475» в `../tasks.md`. Кратко: `world init --bus kafka` предлагает сущности фикстур State процесса `core` через Redpanda. Что уже создано, решают объекты `entities-{world}`, а не журнал: retention `system_events` — 30 дней. Снапшот seq 0 `bootstrap` команда просит у admin-маршрута T-059, `--force` на этом пути — `exit 2`. Заодно закрывается хвост ревью #2 T-058:
- N-3 — тест ветки «`snapshot.created` не вышел»;
- N-4 — `errors.Join` для ошибки `Stop`;
- `--force` над повреждённым указателем;
- подсказка `world status` для `minio`;
- `details` отказа в тексте для оператора.

**Оценка размера — M.** Новый путь CLI: шина Kafka, HTTP-клиент admin-маршрута, чтение объектов. Опция `Bootstrap` для правила объектов. Тесты на внедрённой шине и на State теста с маршрутом на `httptest`. Пять небольших правок пути memory с тестами и мутантами. Риск роста — способ запросить `reason=bootstrap` у маршрута (решение system-architect до кода). Запасной план — части А и Б в индексе.

### Итог в одной фразе
`mvctl world init --bus kafka` создаёт мир в MinIO через State процесса `core`: предлагает по Redpanda только сущности без объекта в `entities-{world}`, ждёт ответы в `system_events`, снапшот seq 0 `reason=bootstrap` просит у admin-маршрута. Заодно закрыт хвост ревью #2 T-058: N-3, N-4, `--force` над повреждённым указателем, подсказка `world status`, `details` отказа.

### Главный вопрос: как admin-маршрут пишет `reason=bootstrap`
В КД §4.9, §4.10 и §19 после T-059 способ не записан. Сделан минимальный вариант, он ждёт подтверждения system-architect (см. «Открытые вопросы»):
- у `POST /v1/admin/state/{world}/snapshot` необязательное тело `state.SnapshotRequest{"reason": "admin"|"bootstrap"}`;
- без тела, `{}` или без `reason` — `admin`, как было в T-059;
- другой `reason` (в том числе `interval`, `shutdown`, `session_ended`) — `400 invalid_reason`;
- не JSON, лишнее поле (опечатка `reson`), два документа — `400 invalid_body`;
- при `400` ничего не пишется. Тело ограничено 4 КБ.

### Что сделано
- **`internal/state/admin.go`** — разбор тела (`snapshotReason`), тип `SnapshotRequest`, коды `400` в комментарии маршрута.
- **`internal/state/bootstrap.go`**:
  - опция `WithObjects(Store)` — правило объектов КД §4.10 (б). Объект сущности есть — сущность не предлагается и попадает в `Skipped`; объекта нет (`ErrNotFound`, бакета нет) — предлагается. Журнал при этой опции для решения «уже создано» не читается. Иная ошибка чтения — `ErrBootstrap` до первой публикации. Общий код ожидания ответов не менялся;
  - тип `Refusal{Entity, Reason, Details, EventID}` — отказ State, которым кончился bootstrap. Возвращается обёрнутым вместе с `ErrBootstrap` (`errors.As`). Текст: `npc/wolf-alpha refused law_violation (invariant_id inv-10) (event …)`, детали — по ключам в алфавитном порядке.
- **`internal/state/store.go`** — `ReadLatest` помечает неразборчивый `latest.json` через `ErrUndecodable` (раньше — только для объекта снапшота). Восстановление T-059 это не меняет: там ветка `err != nil` общая.
- **`cmd/mvctl/internal/world/world.go`**:
  - `Command` получил `OpenBus` (точка внедрения шины, как `OpenStore`) и `CoreURL`;
  - `Run` заполняет их из манифеста: `OpenBus` — Kafka по `MV_KAFKA_BROKERS` и `MV_BUS_VALIDATE_ON_READ`, `CoreURL` — `MV_CORE_URL`;
  - у `Command` теста без них путь kafka ничего не открывает: так тест не дойдёт до брокеров и `core` окружения;
  - новые проверки `core` и `bus`.
- **`cmd/mvctl/internal/world/kafka.go`** (новый) — путь `--bus kafka` по порядку:
  1. `--force` → `exit 2` до любых действий. Текст называет процедуру КД §4.10 (в): остановить `core`, удалить бакеты `entities-{world}` и `snapshots-{world}`, поднять `core` (мир `uninitialized`), `world init --bus kafka`.
  2. `--store memory` → `exit 2`; по умолчанию `minio`. Пустой `CoreURL` → `exit 2`.
  3. `--rules` не читается, это сказано в справке.
  4. Фикстуры → `EnsureWorldBuckets` → `ReadLatest`. Указатель есть → `exit 2` с процедурой. Неразборчивый → находка `store` с процедурой. Ошибка транспорта → `store`.
  5. `GET /health` `core`. Недоступен или ответ не health → находка `core` с адресом и именем `MV_CORE_URL`. State не запущен, мира нет в `worlds`, мир `fail` → находка `core`. Всё это — до открытия шины и публикаций.
  6. Шина → `Bootstrap(..., WithObjects(NewObjectStore(client)))`. Отказ → находка `bootstrap`, `details.refusal` в `--json`.
  7. `POST` admin-маршрута: `X-Client-Id: mvctl`, `X-Actor-Kind: ci`, тело `{"reason":"bootstrap"}`. Ответ ≠ 200 → находка `snapshot` вида `core at <url>: POST … answered 503 world_stopped: <message>`, `exit 1`.
  8. После 200: `GET /health`. `snapshot_event_failed: true` у мира → предупреждение, `exit 0`. `reason` в указателе не `bootstrap` (маршрут без T-475) → предупреждение. `/health` не прочитан → предупреждение «не известно, вышел ли `snapshot.created`».
- **`cmd/mvctl/internal/world/core.go`** (новый) — HTTP-клиент `core`:
  - разбор ошибки терпимый: `{"error":{"code","message"}}` маршрутов, `{"error":"…"}` у `runtime.AdminOnly` (`403` с подсказкой про `MV_CORE_ADMIN_CLIENTS`), любое другое тело цитируется (до 200 символов);
  - `worldOfHealth` читает `details.contexts.state.details.worlds.<world>`.
- **`cmd/mvctl/internal/world/init.go`**:
  - `runInit` разбирает флаги и ветвится на `initInMemory` и `initOverKafka`; печать итога вынесена в `writeInitialized`, общую для обоих путей;
  - **N-3** — чистая функция `snapshotOutcome(pointer, err) (snapshot, warning, failure)`. Указатель есть → `exit 0`, ошибка рядом с ним — предупреждение. Указателя нет → `errSnapshot`. Указатель и ошибка оба `nil` → тоже `errSnapshot` (раньше разыменование `nil`);
  - **N-4** — `run.err = errors.Join(run.err, stopped)`, выбор `CheckSnapshot`/`CheckBootstrap` не изменился;
  - **повреждённый указатель**: при `--force` `ErrUndecodable` не останавливает очистку, мир создаётся заново (seq 0). Без `--force` — находка `store` с именем `latest.json` и `--force`. Ошибка транспорта — `store` в обоих случаях;
  - `details.refusal` в отчёте на отказе;
  - справка `--bus`, `--store`, `--rules`, `--force`.
- **`status.go`** — подсказка для неинициализированного мира в `minio`: `run mvctl world init --bus kafka while core is running`.
- Вывод DoD-команды пути memory не изменился: те же строки, `cursor.system_events: 11`, `state_hash: sha256:0046b8a7…`.

### Отклонения от дизайна
1. **`reason` в теле admin-маршрута** решён исполнителем, а не system-architect до кода: КД этого не называл, а DoD предлагал тот же вариант. Правка КД §4.9–§4.10 — за system-architect.
2. **Комментарий `Bootstrap` в КД §4.10** «opts меняют только ожидание» устарел: `WithObjects` меняет источник решения «уже создано». Текст правит system-architect.
3. **Проверка `/health` `core` до bootstrap** и находка `core` — сверх DoD. Без неё неработающий `core` стоил бы 10 с таймаута и оставлял бы предложения в журнале, которые State после рестарта не прочтёт (он читает с `End`).
4. **`ReadLatest` помечает `ErrUndecodable`** — правка `store.go`, в перечне «Файлы» её не было. Без неё повреждённый указатель не отличить от ошибки транспорта.
5. **Новые файлы** `core.go`, `kafka.go` и тесты `kafka_test.go`, `init_memory_test.go`, `kafka_integration_test.go`, `internal/state/admin_test.go` — внутри пакетов из «Файлов». `.golangci.yml` не менялся: новых импортов `internal/*` нет.

### Открытые вопросы (к system-architect через оркестратора)
1. **Способ `reason=bootstrap`** — подтвердить тело `{"reason": "admin"|"bootstrap"}` и коды `400 invalid_reason`/`invalid_body` и внести в КД §4.9–§4.10. Уточнить, нужно ли ограничивать `bootstrap` миром без `latest.json`. Сейчас ограничения нет, `world init` проверяет указатель сам; `bootstrap` поверх инициализированного мира дал бы seq > 0 с этой причиной.
2. **Комментарий `Bootstrap`** в КД §4.10 — дополнить опцией `WithObjects`.
3. **`MV_CORE_URL`** описан в манифесте как «адрес, куда gateway проксирует `/v1/admin/*`», а теперь его читает и `mvctl`. Описание в `shared/env/vars.go` (EPIC-001) стоит расширить; код от этого не зависит.

### Предложения в бэклог
1. EPIC-001: описание `MV_CORE_URL` в `shared/env/vars.go` и `.env.example` — «адрес `core` для gateway и `mvctl`».
2. T-063: на стенде проверить, что `MV_CORE_ADMIN_CLIENTS` `core` содержит `mvctl` (умолчание — да). Иначе `world init --bus kafka` получит `403` с подсказкой.
3. Имя атрибута в отказе создания («Бэклог по приёмке T-058», строка 4) не закрыто: печатается всё, что есть в `details` события, а `details.attribute` в схеме нет.

### Риски и допущения
1. **`MV_BUS` по умолчанию `kafka`**, поэтому голый `mvctl world init` теперь идёт в стек окружения (`MV_KAFKA_BROKERS`, `MV_CORE_URL`, MinIO), а не отказывает `exit 2`, как до T-475. Так задумано для T-063, но оператор должен это знать.
2. Проверка `/health` терпима: health без контекста `state` не считается отказом, решают ответы на предложения.
3. Предупреждение «не известно, вышел ли `snapshot.created`» появится, если `/health` недоступен сразу после 200 маршрута. Код выхода остаётся `0`.

### 1. Тело admin-маршрута снапшота — подтверждено
Как в коде: необязательное тело `{"reason": "admin"|"bootstrap"}` (`state.SnapshotRequest`, не больше 4 КБ).
- Без тела, `{}` или без `reason` — `admin`, как в T-059.
- Другой `reason`, в том числе `interval`, `session_ended`, `shutdown`, — `400 invalid_reason`.
- Не JSON, неизвестное поле, второй документ — `400 invalid_body`.
- При `400` ничего не пишется.

*Почему неизвестное поле — отказ:* опечатка `reson` записала бы `admin` там, где просили `bootstrap`. Внесено в КД §4.9, абзац «Тело и ответы admin-маршрута снапшота», вместе с полным перечнем ответов маршрута.

### 2. `reason=bootstrap` над инициализированным миром — риск есть, пункт итерации 2
**Что происходит сейчас.**
- `Applier.writeSnapshot` берёт `seq` у `nextSeq` — следующий за наибольшим объектом снапшота. Над живым миром это `seq > 0`, а не 0.
- Указатель переписывается текущим состоянием, как любым снапшотом. Данные верны: это тот же снапшот, что `admin`, с теми же сущностями, окном и курсором. Потери данных нет.
- Неверна метка. `bootstrap` значит «снапшот, которым мир начался»: так его читают оператор и `mvctl world status`.

**Реальный путь к ложной метке** — не опечатка, а два `world init --bus kafka` одновременно. Оба видят мир без указателя. Если второй читает объекты после того, как первый создал сущности, он пропускает всё и доходит до `POST` (если читает раньше — его предложения State гасит как повтор, и второй кончается таймаутом `ErrBootstrap`). Второй `POST` пишет `seq 1, reason=bootstrap`. `afterTheSnapshot` сверяет только `reason`, поэтому команда завершается `0`, как будто мир создала она. Проверка указателя в команде гонку не закрывает. Её закрывает проверка на worker'е мира: она последовательна с записью снапшотов этого мира.

**Решение (КД §4.9):** `reason=bootstrap` принимается только у мира без `latest.json`. Правило живёт в State, а не в маршруте, и действует для любого вызывающего `Context.Snapshot`.
- Указатель есть или не читается (`ErrUndecodable`) — `409 world_initialized`. Ничего не пишется, счёт `MV_SNAPSHOT_EVERY_FACTS` и признаки снапшота в `/health` не меняются.
- Иная ошибка чтения указателя — `500 snapshot_failed`.
- *Почему условие — указатель, а не `seq == 0`:* объект снапшота без указателя (процесс упал между двумя PUT, §4.4) навсегда запер бы `world init` отказом `409`. Условие совпадает с предусловием команды и с признаком `uninitialized` (§18). Цена — в этом редком случае снапшот `bootstrap` получает `seq > 0`.

### 3. Комментарий `Bootstrap` — поправлен (КД §4.10)
Текст «opts меняют только ожидание» заменён.
- `opts` задают ожидание (`WithAnswerTimers`) и источник решения «уже создано» (`WithObjects`). Содержание и порядок предложений `opts` не меняют.
- С `WithObjects` журнал для решения не читается. Объект есть — `Skipped`. `ErrNotFound` или нет бакета — предлагается. Иная ошибка — `ErrBootstrap` до первой публикации.
- Иной отказ State — `ErrBootstrap` вместе с `*Refusal` (`errors.As`).
- В сигнатуры добавлены `WithAnswerTimers` и `WithObjects`.

### 4. Голый `mvctl world init` идёт в стек — соответствует КД, ужесточения нет
`--bus` берёт `MV_BUS`, как процесс; T-058 брал то же умолчание (`env.Bus.String()`), только отказывал на `kafka`. Явный `--bus kafka` защиты не добавляет: оператор копирует команду из runbook вместе с флагом. От случайного вызова защищают предусловия:
- над миром с указателем — `2`;
- `--force` на этом пути — `2`;
- `reason=bootstrap` у мира с указателем — `409` (п. 2).

Над здоровым миром голый вызов кончается `exit 2` «мир инициализирован» и ничего не пишет. Остаточный случай — мир без указателя, но с объектами живого мира (указатель утрачен). Это повреждённое развёртывание, а не случайный вызов; предложение — «Предложения в бэклог» п. 3. Записано в КД §4.10 (з).
