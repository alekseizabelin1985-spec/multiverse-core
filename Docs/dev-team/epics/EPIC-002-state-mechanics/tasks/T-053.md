### Решения по ходу
1. **`Actor.Kind`** — развилка ADR-024 и §17 («поле против аргумента `ChangesFor`»). Выбрано поле: сигнатура C-03 не меняется, `Resolve` тоже нужен вид для `Outcome.Loot`. Заполняют его `ActorFromEntity` (только NPC, атрибут необязательный: нет вида — нет трофея) и `Rules.Stats` (только NPC). У персонажа поле пустое, поэтому `test/fixtures` сравнивает актёров целиком без правок. Метка `contract-change`: C-03 v1.3 оформляет system-architect.
2. **Бэклог T-050, `dmg`.** Закреплено «только кубы». Грамматика не знает плоского урона, а расширять её — отдельная задача (ADR-012 п. 2). `ActorFromEntity` называет число числом («not a dice expression»), а не «нет атрибута», и сразу разбирает выражение. Модель данных (`int / формула`) стоит поправить аналитику.
3. **`rest`.** `Resolve(rest)`: `Hit = true`, `HPAfter = HPMax`, бросков нет, `combat.decided` не порождается (C-03 «Отдых»; схема не знает `rest`). Отдых кубами (`rest.restore: d4`) отвергается ошибкой: у `dice.rolled` нет назначения для такого броска, а бросок без публикации — непроверяемый. `ChangesFor(rest)` — `set hp` с `cause=rest`; при полном здоровье — ничего.
4. **Проверки `Resolve`.** Мёртвый, покинутый или вознёсшийся не действует. Стороны закреплены: `attack` — персонаж по NPC, укус — NPC по персонажу; иначе назначения бросков в `dice.rolled` были бы ложными. Исключённая цель → `ErrInvalidTarget`. У бегства нет крита и фамбла: правила их не называют. `LivingEnemies < 0` — ошибка, 0 допустим.
5. **Назначения бросков** заданы в коде (`hit`/`damage`, `npc_hit`/`npc_damage`, `flee`), как в §5.4 и у обоих двойников. `attack.rolls`/`flee.rolls` правил остаются описательными (предложение 1).
6. **HP в `ChangesFor` считается от цели**, а не копируется из `Outcome.HPAfter`. Так делает `pack` двойника при повторе после конфликта версий. Если повтор меняет, кто пал, — ошибка (C-05 v1.4 п. 1в).
7. **`FixedMechanics`** заполняет `Loot` по `Actor.Kind`: прежний комментарий «вида нет» стал неверным. Пакетный комментарий поправлен.
