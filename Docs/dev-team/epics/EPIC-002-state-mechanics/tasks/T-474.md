## Описание и DoD
См. раздел «### T-474» в `../tasks.md`. Кратко: по КД §4.8 восстановление пропускает `*.proposed` в `[cursor, End)`, и действие игрока во время рестарта `core` остаётся без ответа (`timeout` у шлюза). После догона до `End` State решает предложения диапазона без факта и без отказа так же, как пришедшие поздно: дедуп по `proposal_id`, id отказа выводится из причины, живой интент — правило T-057 и §18. Тест: предложение во время рестарта → ровно один факт или отказ; второй рестарт дубля не даёт.

**Оценка размера — M.** Нужны: поиск неотвеченных предложений по диапазону журнала (факты и отказы по `proposal_id`), порядок «догон → roll-forward → решение предложений → `Tail`», тест двух рестартов на стороже `oneStateOverTheWorld`, replay без двойного решения, мутанты и правка КД через system-architect. Если T-059 оставит чтение через группу `core.state`, объём падает до S (тест и правка КД) — см. строку DoD.
