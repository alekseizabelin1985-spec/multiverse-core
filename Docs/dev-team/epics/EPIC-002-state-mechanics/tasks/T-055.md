### Решения по ходу
1. **`WithCauseID` для фактов State — «да», `parts` — id сущности** (и для отказов: id сущности или пусто). Ответ публикуется целиком до изменения мира. Если публикация упала посреди пакета, шина повторяет то же событие, и уже ушедшие факты выходят с теми же id. `proposal_id` в `parts` не входит: у нового события под тем же `proposal_id` другой `causation_id`, и id всё равно разные. Такой повтор гасит окно `proposal_id`.
2. **Паника → ошибка шине, а не повторная паника.** Подробно — `dev-log.md`.
3. **Чтение подпиской с группой `core.state`, а не курсором ADR-011 п. 4.** Курсор снапшота и догон журнала приходят с T-057/T-059. До них мир живёт только в памяти, и группа, продолжающая с коммита, — единственное чтение, которое после рестарта не применит старые предложения второй раз.
4. **Порядок фиксации: весь ответ опубликован → копии в `memstore` → `proposal_id` в окне** (§4.5 п. 12). Упавшая публикация ничего не оставляет, повтор решается заново.
5. **Правило C-02 v1.3 «одна сущность — один набор» включено в T-055.** В индексе оно названо в T-056, но без него пакет из двух наборов по одной сущности публикует два факта под одной версией. Это нарушает «версии строго +1» самой T-055. Остальная матрица (`dead_entity`, владение, инварианты, матрица статусов, связка «путь ↔ причина», `last_change`) не делалась.
6. **Предложение без мира в конверте или чужого мира — пропуск** (`Debug`): у нескольких worker'ов нет единственного адресата. Двойник применяет предложение без мира к своему миру. При замене двойника (T-056) это расхождение надо решить.
7. **`MV_STATE_WORLDS` объявлена** (design.md §4.3 называет её, в манифесте её не было).
8. **Бои I1-α в `cmd/multiverse`:** стенд теста держит `FakeState` на мире фикстур. Контекст `state` процесса там переведён на другой мир (одна строка): два State на одном мире публикуют каждый факт дважды. Мутант M22 (без строки) краснеет. Перевод стенда на настоящий State — T-056.
9. **`memoryOptions().idSource` = `uuid`.** Процесс теперь ставит генератор `Deps` поверх `testkit.Deterministic`. С `sequence` все 16 боёв начинались бы с `seq-1` и потеряли бы разнообразие, ради которого у них разные префиксы. `uuid` — то, что `parseServe` даёт по умолчанию, и то, что обещает комментарий хелпера.
