### Итог в одной фразе
State восстанавливает мир до приёма предложений: снапшот с проверкой `state_hash` (и откат к предыдущему из K), догон фактов журнала по правилу C-02 v1.6, сверка с объектами сущностей, roll-forward интентов, `analytics.replay.completed mode=recovery`. Чтение `system_events` — собственным курсором (`Journal.Tail` с `End`), а не группой. Добавлены секция мира `/health`, admin-маршрут снапшота, мир `uninitialized`, N-3 и N-4. Хранилище и восстановление подключены в `cmd/multiverse` одним изменением.

### Способ чтения `system_events` — курсор, T-474 получает полный объём
КД требует курсор, выбора нет:
- ADR-011 п. 4: «State не использует consumer group для `system_events`: читает `Journal.Tail` со своего курсора»;
- КД §4.8: «State ведёт свой курсор, а не consumer group — ADR-011»; C-01 v1.1: «`Journal` … State — свой курсор».

Сделано так:
- **С хранилищем** (`Config.Objects`): каждый `Start` — рестарт. Берётся `End` журнала, каждый мир восстанавливается, `Tail` идёт с `End`. Предложения `[cursor, End)` не решаются (КД §4.8, «Что пропускается»), значит **T-474 получает полный объём (M)**: предложения без ответа из этого диапазона остаются за ней.
- **Без хранилища** (память, тесты, стенд I1-α, e2e `--bus=memory` без MinIO): восстанавливать нечего. Первый `Start` читает с офсета 0, как новая группа (C-01 v1.2). Следующий `Start` того же объекта продолжает с события после последнего обработанного. Семантика прежней группы сохранена: предложение, прерванное `Stop`, приходит снова.

`const Group = "core.state"` удалена: читателей вне пакета нет.

### Решения по ходу (временные, до system-architect)
1. **`log_gap` и факты.** Мир берётся из объектов. Сущность на версии снапшота под тем же предложением сохраняет запись коммита снапшота вместе с id факта. У сущности впереди снапшота `fact_event_id` пуст: повтор её предложения опубликует факт под первым id, даже если он уже выходил; потребители гасят дубль по id. Recovery ничего не публикует (§18).
2. **`analytics.consistency.violated`** (`state_divergence`, `log_gap`) State не публикует: в реестре у типа один издатель `mvctl` (`registry_ops.go`), а `shared/contracts` — не моя зона. Сейчас это лог `Error handled=false` для дивергенции и `Warn code=log_gap` для разрыва, плюс `/health`. В схеме `analytics.replay.completed` поля `log_gap` нет — оно не публикуется.
3. **N-4.** Выбран признак `snapshot_event_failed` в секции мира до следующего вышедшего `snapshot.created`. Повтор при следующем триггере отвергнут: КД §9 v0.4 повтор запрещает.
4. **Точность «ровно один» на границе `announcerOf`.** Два разных факта одной версии распознаются по истории сущности (≤ 50 записей). Для более старой версии дубль с другим id неотличим от уже учтённого и пропускается.

### Отклонения от дизайна и DoD
1. **(e) «процесс не поднимается с пустым состоянием».** `Start` не падает: мир остаётся без сущностей и остановлен (`/health fail`), предложения получают `ErrWorldStopped`, остальные миры процесса работают. Падает `Start` только когда хранилище или журнал не читаются. КД §9: «мир не обслуживается».
2. **«admin-маршрут отклоняет запрос без `X-Actor-Kind`».** Доступ решает `runtime.AdminOnly` (ADR-009 п. 9, C-06): отказ без `X-Client-Id` из списка и при значении `X-Actor-Kind` вне перечня. Сам заголовок необязателен. Контракт `shared/runtime` не менял; тест закрепляет его поведение.
3. **Snapshot без мира.** Снапшот неинициализированного мира отвечает 500 `snapshot_failed` (нет `laws_version`), как в T-057.
4. `/health`: ключи `world`, `snapshot` в секции мира перегружены значениями §9/§18 (`world: uninitialized`, `snapshot: corrupted`). Ключ мира — сам `worlds.<id>`, дублировать его полем `world` не стал.

### 2. Отступления от DoD (приняты system-architect#1, отражены в индексе)
1. **Битый снапшот останавливает мир, а не процесс** (КД §9, §19 п. 5). `Start` не падает: мир без сущностей стоит с `fail {reason: snapshot_corrupted, snapshot: corrupted}`, остальные миры процесса работают. `Start` падает, только если не читаются хранилище или журнал.
2. **Доступ к admin-маршруту решает `X-Client-Id`** (`runtime.AdminOnly`; ADR-009 п. 9, C-06, КД §4.9, §19 п. 9). Запрос разрешённого клиента без `X-Actor-Kind` получает 200. Устаревший абзац `foundation.md` §3 — в бэклоге system-architect.
3. **`analytics.consistency.violated` не публикуется** (КД §4.8, §9, §19 п. 7). У типа нет издателя `core/state` в реестре, поэтому след остаётся в `/health` и в логе. Публикация — после `contract-change` EPIC-005.
4. Также приняты: 500 `snapshot_failed` у неинициализированного мира; поля `log_gap` в `analytics.replay.completed` нет (схема закрыта); секция `/health` — `details.worlds.<id>`, ключи `world` и `snapshot` несут значения §9 и §18.

В индексе строки DoD (e), (f) и строка admin-маршрута зачёркнуты с пометкой «заменено (приёмка T-059)», описание дополнено пометками.

### 3. Способ чтения и T-474
Способ чтения — собственный курсор (ADR-011 п. 4, КД §4.8, C-01). С хранилищем каждый `Start` — рестарт: `End` берётся один раз до восстановления миров, `Tail` идёт с `End`, `const Group` удалена. ### Вопросы исполнителя
1. **`log_gap`: подтверждено с уточнением (КД §4.8, §19 п. 1).** Мир берётся из объектов, recovery ничего не публикует. Факты `entity.created`/`updated`, которые `ReadRange(cursor, End)` доставило при разрыве (остаток журнала после retention), не применяются, а только отмечают объекты. Если у объекта совпадают `id`, `version` и `last_change.proposal_id` с фактом, в память ставится `fact_event_id` = id этого факта. У объекта без найденного факта `fact_event_id` остаётся пустым, и повтор его предложения публикует факт под id первого вывода, возможно второй раз. Потребители гасят такой факт по id. Остаточный случай принят: факт мог уйти только в утраченную часть журнала, а предложения старше retention издатели не повторяют. *Почему не «как есть»:* эти факты уже прочитаны в `readFacts` и при разрыве выбрасываются. Без отметки дубль получает любая сущность, изменённая после снапшота, даже если её факт лежит в журнале. **Итерация 2, п. 1.**
2. **Конверт досылки (Mi-3 T-057): оставить как в коде (КД §4.5 п. 2, §19 п. 2).** От первого вывода (запись коммита) берутся id, `timestamp`, `causation_id` и payload с `applied_at` и `cause`. От события-повтора — `correlation_id`, `actor_kind`, `locale`, `scope`. Конверт в `last_change` не хранится, `contract-change` `shared/entity` не нужен.
   - *Почему:* досланный факт ждёт тот, кто повторил предложение, то есть новая цепочка. Корреляция первой цепочки её ожидающему уже не нужна: у шлюза ход закрылся `timeout`. Потребители узнают факт по id.
   - Правило «досылать только при `p.Event.ID == proposal_event_id`» отвергнуто: при повторе издателя новым событием факт остался бы невысланным навсегда.
   - Бэклог EPIC-005 (`mvctl trace`): у досланного факта `causation_id` указывает в другую цепочку, это законная форма, а не обрыв трассы.
3. **`batch_size` (Mi-2 T-057): «применённые» наборы (КД §4.5 п. 10, §19 п. 3).** Значение решается на шаге 9, до записи. Записанные сущности частично записанного неатомарного пакета несут полный `batch_size`. По разнице между `batch_size` и числом сущностей, чья запись коммита называет этот `proposal_id`, аудит видит частичную запись. Число записанных потребовало бы второго PUT уже записанных сущностей, а п. 12 его запрещает. Roll-forward пишет число наборов интента — для атомарного пакета это то же число.
4. **N-4: `snapshot_event_failed` подтверждён (КД §9, §19 п. 4).** Признак держит `degraded` до следующего вышедшего `snapshot.created`; повтора события нет. Рестарт признак снимает: указатель записан, а новый процесс о невышедшем событии не знает.
5. **Число повторов записи внесено в КД §4.5 п. 11:** четыре попытки State (паузы 100/300/900 мс). Каждая попытка — до трёх запросов клиента (паузы 100/500 мс). Итого до 12 запросов и ≈ 3,7 с пауз до `persist_failed`. `ErrNoBucket`/`ErrNotFound` не повторяются, `ListIntents` на досылке повторяется так же.
6. **Место стража — `shared/testkit/state`: оценка «подходит» (КД §19).** Это подпакет поставщика C-02 (`ownership.md`, строка `shared/testkit/**`, §3 п. 8). Тесты `cmd/multiverse`, `test/e2e` и `internal/state` его видят, production — нет (`no-testkit-in-production`). Условие — `guard.go` не импортирует `internal/*`, сейчас это так (`shared/contracts`, `shared/eventbus`). Подтверждение — за tech-lead#1.

### Отступления от DoD
- **Битый снапшот: `Start` не падает — принято (КД §9, §19 п. 5).** Суть DoD («не подниматься с пустым состоянием») соблюдена: мир без сущностей остановлен, `/health fail {reason: snapshot_corrupted, snapshot: corrupted}`, `Stop` не пишет, `latest.json` не тронут. Падение `Start` дало бы цикл рестартов (`restart: unless-stopped`) без `/health` и admin-маршрута, остановило бы остальные миры процесса и не сказало бы оператору ничего, кроме строки лога. ADR-011 п. 3 и КД §9 говорят «мир не обслуживается», а не «процесс не стартует».
- **Admin-маршрут без `X-Actor-Kind` — принято (КД §4.9, §19 п. 9).** Доступ решает `X-Client-Id` (ADR-009 п. 9, C-06, `runtime.AdminOnly`). Формулировка DoD устарела: оператор приходит через прокси шлюза с `human`, и запрет без `X-Actor-Kind: ci` закрыл бы маршрут оператору. Отступления 3 и 4 раздела «Выполнение» (500 `snapshot_failed` у неинициализированного мира; ключи `world`, `snapshot` в секции мира) тоже приняты.
- **`analytics.consistency.violated` не публикуется — принято для T-059 (КД §4.8, §9, §19 п. 7).** До строки издателя `core/state` в `shared/contracts/registry_ops.go` след — `/health` и лог. Строка — `contract-change` владельца EPIC-005, затем публикация — задача EPIC-002: `layer: state`, `detected_by: snapshot_diff`, код `state_divergence` (`severity: break`) или `log_gap` (`warn`). Схема оба кода уже знает. Для I1-α не нужно: мир с дивергенцией стоит с `fail`. Нужно до замера NFR-012 (`state_divergence_count`, КД §10). Поле `log_gap` в `analytics.replay.completed` не вводится: схема закрыта.

### Риск compose: решение (б) — проба принимает `degraded`, мир `uninitialized` остаётся `degraded` (КД §19)
**Что меняется.** `multiverse health` отвечает `0` при HTTP 200 и `status ∈ {ok, degraded}`. Ответ `1` — при `fail` (HTTP 503), другом коде, недоступном адресе, неразборчивом теле или статусе вне перечня. Healthcheck в `docker-compose.yml` не меняется (`["CMD", "/multiverse", "health"]`).

*Почему (б):*
- `infrastructure.md` §7.2 уже определяет `degraded` как работающий процесс (HTTP 200, «не переводят процесс в `down`»), а §6.3 — `make up` без LLM не падает. Проба «только `ok`» противоречит обоим.
- `uninitialized` — первый видимый случай, но не единственный. С настоящим контекстом `llm` `core` без LLM не станет `healthy`. `gateway` с `projection=stale` или `links_compaction: pending` уже сегодня не пускает `telegram-bot` (`depends_on: gateway: service_healthy`).
- Контейнер `unhealthy` compose не перезапускает, поэтому строгая проба ничего не чинит, а только блокирует `--wait` и зависимых.

*Почему не (а):* сигнал «выполните `mvctl world init`» пропал бы из `make health`, а класс дефекта пробы остался бы. Прецедент шлюза («projection missing не деградирует») не переносится: шлюз мир не создаёт и сделать ничего не может, а State — владелец мира.
*Почему не (в):* ровно то, что закрыла приёмка T-057. Пустая память оказалась бы над хранилищем, `world init --bus kafka` (T-475) создал бы мир, который State не записал, а переход к хранилищу потребовал бы рестарта. К тому же это второй режим State, зависящий от содержимого бакета.
*Почему не (г) «`world init` в `make up`»:* инициализация мира — решение оператора (`--force` стирает мир), а не шаг подъёма инфраструктуры. К тому же путь `--bus kafka` появится только с T-475.

Порочный круг размыкается так: `make up` → `core` `healthy` (`degraded {world: uninitialized}`) → `mvctl world init --bus kafka` (T-475) → `ok`.
