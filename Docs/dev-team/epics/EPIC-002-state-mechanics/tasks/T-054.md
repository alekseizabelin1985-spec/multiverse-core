### Семантика проверок

Проверке доступен только мир **после** изменения (`StateView`) и `touched` — id изменённых сущностей (КД §4.5 п. 8). Мира «до» нет ни у State (`overlayView`), ни у стража (своё представление плюс ops на копии, КД роя §10.4). Поэтому каждый закон записан как свойство одного состояния мира, от затронутых сущностей наружу. Переходы — «мёртвого не меняют», `dead → alive` — State решает сам по сущности до изменения (КД §4.5 п. 5: `dead_entity` и `law_violation inv-09`). Нарушение, оставленное прежними изменениями и не касающееся затронутых сущностей, — дело аудита, а не причина отклонить чужое предложение. Id из `touched`, которых нет в мире, пропускаются: это `unknown_entity` (§4.5 п. 3).

### Решения по ходу
1. **`touched` — id сущностей, а не пути.** Так в КД §4.5 п. 8 («`touched = ids изменённых`») и в ADR-012 п. 5. В промпте задачи сказано «список изменённых путей» — принял формулировку КД (открытый вопрос 1).
2. **inv-01 проверяется со стороны затронутой встречи.** Если проверять встречи каждого затронутого бойца, State отклонит `/forget` посреди боя и смерть NPC от чужой руки. Оба пути контракты разрешают: встречу потом закрывает агент (C-04 v1.1, C-05 v1.4 п. 6).
3. **inv-09 — по записи смерти.** Переход `dead → alive` в мире «после» не виден. Видна запись, которая осталась: `died_at`/`killed_by` пишутся вместе с `status=dead` (`ChangesFor`) и входят в пути трупа (§4.5 п. 5).
4. **inv-03 без индекса.** `lootIndex` из §4.5 вычисляется из инвентарей всех персонажей мира, отдельного индекса нет — копии, которая разойдётся с инвентарями, не будет.
5. **Проекции региона не проверяются.** `attrs.go` говорит, что `players_present` «checked by inv-10», а таблица КД §5.7 про это ничего не пишет. Шлюз меняет `position` без региона (строка `gateway` в `OwnershipRules`), так что такая проверка отклоняла бы каждый ход. Сделано по КД (открытый вопрос 2).
6. **Сломанные данные у затронутой сущности — нарушение, а не пропуск.** Нечитаемые `hp`, `inventory`, `npcs`, `participants`: закон, который нельзя прочитать, никто не держит.
7. **Правка вне `invariants.go`** — только комментарии: `types.go` (`Invariant.Check`), `rules.go` (`Rules.Invariants`) и `shared/testkit/mechanics/fixed.go` (устаревшее «every Check still nil»). Код и тесты `shared/testkit/state` (T-448) не трогал, хотя в `state.go:119,166,176` и `apply_test.go:484` висят комментарии «until T-054» — предложение 1.

### Открытые вопросы (к tech-lead#1 / system-architect)
1. **Форма `touched`.** В КД и ADR-012 п. 5 это id сущностей, в формулировке задачи — «список изменённых путей». Реализовано по КД. Если State (T-056) передаёт пути, нужен отдельный контракт: по одним путям inv-01 и inv-03 не выразить без id.
2. **`players_present` и inv-10.** `shared/entity/attrs.go:353` и `data-model.md` §3.2 обещают проверку проекции инвариантом, а КД §5.7 — нет. При таблице владения, где шлюз не пишет регион, проверка отклоняла бы каждый ход. Нужна правка одного из документов: либо проекцию пересчитывает State, либо она не проверяется.
3. **Требование к агенту встречи EPIC-003 (групповой бой, I2).** Если персонаж погиб, а бой идёт, пакет, трогающий встречу, должен вывести его из участия (`out_of_combat` или `dead`) — иначе inv-01. Для соло это уже так: бой закрывается тем же пакетом (`FakeEncounter.finish`). Для группы двойника нет — нужно подтверждение в C-05.
4. **TTL возрождения (вторая половина inv-09).** В мире нечем связать новое существо с прежним: у `spawned_by` нет времени, у сущности NPC нет ссылки «кого заменяет». Проверка остаётся за GM региона (§5.7). Если State должен её держать, нужен атрибут в модели данных.
