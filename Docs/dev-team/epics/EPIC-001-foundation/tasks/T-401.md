### Что выяснилось до правок
- **`-short` сейчас ничего не отсекает.** Ни один тест дерева не вызывает `testing.Short()`: грэп `testing.Short|test.short` по `*.go` пуст. Поэтому membus-половина контракта (`TestBusContractOnMembus`, в том числе кейс `Close` и оба кейса с хвостом) уже идёт под `-race` в задании `unit`. Туда же попадают `membus`, `Harness`, `FakeNarrator` и `FakeEncounter`. Причина в индексе верна наполовину. Под детектор действительно не попадали:
  1. набор на живом брокере `TestBusContractOnRedpanda` вместе с kafka-адаптером: он за тегом `integration`, а задание `integration` шло без `-race`;
  2. e2e: `stubs_v0` (Harness + FakeNarrator + FakeState на одной шине) и остановка процесса по сигналу.
- **Повтора нет нигде.** Детектор видит только те гонки, что случились в прогоне, а `unit` проходит каждое чередование один раз.
- Были ли прогоны CI с `-race` на раннере, я проверить не мог: push и Actions мне недоступны.

### Решение
1. **`integration` получил `-race`** (`CGO_ENABLED=1` в окружении шага), отдельного задания нет. Отдельное задание заново собрало бы образ MinIO и подняло бы контейнеры ради того же набора, то есть удвоило бы расход минут (бюджет U-9 — 2 000 мин/мес). Тайм-аут теста остался 20m: красный прогон складывается из 15-секундных ожиданий, а детектор замедляет только CPU-часть. `timeout-minutes` задания поднят с 25 до 30: холодный кэш buildx (~5 мин) плюс 20m теста давали ровно 25 ещё до детектора.
2. **Новое задание `race`** (ubuntu, без Docker, `CGO_ENABLED=1`, `timeout-minutes: 20`), два шага:
   - `go test -race -count=3 -timeout 10m ./shared/eventbus/... ./shared/testkit/... ./shared/runtime/... ./shared/clock/...`;
   - `go test -race -tags e2e -count=1 -timeout 10m ./test/e2e/...` с `GOFLAGS=-race`.

   | Место из индекса / T-415 / T-426 | Где лежит | Чем покрыто |
   |---|---|---|
   | кейсы с хвостом, `Close` | `shared/testkit/contract` | `TestBusContractOnMembus` ×3 в `race`; `TestBusContractOnRedpanda` в `integration` |
   | ручка хаоса на работающей шине | `shared/eventbus/membus` (`SetChaos`), контракт (`Duplicate`) | `race` ×3 |
   | `deliverNext`, `Goexit` в обработчике (T-415) | `shared/eventbus/membus` | `race` ×3 |
   | паника обработчика паркуется (T-426) | `shared/eventbus`, контракт | `race` ×3; на брокере — `integration` |
   | `Harness.mu` | `shared/testkit/gateway` (включая стенд с `FakeEncounter`) | `race` ×3; e2e `stubs_v0` |
   | проекция рассказчика (`FakeNarrator.mu`) | `shared/testkit/swarm` | `race` ×3; e2e `stubs_v0` |
   | `failMu` (T-415) | `shared/testkit/swarm` (`FakeEncounter`) | `race` ×3 |
   | `runtime.StartAll`, реальные таймеры | `shared/runtime`, `shared/clock` | `race` ×3 |
   | процесс целиком: старт, остановка по сигналу | `test/e2e` | `race`, дочерний бинарник собран с детектором |

   - Список — пакеты, а не `-run`: шаблон, который перестал совпадать после переименования, даёт зелёный `ok … [no tests to run]`.
   - Без `-short`: здесь место конкурентным кейсам, слишком медленным для `unit`. Сегодня таких нет.
   - `-count=3`, а не больше: без детектора тот же набор с `-count=5` уже поймал флак (см. ниже). Каждый повтор — ещё одно чередование и ещё треть времени задания.
   - `GOFLAGS=-race` наследует `go build` дочернего `cmd/multiverse`, который собирает e2e. Процесс с найденной гонкой завершается с кодом 66, и `TestTheProcessStopsCleanlyOnASignal`, требующий 0, падает и печатает вывод процесса с отчётом. Гонка в процессе, убитом отменой контекста (`empty_world`), сама по себе не видна. Это ограничение, а не покрытие.
   - Задание `e2e` осталось без флага: оно — ворота «e2e ≤ 10 мин» ADR-010.
   - **Оценка времени — не замер**: 4–7 мин. Настройка ~1 мин, сборка с детектором 1–2 мин, первый шаг 1–2 мин, e2e ~1–2 мин. База без детектора на машине владельца: набор первого шага с `-count=5` идёт ~19 с, e2e — 13 с. Детектор даёт ×2–20 по CPU, у раннера приватного репозитория 2 ядра. Критический путь (`integration`) задание не удлиняет, но каждый прогон тратит на него ещё 4–7 минут бюджета.
3. **Makefile.**
   - `make test-race` — те же два вызова (`RACE_PKGS`, `RACE_COUNT ?= 3`). Без cgo — отказ с кодом 1 и объяснением: кто просил детектор, не должен принять зелёный прогон за проверенный. Сообщения только на ASCII: консоль Windows показывает UTF-8 как CP1251 (T-403).
   - `make ci` включает `test-race`, а `ci: RACE_OPTIONAL := 1` превращает отказ в `SKIPPED` с кодом 0. Значение, заданное для цели, доходит до её пререквизитов, а через `ci` — и до `deploy`. `make ci RACE_OPTIONAL=` возвращает строгий отказ.
   - `make test-integration` подставляет `$(RACE)` по тому же правилу, что `make test`, и вслух говорит, какой прогон состоялся. Тайм-аут 15m → 20m, как в CI: прежнее расхождение.
4. **Документы.** В `architecture/infrastructure.md` поправлены §2.2 (строки `test`, `test-integration`, новая `test-race`, `ci`) и §3.1 (строки `integration`, `e2e`, новая `race`, абзац про бюджет, список required checks). README и runbook задания CI не перечисляют и не менялись.

### Как проверить на раннере
1. **PR с этой веткой**: в списке проверок появилась `go / race`, зелёная.
   - В логе шага «go test -race -count=3 …» — строки `ok  multiverse-core.io/shared/testkit/contract`, `…/shared/testkit/gateway`, `…/shared/testkit/swarm`, `…/shared/eventbus/membus`. Время этих пакетов заметно больше, чем у тех же пакетов в `unit`: три повтора плюс детектор.
   - В шаге e2e — `ok  multiverse-core.io/test/e2e`.
   - Ни одной строки `WARNING: DATA RACE`.
2. **`go / integration`**: в логе шага строка команды `go test -tags integration -race …` и `ok  multiverse-core.io/shared/testkit/contract`. Если детектор не включился, шаг падает сразу с `-race requires cgo`, а не проходит молча.
3. **Контрольный мутант — единственное доказательство, что детектор ловит** (зелёный прогон его не даёт). В одноразовой ветке убрать `e.failMu.Lock()` / `defer e.failMu.Unlock()` в одном из двух мест `shared/testkit/swarm/fake_encounter.go`, открыть PR на `epic/**`. Ожидается `WARNING: DATA RACE`, стеки двух горутин в `fake_encounter.go`, строка `testing.go:…: race detected during execution of test` и `--- FAIL` в `race` и `unit`. Если не упало ни в одном — мутант не попал в конкурентный путь, берётся другой (например, `Harness.mu` в `record`). Ветку потом удалить.
4. Если `race` покраснел на `TestTheHarnessAndTheEncounterOfTheSwarmOnOneBus/fight-NN` **без** `WARNING: DATA RACE` — это флак ниже, а не гонка.

### Риски и допущения
- **Детектор проверяет и сторонний код** (kafka-go, testcontainers-go, segmentio). Гонку в зависимости подавить нечем: у Go-детектора нет suppressions. Такое падение `integration` лечится обновлением зависимости или issue вверх по течению, не флагом.
- Время заданий — оценки, не замер. Первый прогон на раннере покажет реальные цифры; их стоит вписать в §3.1.
- `-tags integration ./...` гоняет и все unit-тесты: теперь это ещё один их проход под детектором внутри `integration`. Сужать список я не стал — это смена смысла задания, а не T-401.
- Список пакетов `race` задан в двух местах (`go.yml` и `RACE_PKGS` в Makefile): CI в этом репозитории `make` не вызывает. Обе копии помечены комментарием «менять вместе».
