- **Причина (T-409)**: C-01 v1.3 приведён к коду, но `cmd/multiverse/serve.go` не передаёт контекстам шину, журнал и реестр через `Deps` — контексты EPIC-002 не смогут их получить. Срок — не позже EPIC-002 T-055.

Ещё: doc-комментарий `shared/runtime/http.go:104` говорит `"operator" when unset`, а манифест — `operator,mvctl,ci-harness` (ревью T-411).
- **Метка**: `contract-change`.

## Выполнение (developer)
Исполнитель — developer#1 (TEAM-1). Начало 2026-09-11 12:37 (+03:00), окончание 2026-09-11 12:52. Не закоммичено: файлы в индексе.

**Что сделано.**
- `Deps` в Go не менялся: поля `Bus`, `Journal`, `Contracts` в `shared/runtime.Deps` уже были, их не заполнял `serve.go`. Теперь заполняет. `Contracts` — `contracts.Default()`. `Bus` и `Journal` — ОДИН транспорт: оба поля указывают на один объект, поэтому журнал читает тот же лог, куда пишет шина.
- Вид транспорта берётся из `opts.bus`, то есть из источника T-408 (манифест `MV_BUS`, явный `--bus` перекрывает). Второго источника нет. `kafka` → `eventbus.NewKafka` с брокерами из `MV_KAFKA_BROKERS`; `memory` → `membus` с настоящим списком топиков реестра. У обоих `SkipValidateOnRead = !MV_BUS_VALIDATE_ON_READ` и тот же реестр, что у контекстов.
- Жизненный цикл (ADR-023 п. 4): шину создаёт процесс, и закрывает её только он — последней на ЛЮБОМ пути выхода. Нормальный путь: HTTP-сервер → `StopAll` (обратный порядок) → `Close` шины. Контекст не удалось запустить: `StartAll` останавливает уже запущенные → `Close`. Не удалось занять порт: `shutdown` → `Close`. Сделано через `defer`, объявленный сразу после создания шины.
- `serve` разделён на разбор (`serve`) и прогон (`process.run`), чтобы тест мог прогнать весь жизненный цикл со своими контекстами и увидеть закрытие шины. Повторный сигнал во время остановки по-прежнему доходит до обработчика по умолчанию (`release`).
- Импорт `membus` (он в `shared/testkit`) вынесен в отдельный файл `cmd/multiverse/bus_memory.go`. В `.golangci.yml` добавлено правило `cmd-multiverse-bus-memory`: этому файлу — только `shared/testkit/membus`, больше ничего из `testkit`.
- Устаревшие комментарии: `ownership.go` (блок над `ownershipRules` и doc `OwnershipRules`) и `ownership_test.go` — теперь истина сам `ownership.go`, ADR-025; комментарий над `Deps` — по C-01 v1.3 (нет `Store`/`Env`, кто владеет шиной); `vars.go` — `scripts/lib/LlmEndpoint.psm1`; `http.go` — «по умолчанию то, что объявляет `env.CoreAdminClients`», без третьей копии списка.

**Изменённые файлы.** `cmd/multiverse/serve.go`; создан `cmd/multiverse/bus.go`, `cmd/multiverse/bus_memory.go`, `cmd/multiverse/serve_test.go`; `shared/runtime/runtime.go`, `shared/runtime/http.go` (только комментарии); `shared/contracts/ownership.go`, `shared/contracts/ownership_test.go` (только комментарии); `shared/env/vars.go` (только комментарий); `.golangci.yml`.

**Тесты (новые, `cmd/multiverse/serve_test.go`).** Контекст получает непустые `Bus`/`Journal`/`Contracts`, это один транспорт, реестр — `contracts.Default()`, `End` отвечает по каждому топику реестра, неизвестный топик отвергается (`ErrNoTopic`). Порядок ADR-023: `start first, start second, stop second, stop first, bus closed`; каждый контекст читает журнал в своём `Stop`, так что шина, закрытая раньше, видна дважды. Два неуспешных пути выхода (контекст не запустился; порт занят) закрывают шину последней. `openBus`: `kafka` → `*eventbus.Kafka` без обращения к брокеру; значение вне перечня отвергается; `MV_BUS_VALIDATE_ON_READ` доходит до транспорта (по умолчанию невалидное паркуется, при `false` — отдаётся обработчику); `maybe` отвергается.
