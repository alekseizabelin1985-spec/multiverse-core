## Описание и DoD
Главный источник — раздел «### T-430» в `tasks.md` (решение system-architect из T-431 и DoD). Кратко:
- `runtime.StopAll(ctx, contexts, log *slog.Logger)` перехватывает панику в `Stop`. Ошибка — `stop context <имя>: panic: <значение>`, стек идёт в лог `Error` (поля `context`, `panic`, `stack`). Остальные контексты останавливаются в обратном порядке, шина закрывается последней (ADR-023 п. 4).
- Откат `StartAll`: ошибки `Stop` дописываются к ошибке старта в той же строке через «; ». `%w` остаётся у ошибки старта. Переводы строк в тексте паники (`Start` и `Stop`) экранируются как `\n` и `\r`, а в поле лога `panic` значение пишется как есть.
- `delivery.go`, ветка `DLQ == nil`: причина через `%v`, без `%w` и без нового значения ошибки. Её случай добавлен в сторож `panic_stop_test.go`.
- Doc-комментарии `StopAll`/`StartAll` описывают поведение; README не заводится.

### Предложения в бэклог
1. Экранируется только текст паники, как решил архитектор. Ошибка, которую `Start`/`Stop` возвращают сами, может нести перевод строки (например, `errors.Join` внутри контекста), и тогда строка stderr всё равно разорвётся. Такой контекст уже есть: `FakeContext.Stop` (`shared/testkit/swarm/fake_context.go:185`) возвращает `errors.Join(encounter.Wait(), narrator.Wait())`. Это контекст `swarm` при `MV_SWARM_FAKE=true` (хук T-255, `cmd/multiverse/fake_contexts.go`), то есть путь процесса, а не только тестов. Вероятность низкая. На откате `Stop` сразу отменяет подписки, а отменённая подписка возвращает `nil` (C-01): перевод строки появится, только если обе подписки заглушки упали сами в окне старта. На обычной остановке ошибки `Stop` уходят в slog (`serve.go`, `run`/`shutdown`), и обработчик экранирует их сам (исправлено по ревью #1, Mi-1). Если строку нужно держать одной при любой причине, это решение system-architect: экранировать текст ошибок `Stop` в хвосте отката дёшево, а ошибку старта с `%w` — только отдельным типом ошибки.
2. Обратная косая черта в значении паники не экранируется, поэтому `a\nb` (буквально) и `a<LF>b` дают одинаковую строку ошибки. Различить их можно по полю лога `panic`, где значение как есть. Решением это не требовалось.
