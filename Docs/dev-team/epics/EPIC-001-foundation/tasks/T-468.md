## Описание
**Сейчас.** Принятое значение адреса LLM может содержать `@` после первого `/`, например `http://127.0.0.1:1/fakepw@x` или `http://pw:2024/x@10.0.0.5:8080`. Разбор T-450 такое значение принимает: userinfo в authority нет. Но то, что стоит перед `@`, может быть концом пароля с `/` внутри. C-15 v1.5: «Если `@` есть где угодно в значении, ни одна фраза отказа не называет хост».

T-463 закрыла четыре фразы `llm_endpoint_judge`/`LlmEndpoint.psm1`, облачную фразу правила 6 `compose-lint` и отказ `up` «refusing to start a second server» `llm-server`. Остальной вывод скриптов при `@` по-прежнему печатает пробу (хост и путь) или значение целиком. Проверка ревью #2 T-463 на мёртвом порту 127.0.0.1:1 дала в обеих половинах одну и ту же строку: `bench: no answer from http://127.0.0.1:1/fakepw@x — … (config E expects MV_LLM_URL=http://127.0.0.1:1/fakepw@x)`.

Решение оркестратора при приёмке T-463 (вариант (б)): вся маскировка вывода скриптов собрана в этой задаче. До её слияния пометка «Код расходится» в C-15 v1.5 и ADR-005 остаётся, суженная до перечня ниже.

**Что сделать.** Если в значении (`$LLM_EP_RAW` / `$ep.Raw`) есть `@` в любом месте, строка не называет ни хост, ни пробу, ни значение. Как в `U19` T-463, она называет переменную и схему (`the address of MV_LLM_URL (http://…)`) с хвостом «(the rest of the value and its host are not printed: the value holds an @, and what stands in front of it may be a key)». Без `@` строки не меняются побайтно. Тексты половин sh и ps1 совпадают (стенд паритета, P01/P02).

1. **Строки успеха `llm-server`** (`scripts/llm-server.sh`, `scripts/llm-server.ps1`):
   - `llm: probing <проба> (from VAR=RAW)` — `llm-server.sh:359`, `llm-server.ps1:415`;
   - `llm: VAR=RAW is not an address of this machine — …` — `llm-server.sh:99`, `llm-server.ps1:126`;
   - `llm: starting … the platform calls it at <URL>` — `llm-server.sh:622`, `llm-server.ps1:676`.
2. **Строки `health` с кодом 1** (`llm-server`): `<проба> unreachable — …` (три варианта), `<проба><путь> = 401/403 — the endpoint needs a key …`, `<проба><путь> = <код>` — `llm-server.sh:376-389`, `llm-server.ps1:432-446`.
3. **`llm-bench`** (`scripts/llm-bench.sh`, `scripts/llm-bench.ps1`):
   - три отказа: «no answer from …», «…/health is still 503 …», «… answered <код> …» — `llm-bench.sh:844-846`, `llm-bench.ps1:478-482`;
   - строка пропуска фазы `bench: model … is not in <проба>/v1/models — phase … skipped` — `llm-bench.sh:916`, `llm-bench.ps1:558`.
4. **Поля `url` и `probe_url` отчёта `llm-bench`** (`llm-bench.sh:1005`, `llm-bench.ps1:815-816`; отчёт пишется в `ops/metrics`). Форма записи при `@` — та же маска (схема и `…`) или отдельное поле-признак. Выбор записывается в «Выполнении» с доводом: читатели отчёта (`mvctl report`, сравнение конфигураций) не должны сломаться.
5. **Стенд паритета `testdata/script-parity`**:
   - сценарии с `@` по образцу `U19` и `B07` — на каждую строку п. 1–4, порт двойника `{PORT}` или `{DEAD}`, `AbsentFold` — `fakepw` и хост;
   - по сценарию без `@` на группу — строки прежние;
   - мутант «маскировка снята» в половине sh и в половине pwsh на каждую группу п. 1–4, контрольный мутант первым.

Номера строк — по кончику `epic/EPIC-001-foundation` после слияния T-463; исполнитель сверяет их заново.

### Зависимости
- **Ответ system-architect** (вопрос T-463, ревью #2, бэклог п. 1): распространяется ли правило «при `@` хост не называется» на весь вывод скриптов, а не только на отказы.
  - Если **да** — объём п. 1–5 целиком.
  - Если **только на отказы** — остаются три отказа `llm-bench` (п. 3), строки `health` с кодом 1 (п. 2, если system-architect относит их к отказам) и сценарии с мутантами к ним. Остальное снимается строкой в «Выполнении». Пометка в C-15 и ADR-005 после слияния снимается по ответу.
- Старт — после слияния T-463: общие файлы `scripts/llm-server.*`, `testdata/script-parity/{scenarios,mutants}.go`.

### Не входит
- Правка `contracts.md` и ADR-005 — только system-architect.
- Go-код платформы (`internal/llm`, T-451).
- Реестр мутантов `compose-lint` (бэклог приёмки T-463).
- Стенд LLM владельца 127.0.0.1:8888: в сценариях — только двойник.

## DoD
1. При `@` в значении ни одна строка из п. 1–4 описания (в объёме, подтверждённом ответом system-architect) не содержит хост, пробу или значение. Регистр не спасает: `AbsentFold`. Без `@` строки побайтно прежние.
2. Тексты половин sh и ps1 совпадают: P01/P02 зелёные, число общих шаблонов — в отчёте.
3. Сценарии стенда паритета — по одному с `@` на каждую строку и по одному без `@` на группу; обе половины отвечают одинаково.
4. Мутант «маскировка снята» краснеет в каждой половине на каждую группу; контрольный мутант первым; `make parity-mutants` — зелёный.
5. Отчёт `llm-bench` при `@` не содержит хост и значение в `url`/`probe_url` (сценарий по образцу `B01` с проверкой файла отчёта); выбранная форма поля записана с доводом.
6. Прогоны зелёные: `make scripts-parity` (включая `T01`/`T02` — классы таблицы не меняются), `bash -n`, разбор `.ps1`, `make compose-lint`, `golangci-lint run ./...`.
7. В «Выполнении» — строка для system-architect: после слияния снять пометку «Код расходится» в C-15 v1.5 и ADR-005 (или перечень того, что остаётся по ответу).
8. `infrastructure.md` §3/§6.3.1 — число сценариев и мутантов стенда. Запись в `dev-log.md`, карточка заполнена, `.env` не открывался.
