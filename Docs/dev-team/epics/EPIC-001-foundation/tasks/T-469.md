Умолчания — по рабочей копии T-306 на 2026-09-13, исполнитель сверяет их с манифестом своей ветки;

`MV_ANTHROPIC_API_KEY` (`Secret()`, `RequiredWhen("MV_LLM_PROVIDER", "anthropic")`) не передаётся ни в один compose-файл. Ключ провайдера LLM читает контекст `llm`, который поднят в `core`. Сервис исполнитель подтверждает по коду; если читатель другой — строкой в «Выполнении».

Найдено при приёмке T-464, подтвердить проверкой части (б): `internal/gateway/context.go:245` читает `MV_GM_PATH`, а compose передаёт её только `core`.

**Что сделать.**

**(а) Строки compose.**
- `gateway`: десять `MV_GATEWAY_*` (T-305, T-306, T-307), каждая с умолчанием манифеста ветки.
- `MV_ANTHROPIC_API_KEY` — в сервис контекста `llm` в форме `${MV_ANTHROPIC_API_KEY:-}`, без `:?`: ключ законно пуст у локального провайдера, требование при `anthropic` проверяет процесс при старте. Правило 3 (T-464) такую форму принимает и советует её же.
- Прочие переменные, которые найдёт проверка (б), — сюда же, если их не больше пяти. Если больше — перечень строкой в «Выполнении» и отдельная задача через tech-lead.

**(б) Машинная проверка** (изменение контракта `contracts.md` §16 п. 5 — через system-architect; до его решения код части (б) не пишется).
- Правило: каждая платформенная переменная, которую читает контекст, доходит до `environment` каждого сервиса, где этот контекст поднят (`--contexts=…` в `command`). Исключение — переменные, помеченные в манифесте как переменные только хоста.
- Что уже есть: `shared/env` помечает инструменты хоста `Tooling()` (`ScopeTooling`: `MV_LLM_BIN` и др.). Кандидаты из ревью, у которых пометки нет: `MV_SWARM_FAKE`, `MV_BACKUP_AGE_RECIPIENT`. Какую пометку принять и откуда брать связь «переменная → контекст» (объявление в манифесте, `Scope` или таблица в линтере) — решает system-architect.
- Линтер без Go (правило 8 читает `vars.go` как текст). Если решение потребует правки `shared/env/**` на Go или нового поля в манифесте — это отдельная задача владельца `shared/env`, а T-469 проверку только подключает. Если так выходит больше S — дробить через tech-lead до старта.

**(в) Общее правило формы передачи.** Правило 8 сейчас принимает две формы: `${MV_X:-<умолчание манифеста>}` и ключ без значения, а в совете отказа предлагает ключ без значения. Рекомендация ревьюера #1 T-464 — для новых строк `${MV_X:-<умолчание манифеста>}`. Доводы: форма уже у соседей, значение видно в `docker compose config`, при пустой строке `KEY=` в `.env` действует умолчание. Ключ без значения в этом случае передаёт процессу пустое значение — для `MV_STATE_WORLDS` это отказ State «names no world».
- Правило записывается в §16 п. 5 (system-architect) и в `infrastructure.md` §3.1.1, правило 8.
- Совет `fix_for` в `scripts/compose-lint.sh` приводится к правилу. Фикстуры `expect-text` с советом «pass it through as a key with no value» обновляются.
- Существующие строки с ключом без значения (`MV_GATEWAY_CLIENT_IDS`, `MV_GATEWAY_ACTOR_KIND_CLIENTS`, `MV_CORE_ADMIN_CLIENTS`) переводятся на новую форму, только если system-architect так решит: у списков допуска пустое значение — это «никто» (T-411), их оставили без значения намеренно.

### (в) Форма передачи
Совет правила 8 (`fix_for`) и шапки `compose-lint.sh` и `docker-compose.yml` приведены к общему правилу:
- обычная переменная — `${MV_X:-<умолчание манифеста>}`;
- необязательный секрет — `${MV_X:-}`;
