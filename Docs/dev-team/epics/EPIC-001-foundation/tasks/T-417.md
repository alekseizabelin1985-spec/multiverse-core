## Описание и DoD
- **Причина (T-416, ADR-027)**: `eventbus.Dedup.Seen` спрашивает и запоминает одним шагом — издатель с единственным побочным эффектом вынужден заводить своё окно (нарратор T-220); дубль при потерянном подтверждении публикации не гасится, потому что `Derive` каждый раз берёт новый id.
- **Что сделать**: `Dedup.Has`/`Add` (двухшаговый API, `Seen` остаётся); опция `WithCauseID` у `Derive` — id из причины (UUIDv5 по таблице применимости ADR-027); окна дедупликации пригодны для снапшота C-14 v1.2. Метка `contract-change`.
- **DoD**: тесты на оба механизма; таблица применимости `WithCauseID` из ADR-027 покрыта тестом (неверные `parts` не склеивают разные события); contract-тест шины зелёный на `membus` и Redpanda (T-394). Срок — до T-229.

**Что сделано**
- `eventbus.Dedup.Has(id) bool` — спросить; окно не меняется, порядок вытеснения тоже. `eventbus.Dedup.Add(id)` — запомнить ровно как `Seen`: освежает существующий id, вытесняет самый старый сверх ёмкости, пустой id игнорирует. `Seen` не изменился. `Seen`, `Add` и `Restore` идут через один приватный `remember`. `IDs`/`Restore` снимают окно, заполненное любым путём (C-14 v1.2 (а)).
- `eventbus.WithCauseID(parts ...string) DeriveOption` и `eventbus.CauseIDNamespace` — id производного события = UUIDv5 от `causation_id`, типа и `parts`. В `NewRoot` (и в `Derive` от конверта без id) опция паникует.
- `Derive`: генератор вызывается после опций и только если id не поставлен. Без опции — прежнее поведение, с опцией генератор не трогается.
- Contract-тест шины: новый случай `TwoStepDedupRemembersOnlyAfterTheSideEffect`.
- README пакета: C-01 v1.4, `WithCauseID` с таблицей применимости, двухшаговый `Dedup`.

**Отклонения от дизайна**
1. Имя UUIDv5 кодируется префиксом длины перед каждой частью, а не разделителем (ADR-027 п. 1): `parts` — произвольные строки, и разделитель внутри части склеил бы разные события. Кодирование закреплено golden-тестом.
2. С опцией генератор id не вызывается (ADR молчит): иначе повторная публикация после рестарта сдвигала бы последовательность.
3. `Has` не освежает порядок вытеснения — буква ADR-027 п. 3.

**Предложения в бэклог**
- Уточнить формулировку ADR-027 п. 1 («разделитель, которого нет в id» → «префикс длины у каждой части»).
- Если сверке встреч (T-230/T-237) понадобится id без построения события — чистая функция в C-01, через архитектора.
- Прогон contract-теста на Redpanda с новым случаем — T-394 или оркестратор.
