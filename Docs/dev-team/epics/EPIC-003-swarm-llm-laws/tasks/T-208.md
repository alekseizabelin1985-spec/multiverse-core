**Отклонения от дизайна и решения по ходу.**
1. **Модели для сверки в `Health`** — опция `WithRequiredModels(...)`: `Health(ctx)` из C-15 модели не принимает, а `Config` моделей не держит. Без опции `Health` модели не сверяет. Кто передаёт список (модели блупринтов) — проводка процесса или шлюз (T-212).
2. **Запасной путь `/health` → `/v1/models`** для 401/403/404/405/501 — по правилу скриптов (T-403). Сервер стенда владельца отвечает на `/health` 404. В DoD только 200/503; без запасного пути `Health` стенда всегда был бы `unavailable`.
3. **Пометка оценки токенов — `WARN` в логе**, а не поле записи: поля нет ни в `llm.Response` (C-15), ни в `llm.output.tokens` (`additionalProperties: false`).
4. **Какие коды — `ErrUnavailable`**: нет ответа, 408, 429, 5xx. 400/401/403/404 — нет: повтор того же запроса не поможет. Отмена и таймаут — ошибка контекста. Решение за шлюзом (T-212, КД §9.5): «любая ошибка провайдера после повторов → `ErrUnavailable`».
5. **Тело ответа с кодом ≠ 200 в ошибку не попадает**: облачный отказ по ключу цитирует его начало и конец, а отказ запроса может цитировать промпт. Цена — диагностика 400 от llama-server (например, ошибка грамматики) видна только по коду.
6. **Редиректы не выполняются**: локальный сервер с 307 на внешний адрес увёл бы промпт мимо гейта облака.
7. **`json_schema.name` — имя фазы** (`narrative`, `tick`), при пустой фазе — `response`. В `llm.Request` имени схемы нет.
8. **`Response.Model` — модель запроса**, а не эхо сервера: облако отвечает датированным именем, которого нет в таблице цен.
9. **`ReasoningLen` — в символах** (как `maxLength` JSON Schema), единица в C-15 не названа.
10. **Нулевое значение `Params` — «не задано»** (решение T-206): запросить явно `presence_penalty: 0` или `top_k: 0` нельзя — уйдут умолчания фазы.
11. **`/v1` снимается и в `New`**: для `Config`, собранного вручную (правило то же, что у `LoadConfig`).
12. **Пустая модель в `Generate`/`Embed`** — ошибка до запроса.
