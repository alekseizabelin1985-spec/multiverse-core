**Решения по ходу.**
1. **Сигнатура `Parse` — по ADR-016 п. 1** (`json.RawMessage, Strategy, error`), `recovered` — метод `Strategy`: отдельный флаг мог бы разойтись со стратегией.
2. **Причины не объявлены строками.** Словарь причин — `guardian/reasons.go` (T-217), его стережёт `TestRejectionReasonsMatchTheGuardianPackage`. Парсер даёт сторожевые ошибки `ErrSchemaInvalid` и `ErrLanguage`, шлюз сопоставляет их с `schema_invalid` и `language`. Вторая копия строк была бы словарём, которого тест не видит.
3. **Пакет не импортирует `internal/llm`.** Шлюз (T-212) импортирует парсер, обратный импорт дал бы цикл. Поэтому `MV_LLM_LATIN_MAX_RATIO` читает `parser.LanguagePolicyFrom`, а не `llm.LoadConfig` (`config.go` вне файлов задачи), и ошибка не совпадает с `llm.ErrConfig` (вопрос 5).
4. **Проверка ярлыка привязана к имени схемы `narrative`, а не к `Kind` вызова.** `guardian.SchemaKind` ещё нет (T-217), а схема нарратива — только `narrative.json` (ADR-029 п. 3). У любой другой схемы `text` не проверяется (тест со схемой `other`).
5. **`strip_think` понимает и хвост рассуждения без открывающего тега** (`…</think>{…}`): так отвечает модель, шаблон которой открывает `<think>` в промпте. Удаляется только то, что стоит перед ответом: блок дальше мог бы лежать внутри строки JSON.
6. **`strip_fence` берёт первый fence без языка или с `json`** (регистр не важен). Fence другого языка, без перевода строки и незакрытый остаются следующим шагам; полный JSON в незакрытом fence достаёт `balanced_object`.
7. **`LoadSchemas` читает `agent/*.json` из `fs.FS` с корнем `schemas/`**, как `contracts.New` читает `events/`. Как бинарник получает `schemas/agent` — вопрос 2.
8. **Доля латиницы — по всем текстам ответа вместе**: NFR-090 говорит об ответе. Латиница — Unicode-скрипт Latin (ADR: «латиница»), поэтому `é` — тоже латиница.
