### Решения по ходу

1. **Обработчики вне `api`.** Component §3 кладёт `handlers_links.go` в `api`, но `api` импортирует бот (DTO), а обработчик связок тянет `links` → `store` → драйвер SQLite. Обработчики — в `internal/gateway/handlers`; в `api` остались типы, таблица ошибок, роутер и middleware (только `net/http`, `slog`, `shared/clock`).
2. **Порядок middleware.** Request id и access-лог — самый внешний слой, recover — второй (в §5.1 наоборот): так `500` паники тоже несёт `X-Request-Id` и попадает в лог. «nolog» (п. 5) — не отдельная обёртка, а политика операции, которую применяет access-лог: он должен видеть и `403` шага 3. Для nolog-операций в строке лога только `request_id` и `code`; у строки паники ещё `handled=false` (NFR-012), значение паники и стек не пишутся. Причина `500` на этих маршрутах в лог не попадает — это цена строгого DoD (см. риски).
3. **`X-Actor-Kind`** вне `human|ci|sim` (в т. ч. `system`) → `400 invalid_request`; `ci|sim` от клиента вне `MV_GATEWAY_ACTOR_KIND_CLIENTS` → `403 actor_kind_forbidden`. `client_mismatch` — для любого маршрута с `{client_id}` в пути.
4. **Body limit**: `Content-Length > 64 КиБ` → `413` сразу; chunked — через `http.MaxBytesReader` и `DecodeJSON`. Тело с `Content-Type` не `application/json` → `400 invalid_request`. Неизвестные поля JSON принимаются (совместимое расширение, api-contracts §1.1).
5. **Таймауты (п. 2 постановки).** Серверные `ReadTimeout/WriteTimeout/IdleTimeout` не трогал — это `shared/runtime`, T-446 (`runtime.SetDeadlines`, `ShuttingDown`). Middleware 8 ставит на контекст запроса дедлайн `api.RequestTimeout` = 5 с всем операциям, кроме `api.LongPollOperations` (`pollDeliveries`). Этот список — явная точка подключения для T-307. Pollguard (`409 poll_in_progress`) уже работает по тому же списку. Решения system-architect о таймаутах в дереве нет, ссылка — T-446.
6. **Решение по заблокированному checkpoint (п. 3).** `DELETE` уже закоммичен, `CompactLinks` вернул ошибку (читатель вне процесса дольше `busy_timeout` 5 с — например, `sqlite3 .backup` — или истёк дедлайн запроса). Тогда `Forget` возвращает результат вместе с `ErrCompactionPending`, стор помечает сжатие отложенным, обработчик отвечает **`503 forget_incomplete`**. Данные не объявляются удалёнными (ADR-019 доп. п. 1: скан сразу после ответа = 0). Клиент повторяет `503` сам (DefaultBackoff); повтор не находит связки, доделывает сжатие и отвечает `{deleted:false}`. Эту неоднозначность клиент уже разбирает через `ForgetResult.Repeated` (T-301/T-311). Страховка — sweeper контекста: каждую `store.SweepInterval` (1 мин) `Sweep` доделывает отложенное сжатие, каждый `store.LinksCompactInterval` (1 ч) — полное сжатие; ещё одна попытка — в `Stop`. Пока сжатие отложено, `/health` gateway — `degraded` с `links_compaction: pending`. Отвергнуто: `200` с отложенным sweeper'ом (нарушает ADR-019 доп. п. 1) и `500 internal` (это не дефект кода, а внешняя блокировка; клиент `500` не повторяет).
7. **Каскад `/forget` (п. 4).** Хуки выполняются **до** удаления: упавший хук останавливает каскад, связка остаётся, повтор `/forget` запускает всё заново (хуки обязаны быть идемпотентными). В T-303 хуков нет: `outbox.DropForPlayer`, предложение `abandoned`, `group.left`, `session.End(forget)` подключают T-307/T-314/T-352/T-355 через `links.NewSQLite(db, ids, hooks...)`. Предложения в T-303 **не публикуются**, поэтому `proposal_id = forget:{player_id}` и правило «`dead_entity` на своём предложении → 200 "уже забыт"» не реализованы — строка для T-314/T-355 (см. предложения). Связка без персонажа удаляется (в ней внешний ID) с `player_id_detached: null` — это и есть «нечего удалять» US-009 для бота; без связки — `{deleted:false, player_id_detached:null}`.
8. **Consent.** Неполная форма — связка остаётся `pending_consent`, обновляется `last_seen_at`, `400 consent_incomplete`. Повторное согласие не меняет три отметки времени (доказательство согласия), только `last_seen_at`. Согласие без предшествующего `resolve` создаёт связку. `notice_shown_at` = `shown_at` клиента; полная форма без `shown_at` → `400 invalid_request`.
9. **Resolve.** `notice_due` = новая связка, или `pending_consent`, или прошлый визит ≥ 30 дней назад (`handlers.NoticeRepeatAfter`). `character_status`: `none` без персонажа; с персонажем — через `Links.CharacterStatus` (read model T-304/T-306), до подключения — `creating`. `external_platform` принимается только `telegram` (enum спецификации), иначе `400 invalid_request`.
10. **Идентификаторы (п. 5).** `link_id` — из `Deps.IDs`, `player_id` = `player-` + `Deps.IDs` (`links.NewPlayerID`). С `--id-source=sequence` они воспроизводимы (тесты). ULID и новая зависимость не нужны. `X-Request-Id` берётся из `uuid.NewString`, а не из `Deps.IDs`: иначе каждый HTTP-запрос (включая отказанный) сдвигал бы последовательность доменных id (тест `TestRequestsDoNotShiftTheSequenceOfLinkIDs`).
11. **Контекст (C-01 v1.3–v1.7).** `Routes` монтирует маршруты до `Start`; зависимости обработчиков и middleware заполняются в `Start`, а сервер процесса начинает обслуживать только после `StartAll`, поэтому гонки нет. `Start`: `Deps.Clock/Timers/IDs/Log` обязательны; `MV_GATEWAY_DATA_DIR` → открытие и миграции `links.db` и `gateway.db` (открытие под `context.WithoutCancel`: короткий локальный ввод-вывод, ограничен `busy_timeout`; иначе сигнал во время старта оставлял бы файлы полуоткрытыми, а `dispatch_test` стартует процесс с уже отменённым контекстом); sweeper — только в `live`. `Stop` (v1.7): отменить sweeper и дождаться его, доделать отложенное сжатие, закрыть `gateway.db`, затем `links.db`; шину не трогает. Подписок у контекста пока нет — их отмену в `Stop` до закрытия шины добавит T-304. `objstore.New` в T-303 не нужен (ни снапшота, ни bootstrap) — клиент хранилища создаст сам контекст в T-304. `DependsOn` пуст.
12. **Тесты EPIC-001.** С настоящим gateway `--contexts=all` открывает SQLite при старте. Умолчание манифеста `/data` в тестах недопустимо (на Windows — корень диска, в CI — нет прав), поэтому `onLoopback` и `emptyWorldEnv` ставят временный `MV_GATEWAY_DATA_DIR` с повторным удалением (Windows «delete pending»).

- Обработчики — `internal/gateway/handlers`, а не `api/handlers_links.go` (решение 1). `handlers_health.go` нет: `/health` отдаёт сервер процесса, поля gateway — через `Health()`.

**Решение system-architect#1 по `503 forget_incomplete` — как реализовано (для T-456)**

Тексты C-08, `api-contracts.md` §1.6 и КД шлюза не правил. Фактические сигнатуры и порядок:
- Код ошибки: `api.CodeForgetIncomplete = "forget_incomplete"`, HTTP 503, сообщение «Удаление не завершено, повторите /forget.». В OpenAPI код входит в `x-error-codes` ответа `Unavailable` (вместе с `bus_unavailable` и `state_unavailable`), у `forgetLink` есть ответ `'503'`. Заголовок `Retry-After` описан у `Unavailable`: «только с `forget_incomplete`».
- `Retry-After: 5` — `handlers.ForgetRetryAfter = 5 * time.Second`, равен `busy_timeout` `links.db`. Клиент T-301 заголовок не читает и повторяет 503 по `DefaultBackoff` (3 повтора: 200/400/800 мс, ≈1,4 с). По решению architect это приемлемо.
- Стор: `links.ErrCompactionPending`; `(*links.SQLite).Forget(ctx, platform, externalID string) (links.ForgetResult, error)`; `ForgetByPlayer(ctx, playerID string) (links.ForgetResult, error)`; `Compact(ctx) error` (неудача ставит отметку, успех снимает); `CompactionPending() bool`; `Sweep(ctx, now time.Time) error`; `ForgetResult{Deleted bool; PlayerIDDetached *string}`; `ForgetHooks.OnForget(ctx, playerID string) error`.
- Порядок `Forget`:
  1. найти связку;
  2. если связки нет: при отметке — `Compact`; неудача → `ErrCompactionPending` (503), иначе `200 {deleted:false, player_id_detached:null}`;
  3. если у связки есть персонаж — хуки по порядку; ошибка хука → связка остаётся, 500;
  4. `DELETE … WHERE link_id = ? AND player_id IS ?`; 0 строк → перечитать по `link_id` (п. 2 или каскад заново, ≤ 3 попыток);
  5. `store.CompactLinks` (incremental_vacuum, затем `wal_checkpoint(TRUNCATE)`) до ответа; неудача → результат + `ErrCompactionPending` → 503; успех → `200 {deleted:true, player_id_detached}`.
- Пока отметка стоит, любой `/forget` отвечает 503, кроме вызова, который сам доделал сжатие: он отвечает как обычно.
- Контекст:
  - `Start`: `DataDir` → открыть и мигрировать `links.db`, `gateway.db` → `NewSQLite` → безусловный `Compact` → `api.Config`/`handlers.Links` → sweeper (только `live`);
  - sweeper: `SweepInterval` 1 мин — `Sweep`, `LinksCompactInterval` 1 ч — `Compact`;
  - `Stop`: остановить sweeper (ждать до дедлайна) → при отметке и остановленном sweeper'е `Compact` → закрыть `gateway.db`, затем `links.db`, всегда;
  - `Health`: `degraded` (HTTP 200) с `links_compaction: pending`, пока стоит отметка.
