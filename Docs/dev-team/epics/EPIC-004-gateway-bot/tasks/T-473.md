## Описание и DoD
Главный источник — раздел «### T-473» в [`../tasks.md`](../tasks.md): описание, DoD задачи и DoD-common (§0). Карточка DoD не дублирует; если они расходятся, прав индекс. Кратко:
- После сбоя брокера подписка `consumer.Dispatcher` кончается (`unexpected EOF`, `failed to dial`), и шлюз глух до перезапуска процесса (T-316, находка 1). Нужна переподписка с нарастающей паузой на `shared/clock.Timers`; `/health` возвращается к `ok`, когда подписка восстановлена. `nil` из `Subscribe` без `Stop` — тоже конец подписки.
- Публичный API `shared/eventbus` не меняется. `Kafka.Subscribe` возвращает `nil` на `io.EOF` — пункт DoD «решение system-architect: …». Правка `shared/eventbus/kafka.go` — только по его решению, tech-lead#1 уведомлён.
- `Dispatcher.Stop` укладывается в `runtime.StopTimeout` (15 с) и во время входа в группу (замер T-316 — 29,7 с). Пауза до первой доставки после сбоя (T-316 — ~30 с) замерена, цель — ≤ 15 с.
- Шаг 8 integration-теста T-316 строгий: `d.Err() == nil`, событие взято в каждом из четырёх топиков, путь с перезапуском удалён.
- Замер при зависшем брокере: `docker pause` своего контейнера testcontainers, один прогон — ack, `gateway.db`, период повторной выдачи (решение Mi-2 приёмки T-316).
- Unit-тесты переподписки — на `membus` или фейке с инъекцией ошибки, на ручных часах; мутанты.
- Брать после слияния T-309: она правит `dispatcher.go`, `context.go` и `/health`.
