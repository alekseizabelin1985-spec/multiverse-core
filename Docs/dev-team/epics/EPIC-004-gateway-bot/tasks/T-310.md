### Что сделано

Новый каталог `cmd/telegram-bot/internal/` (без `main.go` — это T-312):

Все проблемы — одной ошибкой. `Secrets()` для редактора; `LogValue`/`String`/`GoString` без токена, соли и id.
- **`updates`** — `Update`/`Message`/`Chat`/`User` только с полями ADR-018 п. 3 (все печатаются как `redacted` и в `slog`, и в `%v`); `Source{Start(ctx, Handler) error}`; `Telegram` — long polling на `go-telegram/bot` v1.25.0: `getMe` на старте, `allowed_updates=[message]`, `timeout=25`, `WithNotAsyncHandlers`, `WithErrorsHandler` через `privacy.ErrorLog`, заглушённый debug-обработчик, без `WithDebug`; `409 Conflict` → остановка опроса и `ErrConflict`; отклонённый токен → `ErrUnauthorized` с редактированным текстом. `ExitCode(err)`: `ErrConflict` → 3. `Fake` (FakeUpdateSource): `Push`, `Fail`, `Close`.
- **`sender`** — `Sender{Send(ctx, chatID int64, text string, kb *Keyboard) error}` без параметра разметки; `Keyboard{Rows, Remove}` — reply-клавиатура из текстовых кнопок. `Telegram` — `sendMessage` без `parse_mode` и `entities`; `429` — пауза `retry_after` (0 → 1 с; не больше 5 ожиданий и не дольше 60 с), сеть/`5xx` — 3 попытки с паузой 1 с; паузы на `clock.Timers`. Ошибки: `ErrBlocked` (403), `ErrChatNotFound` (400 chat not found), `ErrRejected` (прочие 4xx), `ErrUnavailable` (повторы исчерпаны); текст — редактированный, `chat_id` из него вырезан. `5xx` отличается от отказа по HTTP-статусу, который пишет обёртка HTTP-клиента в контекст вызова (библиотека отдаёт `5xx` только текстом). `Fake` (FakeSender): `Sent`, `FailNext`.
- **`commands`** — `Parse(text) Command{Type, Target, Text, Confirm, Slash, Problem, Hint}` по словарю FR-002: `/start`, `/help`, `/forget [confirm]`, `enter`, `leave`, `look`, `attack`, `flee`, `say`, `rest`, `defend`, `status`, `group create|join|leave`; `/cmd@bot`; регистр не важен. Синонимы без `/` — только в точной форме («look», «attack wolf-alpha»), иначе `Unknown` с исходным текстом (решает `flow`). `say` ≤ 500 символов после trim, пустой `say`, `group join` без id, `/group` без подкоманды → `Problem` + `Hint`. `ActionKey(salt, update_id)` = `hex(HMAC-SHA256(salt, update_id))[:32]`.

Лог отказа — только `reason`. `Counters{Denied, NotPrivate, TooOften}`.

### Решения по ходу

1. **Лимит — скользящее окно, а не token bucket.** Ведро на 20 с пополнением 20/мин пропускает до 39 команд в первую минуту и принимает 21-ю команду через 3 с после серии. NFR-049 требует «≤ 20 команд/мин», US-008 и DoD — отказ 21-й команде до 61-й секунды. Журнал — не больше N отметок на пользователя; до лимита доходят только пользователи из allowlist, поэтому память ограничена размером списка.
2. **Флуд получает один ответ.** «Слишком часто» отправляется на первую отклонённую команду серии, следующие отклонения молча отбрасываются до первой принятой команды. Иначе бот отвечал бы на каждое сообщение флуда.
3. **Граница SEC-06 в тесте.** Мок gateway — `httptest` со счётчиком запросов, а обработчик после шлюза шлёт `POST /v1/links/resolve` обычным HTTP, не через `internal/gateway/client`. Причина: правило depguard `internal-unlisted` (`**/internal/**`) распространяется на `cmd/telegram-bot/internal/**`, включая тесты. Проверено пробой: `import 'multiverse-core.io/internal/gateway/api' is not allowed from list 'internal-unlisted'`. Проба удалена. Правила не расширял — см. «Открытые вопросы».
4. **Граница импортов** — `config/imports_test.go`: `go list -deps ./cmd/telegram-bot/...` (без `-test`: тестам бота позже понадобится `gatewaytest`). Из `multiverse-core.io/internal/` разрешены только `gateway/api` и `gateway/client`; `modernc.org/sqlite` и `pressly/goose` запрещены. Если `go` нет в PATH, тест пропускается.
5. **`WithDebug`** проверяется двумя тестами. Первый собирает бота из настоящих опций `Start` и добавляет записывающий debug-обработчик; обработчик не должен сработать на ответе с обновлением. Второй разбирает AST: ни один не-тестовый файл `cmd/telegram-bot` не ссылается на `WithDebug`.
6. **`409` и порядок** *(исправлено в итерации 2, M-1 ревью #1)*. Прежний текст — «необработанные обновления получит оставшийся экземпляр» — был неверен. Библиотека подтверждает пачку следующим `getUpdates`, а с очередью на 1024 этот запрос уходил сразу, и всё, что лежало в очереди, терялось при любой остановке. Теперь опрос идёт с `bot.WithUpdatesChannelCap(0)`: обновление передаётся только взявшему его обработчику, следующий `getUpdates` уходит, когда последнее обновление пачки уже в работе. При остановке теряется не больше одного обновления — того, что в работе; остаток пачки Telegram отдаёт повторно, повтор гасится `action_key`. Обновление, переданное после отмены `ctx`, обработчику не отдаётся. В тесте `409` конфликт отвечается после обработки обновления 1, чтобы отмена не попала между передачей и вызовом обработчика.
7. **Служебные команды — только со `/`.** «forget» внутри фразы не должен запускать удаление.
8. **Групповой чат — молчание** *(изменено в итерации 2 решением оркестратора)*. Прежде бот отвечал в группу «Пишите боту в личные сообщения.». Приоритет у утверждённых требований US-008 (негативный критерий), FR-131 и NFR-044 перед DoD T-310 и ADR-018 п. 3: бот не отвечает и не зовёт gateway ни участнику allowlist, ни постороннему. В лог — одна строка `reason=not_private` без id на серию сообщений группы; `chat.id` группы держится в памяти не дольше окна и нигде не пишется. *(Уточнено при приёмке, N-7 ревью #2: до приёмки запись вычищалась только при заполнении таблицы и могла жить до рестарта. Теперь шлюз вычищает серии старше окна на каждом обновлении: id живёт в памяти окно после начала серии и до следующего обновления, без обновлений — до остановки процесса.)*

### Отклонения от дизайна

- Лимит: скользящее окно вместо token bucket (решение 1). Один ответ на серию отказов (решение 2).
- Имена переменных: `MV_TELEGRAM_ACTION_KEY_SALT` и `MV_TELEGRAM_COMMANDS_PER_MIN` вместо `MV_BOT_ACTION_KEY_SALT` и `MV_BOT_RATE_COMMANDS_PER_MIN` (component §11.3). Имена окончательно подтверждает architect#3. `MV_TELEGRAM_CLIENT_ID`, TTL диалога и ожидание доставок не объявлял: их читают T-311/T-312, а переменная объявляется вместе с чтением (урок T-408).
- Явная соль короче 16 символов — ошибка конфигурации (в дизайне ограничения нет).
- `updates.Handler` = `func(ctx, Update)`, у ADR-018 п. 2 — `func(Update)`: контекст нужен вызовам gateway из `flow`.
- `Sender` возвращает типизированные ошибки. Потолок `retry_after` 60 с и не больше 5 ожиданий `429` — в дизайне этого нет: ожидание часового бана внутри `Send` заблокировало бы бота.
- `WithSkipGetMe(false)` из component §10.2 в v1.25 без аргумента. Источник обновлений `getMe` не пропускает (проверка токена на старте), отправитель пропускает.
- Код выхода 3 — `updates.ErrConflict` + `updates.ExitCode`. Сам `os.Exit` — в `main` (T-312).
- Сообщения шлюза — константы в `access` (`TextInviteOnly`, `TextPrivateOnly`, `TooOftenText`), подсказки разбора — в `commands.Command.Hint`. В T-311 их можно перенести в `render`.
- Размер: ~1600 строк кода (с doc-комментариями) и ~1700 строк тестов при ориентире M «~600 строк»: шесть пакетов в одной задаче.

        cmd-telegram-bot:
